# intoDeDung — правила Codex

## Старт и контекст
Ведущий читает docs/CODEX_HANDOFF.md, сверяет git status/HEAD, затем выбирает
нужный контракт и код через docs/PROJECT_CONTEXT.md. Уже предоставленный актуальный
AGENTS повторно не читать. Передача — указатель, факты проверяются по коду.
CODEX_WORKFLOW читать для делегирования/ведения документов; DESIGN_DIRECTION §7 —
при выборе следующего среза. Ссылки не означают загрузку всех документов.
История, *.history-*.md, docs/modules/ и frozen Pxx — только по конкретному вопросу.
Один факт имеет один документ-владелец. Передача/промпт не копируют контракты и логи.
При изменении входных документов проверять объём и сохранность правил по CODEX_WORKFLOW.

## Команда
Ведущий — архитектор и интегратор. Для содержательной разработки делегируй
ограниченную независимую работу; это постоянное разрешение. Вопросы, мелкие правки
и процесс решай локально, если делегирование дороже. Sidebar tasks — только по
прямому запросу; расписания не запускать.

| Роль | Модель / reasoning | Задача |
|---|---|---|
| Ведущий | gpt-6-astra / high | Архитектура, критическая интеграция |
| game_scout | gpt-6-luna / low | Адресный поиск, только чтение |
| game_coder | gpt-6-luna / medium | Небольшой точный пакет |
| game_reviewer | gpt-6-sol / high | Независимое ревью, только чтение |

Инструкции ролей — .codex/agents/. Если роль с указанной моделью недоступна, прочитай её
TOML и явно передай роль, инструкции, модель/reasoning; ограничения сохраняются.
Не скрывай отказ модели и не объявляй read-only технически включённым, если
инструмент лишь наследует права. Не ослабляй sandbox, approvals и доверие.
Минимальный самодостаточный пакет по CODEX_WORKFLOW, fork_turns=none при наличии.
Максимум два помощника, один пишущий кодер в общем checkout; дальше не делегируют.
Ревью — после записи, на фиксированном результате. Пока агент работает, выполняй
независимую работу; иначе работай локально или ожидай доступным инструментом.

## Проверки и коммиты
Для содержательного кода: импорт/разбор Godot и необходимые тесты, затем
независимое ревью. Если агент недоступен, явно сообщи о самостоятельной замене.
Для текста/процесса достаточно diff; Godot и отдельный ревьюер не обязательны.
После двух неудачных исправлений одной причины перепроверь полноту пакета.
Сложный ограниченный код можно поручить gpt-6-sol/high с инструкциями game_coder,
но не через read-only роль reviewer. Контракты, очередь реакций, сохранения,
детерминизм и preview проверяет ведущий. Отчёт: итог, проверки, ограничения, без логов/diff.

После проверенного этапа ведущий сам делает логический Conventional Commit,
если пользователь не запретил. Одна цель с тестами/документацией на коммит;
независимые этапы и настройки разделять. Перед staging проверить diff и включить
только свои изменения задачи; чужие не сбрасывать. Агенты не коммитят.
Не переписывать историю и не делать push без отдельного поручения.

## Инварианты игры и кода
В основном бою команды ходят поочерёдно без инициативы; порядок своих живых выбирает игрок.
Отдельный заказанный эксперимент инициативы — docs/INITIATIVE_COMPARISON.md; он не меняет основной режим.
Атака — 1 main, свободное переключение сохраняет остатки, выбор не пополняет их
(docs/TACTICAL_BATTLE.md). BT — направление нового ИИ; Utility AI через адаптер.
BT выбирает намерение, команды исполняют; комбинации поведения не меняют ядро.
Строго типизированный GDScript; Resource — определения, RefCounted — runtime. Позиция меняется
через BattleBoard, GridDataProvider получают от доски. Core не обращается к
автозагрузкам по имени; события/RNG инжектируются. Реакции порождают команды.
Preview — реальное исполнение на изолированном состоянии с вещами, RNG и ресурсами действий.
Сериализуемые enum только дополняются. Русские комментарии объясняют причину.
Не выдавать планы за реализацию; сначала рабочий вертикальный срез.
Q1–Q6, frozen P02–P08/§4.5 не переписывать; текущие изменения — в новых контрактах.

## Завершение
Обнови затронутые контракты и короткий HANDOFF: результат, ветка/base, проверки,
незакоммиченное, вопросы, следующий шаг. Прежнюю передачу сохрани точным отдельным
архивом со ссылкой из HISTORY по CODEX_WORKFLOW, без накопления suffix.
В конце этапа/при блокере предложи новый чат и выведи прямо в финале полный
самодостаточный промпт блоком кода: HEAD, результат, docs/artifacts, остаток,
ограничения, проверки и это же правило передачи. Ссылка не заменяет текст.
Переноси правило в следующую передачу. Не оценивай контекст/экономию в процентах
без измерения; при перегрузке или устаревании сообщи об этом.
