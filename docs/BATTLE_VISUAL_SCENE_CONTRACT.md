# Жизненный цикл визуальных сцен V1

Поручение 2026-10-10: замена арта не должна возвращать пересоздание всего поля
при каждом шаге движения. Контракт охватывает опоры/стены, накладки окружения
и фигуры бойцов. Изображения, геометрия пресетов, темп анимаций, игровой расчёт
и очереди не меняются.

## Допуск сцены

`art_trial_unit` расширяет прежний драйвер через `BattleCharacterSkinVisual`:
отделённый `visual_skin_id` выбирает Resource класса и кадры на одном дочернем
слое. Набор, часы и привязки способностей — [CHARACTER_SKINS_V1](CHARACTER_SKINS_V1.md).
Рисунок не читает настройки/профиль во время playback; Board получает копию
выбора из хаба. Ни выбор, ни вторичный idle не меняют игровые RNG.

По U2026-11-15 первая буква имени больше не рисуется поверх тела бойца,
включая временные силуэты перемещения и процедурный fallback.
Полные имена остаются данными карточек/подсказок; полосы и статусы отображаются
прежним путём. `transient_label` сохранён в API временной фигуры и её очистке.

Корень тайла наследует `BattleTerrainVisual`, корень окружения —
`BattleManagedEnvironmentVisual`, фигура бойца — `BattleManagedUnitVisual`.
Это явное принятие описанного ниже lifecycle.
Доска определяет поддержку по типу экземпляра, без списка путей PackedScene.
`placeholder_tile`, `art_trial_tile`, `environment_overlay`, `placeholder_unit`
и наследующий его `art_trial_unit` подключены к контракту.
Новый производный пресет не требует изменения доски.

`BattleVisualSceneContract.validate` и `validate_unit` проверяют корни отдельными экземплярами
вне дерева и возвращают все ошибки. Новый пресет допускается после проверки
типа **и поведения** в адресном render-сценарии. Наследование само по себе не
доказывает корректность пользовательского Tween, `_process` или override.
Инициализация сцены не должна читать/менять runtime боя, RNG или профиль.

Процедурный fallback и прежние корни `BattleDemoIsoVisual`/`BattleEnvironmentVisual`
остаются совместимыми с доской через создание заново. Проверка допуска их
отклоняет: такой fallback не является выполнением контракта нового арта.

## Значения и применение

Доска передаёт значения **каждой** публикации. Номер revision, identity runtime
и сохранённая готовность команды не заменяют их чтение. Представление не держит
UnitState, CombatState, queue, RNG или alias входных изменяемых коллекций.

| Корень / метод | Полный вход |
|---|---|
| `BattleTerrainVisual.apply_view(values, config)` | `cell:Vector2i`, `role:Role`, `half_steps:int`, `is_void/reachable/enemy_range/burning:bool`; отдельно ненулевой `IsoGridConfig` представления |
| `BattleManagedEnvironmentVisual.apply_view(values)` | `spikes/burning/warning/acid/floor_trap/armed:bool`, `wall_direction:Vector2i`, `corpses:Array[Dictionary]` |
| `BattleManagedUnitVisual.apply_view(values, config)` | `cell`, `half_steps`, `unit:{id,faction,name,alive,hp,hp_max,balance,balance_max}`, `visual_class_id`, `selected/inspected/hovered/acting/show_rear/summon_pending`, `forecast_entry/armor_values/shield_view/raised_shield_view/reaction_view/action_resources_view`, `status_entries`; ненулевой `IsoGridConfig` |

Это внутренний типизированный producer/consumer, не формат сохранения и не
вход недоверенных данных. Board собирает полный набор из отделённых `_view_*`.
Первая публикация всегда применяется. Последующие сравниваются с фактическими
свойствами узла; неизменные значения возвращают `false` без полной настройки
рисунка/пресетов. Изменение возвращает `true`, увеличивает `view_apply_count`.
Тела копируются глубоко. Геометрия конфигурации сравнивается по `tile_size`,
`height_step`, `origin_offset`, поэтому правка Resource на месте не теряется.
Фигура создаёт собственный `BattleUnitView` из скаляров и копирует коллекции.
Постоянные полосы здоровья и брони содержат текущие числа из этой публикации;
цвет, размеры и прогноз — [показ состояния](BATTLE_PRESENTATION_REWORK.md).
Сравнение включает фактические публичные поля: прямое изменение hover/forecast
или геометрии позой не должно скрыться за равенством предыдущему входу.
Редактируемые PNG, геометрия, материалы и посадка остаются в сценах.

При after и обычном refresh Board повторно использует собранные DTO земли, если
совпадают отделённые значения геометрии, среды, владельца/сцен и
набора активных поз. Сравнение глубокое, изменения коллекций на месте видны.
Сброс поз и apply_view с проверкой фактических полей сохраняются; пропускаются
сборка тех же DTO и поиски среды по всем клеткам. Legacy-сцены пересобираются.
Подсветка рассчитывается из текущих режимов/доступности отдельно от сборки земли.
`highlights_use_ground_overlay=false` сохраняет полный `sync_scene_art` при смене
подсветки; авторская сцена может включить флаг, если рисунок от неё не зависит.
Тогда только reachable/enemy_range обновляют ground overlay. Текущий art_trial_tile
и dungeon явно включают этот путь; геометрия/огонь/VOID идут полным apply.
Метки областей собираются по клеткам одним проходом с прежним порядком; redraw
нужен лишь при изменении фактических меток/флагов. Hover/acting также сравнивают
фактические флаги. Сортировка native Vector3 сохраняет ключ position.y/child index.
Порядок клеток строится по диагоналям при смене размеров, с прежним tie-break y;
Y-sort/picking не меняются. Обычный refresh перечитывает runtime полностью.

При полной сборке земли `_index_environment_view` один раз группирует текущие
fire/corpse/acid/collapse/trap по клетке. Индекс живёт только одну публикацию;
порядок тел и первый trap сохраняются. Forced overlay строит свежий индекс.
Это заменяет повторные поиски эффектов для каждой клетки без кэша runtime.
Пустая клетка без существующего overlay/активной позы пропускает его настройку.
Стандартный environment overlay включает `phase_updates_only_standard_effects`:
смена warning_phase обновляет только alpha ArmedRim и redraw warning/fire fallback.
Статичные шипы, тела и кислота не пересобирают пресеты на каждом изменении фазы.
Флаг по умолчанию выключен; сцены со своим рисунком фазы сохраняют полный sync/redraw.
Configure и семплы collapse/hazard/trap по-прежнему обновляют весь нужный рисунок.

`batch_simple_polygons=false` сохраняет native Polygon2D. Dungeon включает
флаг: `BattlePolygonBatch` заменяет команды простого четырёхугольника двумя
`draw_primitive` с той же триангуляцией, UV и цветами. Compatibility объединяет
такие примитивы в batch; исходные узлы, трансформации, Z, clip и PNG сохраняются.
Сложная геометрия, skinning, AA, преобразованные UV, script/чужой draw сохраняют
native путь. При выключении флага callbacks снимаются и native draw восстанавливается.
Изменения polygon/UV/цветов читаются при каждом redraw, кэша геометрии нет.
Pixel-oracle тест сравнивает native/optimized с допуском 1/255 на канал.
Повторная сортировка пропускается только после проверки реальных position.y/child
index каждого узла: позы и прямые изменения пользовательских сцен видны сразу.
Одинаковый action offset не запускает повторный sync. Неизменный выбор палитры
не обходит скрытые спрайты; смена класса/текстуры всё ещё синхронизируется рисунком/idle.
`batch_motion_pose=false` оставляет два прежних setter/sync для offset и lift.
Текущая art_trial_unit включает флаг: `set_motion_pose` фиксирует оба значения,
затем синхронизирует рисунок один раз. Даже равная поза делает sync для ремонта
геометрии; прямые setters и custom-сцены без opt-in сохраняют прежнее поведение.
Движение/падение используют тот же Tween, координаты, сортировку и время контакта.

## Владение и временные эффекты

Доска владеет узлами. Опора хранится по `(cell, floor-or-wall)` до исчезновения
стены, смены board/размера/PackedScene или потери валидного родителя. Накладка
хранится при прежней сцене под той же опорой, пока нужна эффекту или активной
позе. Смена состояния эффекта обновляет узел; исчезновение всех причин удаляет.
Y-sort и picking сохраняют порядок клеток, включая появившиеся позже стены.
Фигура хранится по ID внутри текущих session/board/размера/PackedScene.
Смена владельца или пресета, исчезновение из показанного состава и потеря
родителя завершают её lifecycle. При обычном движении корень и его авторские
дочерние узлы сохраняются. Удалённый боец и новый боец с тем же ID не используют
старый узел после границы отсутствия; legacy-корни по-прежнему пересоздаются.

Общий порядок: создать/подключить при необходимости → `reset_view_pose` →
`apply_view` → после сборки поля `BattleFieldPresentation.restore`.
Новая публикация предварительно завершает прошлое представление;
resize применяет прежние отделённые значения и восстанавливает активную позу.
Тайл сбрасывает временные смещения/сжатие/смерть и возвращает авторский modulate;
окружение сбрасывает collapse/hazard/trap progress. Флаги состояния не стираются
перед сравнением: это позволило убрать повторную полную настройку.
Фигура также снимает временную подпись, восстанавливает опору/высоту из fresh
values, затем получает текущий action offset доски и активную полевую позу.

Перед удалением доска вызывает `retire_view`, затем отключает и освобождает узел.
Метод не освобождает и не переподключает себя. Производный пресет обязан отменить
свои Tween/callback и очистить принадлежащие ему временные ссылки; уход всего
дерева тоже должен быть безопасен. Нельзя запускать независимую игровую команду
из lifecycle. Общего пула и собственного планировщика анимации здесь нет.

`sync_view_transform` обновляет только зависимые от экранного масштаба детали.
Доска сверяет один screen transform за кадр; при его смене вызывает hook
сохранённых сцен. Trial-тайл обновляет только ширину QuietSeam, а не весь арт.
Это покрывает canvas/stretch, который может не прислать notification тайлу.

## Разворот живого бойца к цели атаки — 2026-10-26

U: система общая для всех живых персонажей; после атаки возвращать исходную сторону.
Board задаёт `presentation_facing_x=-1/0/+1` по экранной X-составляющей проекции
`target_cell-actor_cell` из отделённого события. Совпадение экранных X сохраняет
авторский разворот. Это визуальная поза, не механическая спина/фракция и не save/DTO.
Обычная/дальняя атака, прыжок разбойника, ответная и упреждающая атаки проходят
один путь без допуска по имени/классу. Мёртвые фигуры не разворачиваются.
Внешние заклинания мага actor0 не имеют модели атакующего на поле.

Разворот появляется до первого кадра замаха и живёт до окончания связанного
попадания/восстановления. Публикация между замахом и попаданием и resize сохраняют
его из pending strike; speed/zoom/pan не меняют сторону. Завершение, FAULTED,
skip/cancel/replay/retire возвращают авторские трансформации без накопления.

Нативное направление исходника задаёт `metadata/source_facing_x` выбранного
спрайта; при отсутствии метаданных используется экспорт `source_facing_x` корня.
`-1` означает влево, `+1` вправо; учитываются authored transform и `flip_h`.
Фракция не определяет направление текстуры. Для нового рисунка это часть его
настройки, включая фронтальную заглушку с условным направлением.
U2026-11-01: покой выбранных классов ориентирован по команде — PLAYER вправо,
ENEMY влево; source_facing_x задаёт необходимое отражение. Для Мага при отказе
скина этот же принцип применяет общий wrapper к BodySprite. Именованный класс
не получает случайный EnemyPreset; базовая сторона восстанавливается после атаки.
Base `sync_scene_art` обрамляет `_sync_scene_art_layers`: восстанавливает
предыдущую позу, синхронизирует слои и отражает только рисунок вокруг опоры.
Производный unit-пресет расширяет hook слоёв, сохраняя общий wrapper.
Процедурный fallback получает тот же разворот тела. Текстуры/UV/материалы,
ArtRoot, EffectRoot/маркеры, HUD, тень, picking, клетка и сортировка прежние.

Проверки: unit_visual_contract, presentation_attack_styles/reactions и соседние
presentation/render suites по TESTING. Ручная оценка F5 остаётся отдельной.

## Покрытие полного кадра персонажа

U2026-11-02: все текстурные слои фигур в production `art_trial_unit.tscn`
используют общий `character_coverage.gdshaderinc`. Обёртки native_sprite и
character_palette сохраняют ссылки сцен. Промежуточная выборка на игровой
сетке128² удалена: каждый экранный пиксель собирает площадь пересечения со
всеми исходными текселями своего footprint (`fwidth`), без верхнего ограничения
радиуса. Это относится к still/idle/способности/смерти, legacy-слоям и NPC.
Для повёрнутых фигур footprint — осевой прямоугольник производных UV.
При целой позиции и масштабе1:1 выбирается исходный тексель без размытия.

`source_region` ограничивает выборку текущим кадром/кропом; нулевой размер
означает полную текстуру. Соседняя ячейка атласа не участвует в покрытии.
Native-слои сохраняют cutoff alpha0.5; generic Body/NPC — исходную alpha.
RGB-палитры и ткань применяются до суммирования с premultiplied alpha;
результат возвращается в straight alpha, modulate родителя/спрайта применяется
один раз. `native_size` больше не уменьшает рисунок: это только размер старой
сетки масок ткани, в которую отображается центр каждого исходного текселя.
У NPC отдельные материалы с их кропами; параметры PackedScene не мутируют.

PNG, геометрия, опоры, пикинг, направление команд, клипы и тайминги прежние.
Выбранные Маг/Лучница используют тот же skin-сэмплер; условная «М» остаётся
fallback. Земля, HUD и VFX не получают этот sampler.

[сравнение на сцене](art/character-coverage-20261102/README.md).

## Переключаемый ракурс 2:1 / 4:3 — 2026-11-22

U выбрал правую пробу2:1 и поручил попробовать её в игре с прежними тайлами,
покрытиями и персонажами, с быстрым возвратом. Авторские PNG/атласы, UV,
SpriteFrames и материалы остаются прежними; новые изображения не создаются.
Исходные сцены рисуют128×96, а `BattleDemoBoard.shallow_projection` выбирает
экранный верх128×64 или128×96. Authored `battle_board.tscn` включает2:1;
отдельный Board и `IsoGridConfig.DEFAULT_TILE_SIZE` сохраняют4:3.
Высотная ступень32, тела/колонны и вертикальная плотность кладки независимы.

Кнопка рядом с масштабом показывает текущий ракурс. `set_shallow_projection`
возвращает false без изменений при `execution_pending`; между действиями
перестраивает только опубликованное представление и очищает прежнее наведение.
Боевые snapshot/RNG/counters, профиль, выбор персонажа и ресурсы действий
не меняются. Размер сетки участвует в picking, направлениях и масштабе обзора.
Переключение относится к данному Board; новая сцена читает экспортируемый default.
Для постоянного возврата достаточно `shallow_projection = false` в
`scenes/demo/battle/battle_board.tscn`, без восстановления изображений/сохранений.

Terrain преобразует только GroundBase/SurfaceSprite/GroundSurface/DungeonWallTop
от сохранённых авторских масштабов. Боковины строятся по новой верхней грани;
их вертикальная глубина не сжимается. ArtRoot бойцов/колонны остаются равномерными,
наземные тени следуют новому ракурсу. Кислота, кальтропы, напольные ловушки и
огонь переиспользуют прежние кадры с проекцией поверхности; это не новый рисунок
и не новая анимация. У цельных растровых покрытий сжимается весь исходный растр,
включая нарисованный рельеф огня/шипов. Глубокая кислота остаётся ниже пола на8px.
Стеновые панели сдвигают наклонную плоскость без сжатия вертикали; направление
и длина вылета шипов учитывают новую сетку. Исходные points/UV не переписываются.
Повторный sync и возврат4:3 не накапливают масштабы; кадр/фаза огня сохраняются.
Проверки и реальные кадры — [пакет внедрения](art/projection-2x1-runtime-20261122/README.md).
Ручная приёмка ракурса, перекрытий и движения остаётся за пользователем.

### Смерть Защитника

U2026-10-12 принял вариант №3 с гримасой и восстановленной бородой.
Прежний пресет `art_trial_unit` использует `death_frames`/`death` из
[пакета ассетов](../assets/art_presets/trials/defender_death_v1/README.md):

death-2 на2,55с из раздела выше с теми же правилами playback.

Защитника; заморозка/оглушение его не запрещают. Классы и сцены без
клипа сохраняют общее вращение/сжатие/затухание. В клипе рисунок не получает
дополнительный поворот, сжатие или полупрозрачность.

Показ обычной смерти удерживает before до конца клипа, затем штатно публикует
after и тело окружения. Это касается ближнего/дальнего удара, mage.fire,
столкновения цепочки и остальных ground-death событий. Длительность жертвы
не растягивает выпад/возврат атакующего, отдачу или эффект мага. У цепочки
контакт остаётся началом клипа, after звена ждёт смерть, возврат тел идёт
в прежнем темпе; порядок публикаций не меняется. Падение за край, VOID/HAZARD
и обвал используют прежний fall-путь, без клипа с коленом и без тела.

Единственные часы — общий Tween с прежними speed/pause/skip/cancel. Progress
хранится в полевой позе; reset/apply при resize и затем restore восстанавливают
тот же кадр. Публикация, skip/cancel/retire/exit снимают временный клип; локального
таймера или callback смерти нет. Runtime/queue/preview/RNG/save не меняются.
Пользовательская приёмка текущих переходов —
[ART_DIRECTION](ART_DIRECTION.md#завершение-утверждённого-персонажа--2026-10-12).

### Проверки

Команды и состав проверок — [TESTING](TESTING.md). Выбор `current_art_zoom`,
`art_trial_battle` или `battle_view_reuse` автоматически включает три lifecycle
runner: `visual_scene_contract`, `environment_visual_contract`, `unit_visual_contract`,
`defender_idle_clock`, `defender_idle`, `defender_buff`, `defender_death`, `defender_death_routes`,
`defender_cloth_palette`, `rogue_cloth_palette`, `archer_cloth_palette`,
`rogue_animations`, `rogue_buff`, `rogue_death_routes`, `archer_idle`,
а также `presentation_consequences`, `presentation_environment`, `battle_camera_ui`,
`battle_execution_ui` для поз, ловушек, камеры, worker/ИИ и смены UI.
Они также входят в full/render; инициатива этим не подключается.

Hard gate: совместимый новый PackedScene без регистрации в доске, неизменные
identity и счётчики создания/удаления при повторной публикации и обычном
движении, fresh values без revision, правка конфигурации на месте, отделение
тел, снятие/восстановление поз, удаление при смене владельца. Счётчики
`visual_lifecycle_counts` возвращаются копией и включают terrain/environment/unit.
Пассивные операции не меняют live snapshot/RNG/counters; исполнение движения
остаётся настоящим worker → публикации → показ. Более широкие сценарии эффектов,
камеры и порядка показа принадлежат существующим адресным runner.

Frame median/p95/max и число кадров >25ms — диагностические измерения при
обычном `_process`, без универсального порога PASS по времени. Для заявления
об ускорении нужны изолированные A/B одного сценария, parity результатов,
событий/шагов/RNG/counters/admission и несколько прогонов. Вложенные времена
не складываются. Эти проверки ловят возврат пересоздания и ошибки lifecycle;
они не гарантируют отсутствие всех фризов, GPU-стоимость или ручную F5-приёмку.
