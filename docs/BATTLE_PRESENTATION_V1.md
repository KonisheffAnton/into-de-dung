# Первый образец отображения боя — V1

Статус: первый образец реализован, но 2026-09-30 не принят пользователем по
темпу, читаемости, перекрытиям и блокировке UI. Отзыв и каталог точечных пакетов —
[переработка представления](BATTLE_PRESENTATION_REWORK.md); код V1 пока прежний.
Порядок работы и пожелания пользователя принадлежат DESIGN_DIRECTION §7:
предварительно пиксель-арт, конкретный стиль пользователь подберёт позже.
Основание реализации: `02309c3ef5957b309e75bc435ae207ee0f573117`, 2026-09-30.

## Наблюдаемый результат

Один бой на временных фигурах должен показывать, кто действует, где происходит
попадание и какие последствия вызваны. Движение идёт по исполненному пути;
удар, изменение HP/брони, реакция, толчок, падение и смерть читаются в порядке
реальных событий. Действия противника показываются последовательно.
Изменение состояния обозначается у затронутой фигуры; журнал сохраняется
как дополнительное объяснение. Точные намерения врага заранее не раскрываются.

Состав первого образца: существующее изометрическое поле и текущие фигуры,
движение, обычный удар/выстрел, внешний маг K18, реакции/пространственные
последствия, HP/броня/статусы и исход. Временная отрисовка показывает событие;
полноценные покадровые движения персонажей создаются вместе с их будущим артом.
Камера, интерфейс хаба/карты, состав механик и баланс не входят в этот пакет.

## Аудит receipt перед реализацией

До изменения `ActionReceipt` содержал упорядоченные events/steps, но не полный
вид промежуточного мира. Сверка по коду обнаружила следующие границы:

| Переход | Имеющиеся данные / недостающее |
|---|---|
| Движение | `MoveCommand`: from/to, transit_path, остатки; фактический путь уже явный |
| Удар/HP/реакции | `AttackCommand` и `ActionHpExecutor`: участники, оплата, HP/alive before/after, причинный порядок |
| Броня/контроль | Предметные дельты и before/after; нет единого полного вида фигуры/HUD |
| Призыв | `summoned`/`corpse_raised` не содержат всех отображаемых значений нового бойца |
| Граница хода | Несколько `_transition_root`; refill и AbilityBoundary меняют состояние без events |
| FAULTED | События сохраняют prefix; частичная мутация не обязана иметь отдельное событие |
| Публикация | UI делал полный refresh до private fall; H1 забирал исход сразу после join |

Поэтому реализация не восстанавливает мир из последнего receipt/финальных клеток.
Явные снимки каждого исполненного шага, все roots одного вызова и конечный снимок
описаны в [ARCHITECTURE](ARCHITECTURE.md#представление-боя--v1).

## Реализованное поведение

Обычный `BattleDemo` и `HeroHubBattleView` показывают пакет точной штатной
`BattleCoreReactionsSession`: движение по сегментам/транзиту, линию удара,
вспышки и подписи HP/брони/состояний/мага/реакций, цепной толчок и затухание
при смерти/падении. Это условные обозначения, не окончательные движения персонажей.
Показ одного атомарного шага завершается одновременной публикацией его снимка
на поле и в HUD; в этот момент видны HP, броня, состояния, ресурсы и мана/откаты.
Невидимые изменения refill/границы также имеют кадр. Итог фазы и переход похода
публикуются после последнего кадра. До него ввод и следующий шаг ИИ ждут.

Кнопка «Пропустить» / Пробел заканчивает текущий пакет на его конечном снимке;
«Скорость ×1/×3» меняет только темп Tween. Reset/выход отменяют старые callbacks
и отбрасывают пакет. FAULTED показывает фактически исполненные шаги, затем
диагностику остановки. Подробности блокировок и fallback принадлежат
[BATTLE_EXECUTION_UI](BATTLE_EXECUTION_UI.md#показ-после-исполнения--v1).

Порядок кадров связывает `BattlePresentationPlayer`, движение/вспышки исполняет
штатный Tween. Собственного движка ключевых кадров нет. Фабрика фигур доски
принимает `unit_visual_scene: PackedScene` с корнем `BattleDemoIsoVisual`;
без неё используется прежняя геометрия. Заменяющая сцена может содержать штатные
AnimationPlayer/AnimatedSprite2D; готовые клипы/спрайты пока не созданы.
Проекция `IsoGridConfig` по-прежнему начинается с тайла 128×64; это не принятый
размер будущего ассета. Высотное смещение отделено от Y-sort и при движении.

Рендер получает только отделённые значения. Animation callbacks не вызывают
команды, расчёт урона/RNG или изменение боевых позиций/ресурсов. Hover остаётся
изолированным прогнозом и не запускает показ. Неаудированный runtime и старые
демонстрационные сессии сохраняют прежний непосредственный refresh.

## Проверка готовности образца

Один воспроизводимый бой на текущем ядре: движение → удар → фактические
последствия → следующий действующий. Отдельно проверить пропуск/ускорение,
выход во время показа, смертельный исход и каскад реакции/толчка/падения.
Сравнить конечные snapshots, события, RNG и ресурсы с тем же боем без показа;
прогноз остаётся изолированным, hover не запускает боевые анимации.
Runner `test_presentation_capture.gd` проверяет value-only/изоляцию и parity,
`test_battle_presentation.gd` — настоящий UI, порядок кадров, пропуск/ускорение,
многокорневую границу, мага, цепное падение, терминальный H1, reset/exit и FAULTED.
Оба входят в full/render по TESTING; результаты этапа и ревью — HISTORY.
Это не повторная ручная приёмка каждой механики ядра.

Стиль, палитра, персонажи, размеры/направления спрайтов и схема их анимации
остаются открыты. Не выпускать финальные ассеты и не закреплять их формат
до выбора пользователя; временный образец должен позволять заменить отрисовку.
