# Владение исполнением и представлением общего боя

Реализованная граница 2026-09-26. В обычном `BattleDemo` для точного класса
`BattleCoreReactionsSession` движение, все нынешние действия, граница хода и
один шаг ИИ исполняются через `BattleExecutionWorker`. Расстановка и выбор
остаются на основном потоке. D4, инициатива, прежние fixtures и прямой session API
сохраняют синхронный путь. Это ограничение области, а не смена правил боя.
Безопасный отход [K14](SAFE_RETREAT_K14.md) входит в ту же передачу владения
через `retreat_to(Vector2i)`; новый объект runtime для него не требуется.
`click_attack(int)` использует ту же передачу: `BattleClickAttack` выбирает
допустимый подход на изолированной копии, затем вызывает прежние move/attack.
UI остаётся заблокированным для всей операции; capture сохраняет оба root
последовательно. Core-команды/codec не расширяются; правила — TACTICAL_BATTLE.
Ход окружения [K15](ENVIRONMENT_COLLAPSE_K15.md) входит в `end_player_turn`
того же worker; опубликованная проекция Board хранит также копию опасной отметки.
K17 передаёт `cast_unit(int)` тем же способом. ElementalState входит в проверенный
граф, выбранный эффект — scalar StringName; UI публикует значения новых статусов
и вид опасности после join. Правила пакета — [STATUS_EFFECTS_NEXT](STATUS_EFFECTS_NEXT.md).

## Передача владения

До запуска main очищает прогнозы и передаёт существующую session одному worker.
`session`, `_battle`, `board_view.session` у UI очищены; идентичность страницы
действий хранится числовым instance ID, без ссылки на session;
`is_execution_pending()` запрещает повторное действие, выбор действующего,
осмотр через runtime, подготовку прогноза и refresh. Отдельный осмотр показанной
фигуры использует только опубликованную проекцию доски. Камера поля также доступна:
её масштаб/сдвиг меняют только canvas-преобразование показанных узлов. На main
остаются значения завершённого представления. Ссылки на runtime, ранее полученные внешним кодом, нельзя читать
или менять между start и join; API не является общим конкурентным сервисом.

Worker принимает только перечисленные session-методы и скалярные аргументы
(ID, режим, Vector2i). Перед каждой передачей обходится граф session/state/context:
точные штатные классы, штатный RNG и пустой ActionEventSink, отсутствие внешних
подписок на runtime и Resource. Единственная разрешённая подписка — проверенный
синхронный callback смерти именно этой доски/юнита/vitals. Неизвестный класс,
Callable/Signal в данных, внешний listener, превышение лимита обхода или ошибка
старта потока возвращают исполнение на основной поток. Подписки не отключаются.
Завершённый receipt не исполняется повторно и не входит в обход; очередь входит
в аудит, должна иметь точный штатный класс и быть свободна.
Проверка владения не сертифицирует допустимость мира и не кэшируется по revision.

В потоке исполняется настоящий session-метод с pathfinding/BT, строгим admission,
ActionQueue, синхронными внутренними callbacks и всей очередью реакций. Отдельного
preview/commit или отката нет. RNG, ID помощников и counters принадлежат runtime;
этот путь не вызывает глобальный UnitId allocator. Session проверяет исход после
полного submit; INTERRUPTED/FAULTED сохраняют прежний выполненный prefix.

Main опрашивает окончание без ожидания и получает session/result через
`wait_to_finish` только после завершения. Затем возвращает владение UI и передаёт
результат показу V1 ниже либо прежнему полному refresh. Пока результат не принят, следующий
шаг ИИ не запускается. Reset, смена сценария и выход сначала join; прежний result
отбрасывается, только затем runtime закрывается/пересоздаётся. Это ожидание может
задержать сам reset/выход, но не обычные кадры ожидания команды.

## Показ после исполнения — V1

Обычный покадровый опрос руки колоды (`mage_card_reasons`) сохраняет один общий
capability-аудит на запрос. Он видит прямые изменения runtime без смены revision;
сведения о бойцах получает через проверенный короткий DTO UnitState
(владение и полный объём проверок — ARCHITECTURE). Результат между кадрами
не сохраняется; этот опрос не заменяет проверку перед worker/submit.

Для точной `BattleCoreReactionsSession` worker в `start` сначала проверяет
запрос и полный `can_transfer`, затем при флаге показа собирает before и включает
capture до запуска потока. UI забирает только отделённый before через
`take_presentation_before`; runtime к этому моменту уже закрыт для UI.
Повторного аудита того же графа между подготовкой показа и запуском нет;
результат проверки не сохраняется для будущих вызовов. Sync-only оболочка
по-прежнему сама проверяет `can_transfer` перед сбором кадров.
Если запуск потока не удался после успешного аудита, before и capture остаются
для единственного синхронного исполнения после возврата владельца UI.
Отказ запроса/аудита не включает capture. Capture работает при worker
и при синхронном исполнении того же аудированного runtime.
При отказе аудита/custom callback показ не включается; сохраняется прежний fallback.
Флаг `presentation_enabled=false` также оставляет непосредственную публикацию.
Состав пакета принадлежит ARCHITECTURE, поведение и временные визуалы — V1.

После join runtime уже завершён и снова принадлежит main; показ читает готовые
копии, блокируя команды/выбор действующего/расчёт forecast/refresh. Наведение
и клик для краткого осмотра показанной фигуры читают только `BattleUnitView`
и копии статуса/брони из Board, не session. `is_execution_pending()` означает
worker **или** показ, `is_presentation_pending()` — только показ. `_process`
опрашивает worker отдельно и во время показа не обновляет мага/прогноз/ИИ.
`HeroHubScreen` тем же общим guard откладывает outcome/save/переход до завершения
показа; `HeroHubBattleView._refresh` не раскрывает терминальный исход раньше него.

На атомарной границе кадра поле, HUD и цифры результата получают одно after; финальный refresh
разрешён после последнего кадра/пропуска. Журнал roots не дублируется через
turn_events. Кнопки скорости/пропуска доступны при заблокированном игровом вводе.
В основном бою/H1 игровые слоты остаются видимы и отключены до конца показа.
Диагностика открывается поверх поля и не меняет его размер. Подробные прогнозы
и реестр сохранены в этой области; краткий осмотр доступен без её открытия.
Reset/смена/выход отменяют Tween и пакет, затем соблюдают прежний join worker;
никакие отложенные команды из анимации не создаются. Снимки не читаются по revision.
Остаточная жизнь цифр/импактов не входит в execution_pending: естественное
завершение пакета разрешает следующую команду, сохраняя подписи. Пропуск/отмена
очищают их; outcome/save H1 ждёт основной клип, но не окончание затухания чисел.

## Согласованный вид

Постоянный HUD основного боя/H1 загружается из редактируемых сцен; карта узлов,
границы authoring/runtime и совместимость — [BATTLE_HUD_SCENES_V1](BATTLE_HUD_SCENES_V1.md).
Это меняет сборку представления, но сохраняет описанные выше границы чтения сессии.

`BattleUnitView` содержит значения ID, фракции, имени, HP, равновесия и пределов.
`BattleDemoIsoVisual` не хранит UnitState/StatsBag/Vitals. `BattleDemoBoard.refresh`
захватывает высоты, terrain, клетки бойцов, визуальные флаги, броню и среду.
Redraw, resize, overlays и геометрия используют эту проекцию; при pending
`cell_at` для боевой команды заблокирован. `displayed_unit_at` проверяет те же
показанные фигуры/перекрытия для осмотра, без допуска команды. Ввод клетки/фигуры
сначала проходит обратное преобразование камеры; оно не вызывает refresh или
расчёт прогноза. Управление камерой — BATTLE_PRESENTATION_REWORK. Текст и descriptors
также сохраняют последний завершённый вид; статус сообщает об исполнении.
Полный список состояний со стаками/единицами срока, равновесие и остатки ресурсов
для подсказки фигуры/компактной строки берутся из тех же копий Board. Обновление
кадра и обычный refresh обновляют уже открытый осмотр, без чтения session из hover.
Свежий refresh обновляет и прямые изменения без revision. Это presentation DTO,
не save-game и не допуск команды. Старые отложенные redraw не держат live unit.
DTO включает `action_areas` с клетками/источником/готовностью реакции. Подсветка берёт
эти скопированные значения; во время worker сохраняет последний вид, а показ
обновляет зоны вместе с after кадра. Два дополнительных назначения кнопок
принадлежат session образца, не слотам сохранения; лимит/каталог — BATTLE_PRESENTATION_REWORK.

Подготовленные прогнозы по-прежнему изолированы и могут завершиться параллельно;
их устаревшие результаты не публикуются. Клик не ждёт прогноз и заново проверяет
состояние при исполнении. Механизмы прогнозов принадлежат ATTACK_FORECAST.

## Проверки и границы приёмки

`test_battle_execution_worker.gd`: sync/worker receipts, snapshots, RNG/counters,
ресурсы/ID, все действия, обе границы и шаги ИИ, отказ и FAULTED, запрет внешних
callbacks/custom RNG/sink. `test_battle_execution_ui.gd`: настоящий клик,
изоляция вида, все входы во время pending, resize/redraw, публикация helper,
синхронный callback fallback, reset/смена сцены/выход, FAULTED и PNG.
Связанные прежние UI runner ожидают именно завершение live job до чтения runtime.

Подготовка прогнозов, аудит владения, refresh и перестройка узлов остаются на
main и имеют измеримую стоимость. A/B на одной машине не гарантирует плавность
всех состояний; результаты и текущая пользовательская оценка — HISTORY/отчёт.

Прогноз границы хода K13 использует отдельный `TurnForecastWorker`: ему передаётся
отделённый пакет, из которого создаётся изолированная сессия без reset. Живой
session остаётся у UI либо live-worker по прежнему правилу; прогноз не получает
ссылку на него. Публикация проверяет поколение/session/выбор/revision/фазу,
refresh перечитывает мир без revision. Выход присоединяет поток. Поведение и
граница до первого решения ИИ — [ATTACK_FORECAST §K13](ATTACK_FORECAST.md#k13--прогноз-завершения-командного-хода).
