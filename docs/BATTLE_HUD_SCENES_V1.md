# Редактируемые сцены боевого интерфейса

2026-10-04. Поручение «Приступай»: постоянная разметка основного боя и боя
из хаба перенесена в Godot .tscn. Игровые правила и владение worker/runtime
остаются в [BATTLE_EXECUTION_UI](BATTLE_EXECUTION_UI.md); правила колоды —
[MAGE_DECK_V1](MAGE_DECK_V1.md). Перенос не закрывает ручную приёмку и финальный арт.

## Что открывать в редакторе

Все компоненты находятся в `scenes/demo/battle/`:

| Сцена | Что редактировать |
|---|---|
| `battle_hud.tscn` | Фон, отступы, заголовок/фаза, расположение панелей, управление ходом/показом, диагностика, журнал, подробный прогноз и осмотр |
| `hero_hub_battle.tscn` | Оболочка боя из хаба с экземпляром HUD; игровую сессию передаёт хаб |
| `action_bar.tscn` | Четыре вертикальных слота героя |
| `action_bar_legacy.tscn` | Восемь горизонтальных слотов прежних демонстраций |
| `mage_bar.tscn` | Ряд мага и управление страницами; заклинания и слоты руки заданы внутри экземпляра в `battle_hud.tscn` |
| `mage_card.tscn` | Шаблон кнопки карты: значок, шрифт, размеры |
| `hud_button.tscn` | Общий стиль кнопок HUD |
| `roster_entry.tscn` | Шаблон строки персонажа в диагностическом списке |
| `battle_board.tscn` | Область поля, экземпляры компактного прогноза и управления камерой |
| `camera_controls.tscn` | Кнопки масштаба и возврата камеры |
| `forecast_card.tscn` | Фон, отступы и шрифт компактного прогноза |

Открывать во вкладке 2D/Inspector. Для вложенных сцен открыть исходный .tscn
либо включить редактирование дочерних узлов экземпляра. Имена узлов и типы —
привязки к presenter-скриптам; их переименование требует обновления кода.
Числа, названия действий, доступность, выбранная карта, текущая фаза и подписи
состояния приходят из runtime. Содержимое диагностического списка появляется
при запуске; карточку можно оформлять в её сцене-шаблоне. Скрытые заклинания
и слоты руки включает pager по доступному набору, а не редакторское `visible`.

Ширина компактного прогноза и отступы от поля задаются экспортами
`BattleForecastCard` на экземпляре `CompactForecast` внутри `battle_board.tscn`.
Его положение/высота вычисляются по цели, тексту и границам поля; размеры кнопок,
панелей, шрифты и theme overrides при обновлении не переустанавливаются.
Кнопочные подсказки используют обычный `tooltip_text` Godot с текущими данными.
Диагностика закреплена справа внутри окна и рисуется выше слоёв поля/прогноза.
Клетки, фигуры, зоны и эффекты по-прежнему строятся из опубликованной проекции;
они не являются постоянными узлами HUD.

F5 проверяет настоящий маршрут меню → хаб → поход → бой → итог.
Для отдельного боя — F6 на `scenes/demo/core_reactions_battle.tscn`.
F6 компонента/`hero_hub_battle.tscn` не создаёт профиль и поставляемую сессию.
Python или генерация сцен для обычного запуска не нужны.

## Владение и совместимость

`BattleDemo._build_authored_hud` один раз связывает существующие узлы с прежними
обработчиками. Основная сцена и `HeroHubScreen` создают полный authored-экземпляр;
прямой `HeroHubBattleView.new()` загружает ту же разметку при инициализации.
Повторное связывание не дублирует обработчики. Обновления и after-кадры сохраняют
постоянные экземпляры и overrides. Строки runtime-списка сохраняются по unit_id
в пределах одной сессии и вида оболочки; обновляются текст, доступность и порядок.
Ушедшие ID удаляются, новые получают шаблонную строку. Смена сессии/оболочки
сбрасывает только runtime-строки; добавленные автором узлы списка сохраняются.
Обработчик подключается один раз и разрешает ID в текущей сессии только при
живом клике. Во время показа текст и состав списка берутся исключительно из DTO.
Шаблон `roster_entry.tscn` удерживается как PackedScene в BattleDemo, чтобы
каждая строка не загружала повторно сцену и тему. Узлы строк остаются отдельными
экземплярами; авторская сцена и её общие ресурсы при обновлении не меняются.

`BattleActionBar` и `BattleMageBar` связывают именованные узлы, меняя лишь данные
и доступность. Pager сохраняет экземпляры и нажатия при неизменной видимости.
Их прямые `.new()` используют те же сценовые шаблоны. Старые демонстрации и D4
сохраняют прежнюю оболочку и восемь слотов, главный бой/H1 — четыре.
Кнопки сценариев в хабе скрываются по NodePath независимо от редактируемой подписи.

HUD не владеет командами, очередью, RNG или сохранением. Во время исполнения
показывается прежняя опубликованная проекция; после join — готовые after-кадры.
Живой клик, hover/preview, барьер outcome/save и завершение показа не меняются.
Визуальные ширины не кэшируются по revision.

## Проверки

`test_battle_hud_authoring.gd` проверяет оба входа до _ready, сохранность узлов,
размеров и шрифтов после binding/refresh/after-кадров, identity/смену состава
runtime-строк, новую сессию и оболочку, одиночные обработчики,
декорации внутри списка, видимые границы/слой диагностики, `.new()`/legacy
и неизменность снимка/RNG.
Runner включён в full/render; render сохраняет PNG основного и колодного HUD
с изменёнными настройками и открытой диагностикой. Команды — [TESTING](TESTING.md).
Прежние UI runner проверяют ввод, карты, камеры, worker и переходы.
Этот пакет не включает R11/R16/R17, новые правила, финальный арт или баланс.
