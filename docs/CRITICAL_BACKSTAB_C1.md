# C1 — крит, спина и минимальные состояния контроля

Этап выбран пользователем 2026-09-23 после D5/M1. Base игрового кода
`4329a48963fd64da2eade2417c52c7f4a3f25afa`; команда обновлена отдельным
коммитом `c172c7c`. Срез реализован; результаты проверок и приёмки — HANDOFF.

## Согласованные правила

Удар в спину — одна соседняя клетка: тыл PLAYER `(-1, 0)`, ENEMY `(1, 0)`.
NEUTRAL не имеет тыльной клетки. В нынешней изометрии PLAYER начинает со стороны
верхнего левого края; координаты экрана/zoom/pan не участвуют. Правило команды
действует и для помощников. Поворотов персонажей/карты нет.

Бонус спины +50% от B = Сила + Оружие до брони. Надбавка складывается с высотой,
не умножается на неё; спина не усиливает дополнительные компоненты огненной руны,
impact, collision/fall. Крит срабатывает по цели, которая **оглушена или опутана**.
Два состояния одновременно дают один крит: ×2 ко всему прямому удару (включая
дополнительные компоненты) до защиты и ×2 к воздействию на равновесие.
Крит применяется после суммы надбавок спины/высоты. При B10, высоте +20%, спине
+50%: 17 без крита, 34 с критом. Стойка/броня/сопротивления сохраняют свои стадии.
Крит не удваивает collision/fall/шипы/состояния и не использует RNG.

Пользователь уточнил путы: повышают устойчивость. Подтверждён порог BALANCE_MAX
×2, без постоянного изменения stats; иммунитет при нулевом пороге сохраняется.
Успешный принудительный сдвиг снимает путы. Стена, перепад без сдвига и столкновение,
при котором цель осталась на месте, не снимают. Если блокер погиб и цель затем
переместилась, путы снимаются после перемещения. Оставшееся оглушение сохраняется.

Рабочая граница первого сценария: оглушение запрещает добровольные действия;
опутывание — только добровольное движение. Принудительное движение разрешено.
Состояния заданы при старте и истекают в конце ближайшего хода своей команды.
Выбор персонажа не снимает состояние и не восполняет ресурсы; конец хода доступен.
Способности наложения, обновление срока в середине хода и иммунитеты — следующий
отдельный срез, не подразумеваются реализованными.

## Технические границы

Включение явно через данные AttackDefinition; прежние defaults выключены.
Старые три профиля, frozen receipts и эталоны D1 сохраняют прежнее поведение.
Capability контроля поддержана атаками spatial/armor; non-spatial атака с ней
явно отклоняется `control/spatial_required`, без молчаливого обхода состояний.
Новый игровой вход — отдельный сценарий на базе брони; D4 и его профиль не меняются.
Общий AttackCommand исполняет атаки обеих команд; ИИ использует ту же механику,
специальный поиск пути к спине не входит в C1.

Определение и helpers расчёта копируются/проверяются AttackRules. Modifiers
вычисляются до оплаты из live-позиций и состояния цели. Цена остаётся 1 main.
В binding передаются отдельно неизменная B для collision и усиленный impact.
Изменение коэффициента спины задаётся данными; постоянные stats не меняются.

Runtime состояния контроля — отдельный RefCounted, nullable capability UnitState.
Строгая сериализация/изоляция обязательна. Старые canonical снимки производятся
без новых пустых полей. Unit schema 6 добавляет обязательный
`control={schema_version:1,stunned_turns:int,entangled_turns:int}`, сроки 0..1.
`action_resources` обязателен; armor/bleeding/guard сохраняют исходные формы
своих capability. Контроль допускается и без брони. Board/Item envelopes не
меняются; номера Unit 6 и Item 6 (шаблон помощника M1) независимы.
Все внешние snapshot-пути должны признавать состояние и отклонять malformed,
не скрывать capability через downgrade. Restore не пополняет ресурсы/предметы.

Снятие пут и истечение идут через команды и известные дельты pinned guard.
После callback проверяются прежние ссылки/значения; FAULTED сохраняет выполненный
prefix, без нового baseline. Нельзя менять BattleBoard ради формулы или состояний.
Новые события/метаданные строго проверяет очередь; старые события не расширяются
при выключенных новых возможностях. Проверять event/command limits.

Preview исполняет настоящую команду на полном изолированном снимке: состояния,
броня/вещи, ресурсы, RNG/ID, события и последствия. UI читает результат исполнения;
показывает тыл, «Удар в спину +50%», «Крит ×2», состояние и эффективный порог.
Снятие пут должно быть понятно из прогноза и журнала.

## Приёмка

- Тыл/перед/бок обеих команд, дальняя клетка, NEUTRAL, helpers; движение/толчок
  до следующей атаки, высота, legacy броня/стойка и новая броня/дополнительный тип.
- Крит по каждому состоянию, оба состояния, отсутствие состояния; 17/34,
  отдельный impact, неизменные collision/fall, отказ без оплаты и RNG draw.
- Запрет действий при оглушении; путы запрещают только движение, удваивают порог,
  снимаются после push, сохраняются при стене/занятой клетке; точное истечение.
- Unit/board/item snapshot, invalid/subclass/downgrade, legacy bytes, копии;
  forecast/live и неизменность оригинала; callback mutation и FAULTED prefix.
- Новый сценарий: настоящий SubViewport input/scroll, PNG с маркером тыла,
  прогнозом спины/крита, снятием пут; reset/ИИ и командные ходы.

После адресных тестов import/startup, full/render по TESTING, осмотр PNG,
независимое ревью фиксированного результата. Frozen P02–P08/§4.5 и Q1–Q6 прежние.
Не запускать новые артефакты/контратаку/Оппортуниста/горение/M3–M4/графику/экономику.

## Владельцы реализации

`AttackDefinition.backstab_bonus_percent` (0..1000, default0) и
`critical_on_control` (default false) копируются AttackRules и разрешены только
для spatial/armor. `AttackModifiers` определяет rear-cell; расчёт хранится в
AttackDamageCalculation/ArmorAttack. BalancePushRules готовит effective impact
и порог; BalanceCommand передаёт множитель порога в Vitals.add_spatial_impact.
Vitals не знает состояний и не переписывает базовую характеристику.

`ControlRules` проверяет добровольные команды. `ControlTurnEndCommand` строит
отдельные ControlExpireCommand по ID; внешний submit дочерней команды запрещён.
PushCommand снимает путы после успешного move/checkpoint и переносит известную
дельту через SpatialRules.Guard.control_phase. `control_changed` содержит
target_unit_id, before/after DTO и reason push/turn_end. Новая атака дополняет
attacked полем `modifiers={backstab_percent:int,critical:bool}`; очередь проверяет
точную форму. Старое определение не добавляет поле.

`BattleControlSession`/`control_battle.tscn` — отдельный вход; AI вызывает тот же
AttackCommand. UI показывает реальный forecast/events, а направление стрелки
рисует по разности проекций клеток (смещение карты не меняет вектор).

В [K2](CORE_READINESS.md#k2--общий-игровой-сценарий-c1d3d5) те же опции
включены в оба определения D3, без изменения их bleeding policy.
`BattleCoreCombinationSession` завершает контроль исходящей команды перед
унаследованным bleeding/refill входящей. После FAULTED или конца боя дальнейшие
стадии и смена фазы запрещены. Первые шесть персонажей имеют ControlState;
прежний помощник D5/M1 остаётся с nullable control. Наложение контроля не добавлено.
