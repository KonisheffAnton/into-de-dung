## Почему изменён фильтр

При native_size512 одна ячейка отображалась в0.1825 экранного пикселя при100%:
0.25×0.73. Шейдер интегрирует максимум2 ячейки на ось, тогда как нужно около5.48;
выбор неполного покрытия давал зернистость на мелких деталях. Сетка128 соответствует
PixelLab-исходникам, каждая ячейка занимает0.73 пикселя. Полная PNG читается через
тот же source_region: ни обрезания, ни изменения исходного файла нет.

В idle часть кадров содержит сохранённые субпиксельные сдвиги:128→512 nearest
побайтно воспроизводит только3из12 кадров (`grid-source-check.json`). Они не
перезаписаны. Отображение теперь выбирает фиксированную128-сетку, сглаживая часть
таких деталей. `capture-grain.gd` сравнивает прежний и новый материал на тех же
PNG при75/100/125%; результат менее зернистый, немного мягче. Ручная оценка отдельно.

## PixelLab и отбор

Один `edit-images-v2` job `cfb5168d-7db7-4ca7-88e8-4ef8a5e5f8db`, completed,
2PNG,10generations. Вход — прежний крайний развод в двух экземплярах и крест
как reference. Заказаны два этапа приближения к максимуму; запрос, исходныеSHA,
ответ и extraction сохранены. Сервис меняет позы, локально они не рисовались.

Промежуточный вариант с прежним максимальным кадром после двух новых отклонён:
он смещал ступни вбок на2–3 native px. Итог заканчивает развод новой второй позой,
общей по опоре с первой, затем удерживает её. Прежний максимум сохранён в inputs/peak.png
для сравнения, в manifest не входит. Новая конечная ширина примерно на3 native px
меньше прежнего пика и остаётся широкой. Меньшее перемещение рук к концу вместе
с увеличенной задержкой даёт затухание, без программного tween поз/оружия.

По прежнему разрешению U исправлены только слишком тёмные RGB новых B1 PNG:
891/880пикселей заменены на#211e21; alpha/координаты и остальные RGBA неизменны.
`buff-palette-correction.json` хранит аудит. Смерть, idle и still не перекрашены.
Лязг здесь трактуется как характер движения; звуковые ассеты не создавались.
