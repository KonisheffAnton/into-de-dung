# Защитник: цельное движение и более сильный вызов

U2026-10-11 выбрал продолжить здесь и «Ещё усилить вызов и сгладить движения».
Следующий вариант — цельная анимация PixelLab вместо повторения контактной позы
в [предыдущем монтаже](../defender-shield-taunt-defiant-20261011/README.md).
Все прежние пробы сохранены. Это отдельный кандидат, без подключения к игре.

Постановка: подать щит и грудь вперёд, слегка поднять подбородок, сделать два
сильных удара плоскостью меча по собственному щиту с видимым отводом между ними,
ненадолго удержать вызывающую стойку и связно вернуться. Дуги плеча/локтя/кисти
должны быть плавными, контакты — короткими. Стопы остаются на месте.
Без вспышек, звёзд, частиц, лишних ударов и новых мелких деталей.
Это требования запроса, не утверждение о полученном результате.

## Полученный кандидат

Основное [превью с сокращёнными паузами](preview-compact.gif):33 кадра,2.27s.
Сохранены все исходные позы и порядок; изменено только время почти неподвижных
участков01–08/25–32 до40ms, последней стойки до350ms. Внутри ударов09–24
осталось80ms на каждый кадр. Контактные позы вручную не повторяются.
Также сохранены [равномерное превью](preview.gif), [native GIF](taunt-native.gif)
и [раскадровка](filmstrip.png). Их длительности3.11s и2.64s соответственно.

Completed получен23:10 MSK:33 PNG128×128 (входной +32), списаны5 генераций.
[Usage/хеши](pixellab/result.json), [размер/alpha/тайминги](validation.json).
Первый кадр совпадает с эталоном по RGBA, хотя PNG перекодирован; последний
визуально близок, но не пиксельно идентичен. Нижняя граница alpha y97 во всех33.

Ведущий и независимый просмотр: два самостоятельных удара10–14 и19–22,
видимый отвод15–18; связки плавнее прежнего монтажа, опора визуально стабильна.
Остаются запрещённые белые дуги10/19, искры11/20 и остаток дуги12.
Подбородок не поднят, вызывающая подача груди/щита слабее постановки.
Независимый вердикт — APPROVE для честного показа кандидата, REQUEST_CHANGES
для окончательной арт-приёмки. Сокращение пауз усиливает ритм, но не исправляет
рисунок поз или эффекты. Арт-приёмка и проверка в игровом размере открыты.
Игра не менялась; новый кандидат к способности не подключён.

## Источник и запрос

Тот же текущий Защитник в шлеме, не Ветеран.128×128 эталон vertical idle передан
как first_frame и last_frame. Стиль — [ART_DIRECTION](../../ART_DIRECTION.md),
провайдер/секрет — [GRAPHICS_WORKFLOW](../../GRAPHICS_WORKFLOW.md).

- [Манифест](request-manifest.json), [полный запрос без секрета](pixellab/request.json).
- [Эталон](pixellab/reference-128.png), [принятие](pixellab/response.json),
  [итог отправки](pixellab/submission-status.json).
- Один `POST /v2/animate-pixminimax`,32 кадра, seed20261013, no_background=true,
  enhance_prompt=false; переданы subject_description, initial_pose, view и direction.
- Перед отправкой сверена [официальная схема](https://api.pixellab.ai/v2/openapi.json):
  этот режим поддерживает4–40 кадров кратно4. Выбран ради более длинной связной
  хореографии; смена режима не является доказательством более высокого качества.
- Принят с первой попытки22:59 MSK: `dc079ff9-c657-44cd-8eaa-3ca5fe4dbded`.
  Продолжать только GET этой задачи; новый POST автоматически не выполнять.

## Упаковка

После completed сохранить raw JSON в игнорируемом
`test_reports/defender-shield-taunt-fluid-20261011/job-latest.json` и из корня:

```powershell
python docs/art/defender-shield-taunt-fluid-20261011/extract-result.py test_reports/defender-shield-taunt-fluid-20261011/job-latest.json
python docs/art/defender-shield-taunt-fluid-20261011/prepare-preview.py
```

Pillow нужен для превью. Extractor сверяет принятый job id и защищает сохранённые
PNG от подмены. Сохраняются все фактически полученные кадры без изменения;
по документации API добавляет входной кадр к запрошенным32.
GIF использует исходный порядок без повторов/разворота/интерполяции ведущим,
80ms на кадр; в увеличенном превью последняя стойка550ms между повторами.
Nearest и тёмный фон служат только просмотру. Техническая проверка файлов,
независимый визуальный просмотр и приёмка пользователя — отдельные этапы.
`preview-compact.gif` использует отдельные задержки выше; они также проверяются
по фактически сохранённому GIF. Это настройка темпа, не генерация новых кадров.
