## Что получилось у D

В API переданы исходник 64² и управляющая RGB-маска: белый прямоугольник
`x=29..38, y=29..37` (90 px) внутри шарфа, остальное чёрное. Это запрос
дорисовки провайдеру, не ручная подмена исходника или склейка готовых кадров.
Все RGBA-пиксели **вне маски совпадают с входом** в каждом из четырёх ответов:
стопы, лук, руки, голова и внешние контуры остаются неподвижными.
Проверка: [mask-preservation.json](variants/d-mask-64/mask-preservation.json).

Внутри маски провайдер изменил 82/85/85/84 px относительно входа. Между
соседними кадрами различаются 20/13/13 RGBA-пикселей, на шве 4→1 — 15;
alpha не меняется. Это лучшая фиксация геометрии в серии, но не доказательство
естественного дыхания: виден переход складок, а 64² теряет детали.
Принятие или отклонение остаётся за пользователем.

  Уменьшение входов равномерное nearest, без ручных правок поз/alpha.

  [первой пробы](../archer-idle-pixellab-20261014/README.md), SHA256

  `clean-64.png` — его nearest-уменьшение для D. Это не большой статичный рисунок.
- [variants.json](variants.json): endpoint, seed, состав входа, размеры, SHA

  метаданные ответа/job, исходные frame-*.png с SHA в result.json, два GIF,
  filmstrip и motion-measurements.json.
- [prepare.cjs](prepare.cjs) готовит входы; [extract.cjs](extract.cjs) извлекает

  OpenAPI/сырые ответы из ignored-отчёта. Готовые PNG и просмотр от них не зависят.
  Эти скрипты не отправляют API-запросы.
