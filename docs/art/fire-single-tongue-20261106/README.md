## Сборка

Из исходников `fire-low-24.png` и `fire-low-29.png` размером 1254² выделены
30 и 26 существующих мазков. Прозрачные входные crop 128/256 сохраняют
исходные RGB; статические маски имеют единственного владельца каждого пикселя.
[Покрытие 24](field-inputs/coverage-fire24.png) и [29](field-inputs/coverage-fire29.png).
Мелкие остаточные пятна и рассеянный жар остаются на исходной неподвижной плите.
У 29 сохраняются мягкие акварельные мазки, без придумывания острых языков.

PixMiniMax получает отдельную нарисованную форму с указанием слегка согнуть
существующие кончики и вернуть их. Запрошенные 16 кадров дают 17 raw PNG.
Отбираются спокойные неизменённые позы; обратный показ этих же PNG замыкает
локальный цикл. Некоторые последовательности переставлены по измеренной
близости контура. Raw 0 исключён из-за отличающегося цвета.
[Порядок и SHA поз](field-selection/selection.json), [код отбора](field-selection/build.py).

Сборка накладывает raw RGBA на исходный тайл в постоянных целочисленных ROI.
Разные фазы мазков дают общий цикл 7,68 с: 96 слотов по 80 мс. Нативный canvas
1254² использует исходные PNG; уменьшенные 256² файлы служат только просмотру.
Никакой геометрической анимации или локальной перекраски при сборке нет.
[Описание просмотра и проверок](field-preview/README.md).

Отбор проверяет сохранность яркого ядра, границы crop, выход контура не более
4 нативных пикселей, яркость и оттенок. Явные искры и вспышки не используются.
Измеряются все 96 переходов, включая 95→0, яркость всего эффекта и ядра,
сохранность пикселей вне разрешённых областей. Точка 7,68 с совпадает с 0 точно;
видимый переход 95→0 оценивается отдельно и не объявляется одинаковым кадром.
Метрики ограничивают явные дефекты, но не заменяют художественную оценку.
Кадры с отдельными точками/полосами, найденными независимым просмотром,
исключаются целиком по явному списку; raw PNG не ретушируются.

## Контрольные пробы и ответы провайдера

- Первый полный crop `fire24-single01` добавлял рост/искры. Прозрачный отдельный
  мазок `fire24-cutout02` дал одобренный характер движения. Две inpaint-подложки
  `cleanplate03/04` отклонены из-за тёмных зазоров и в сборку не входят.
- На некоторых крупных 32-frame запросах цвет стал плоским красным. Изменение
  `drift_threshold` и обнуление скрытого RGB при alpha 0 этого не исправили.
  [Сравнение контролей](color-control-comparison/report.json) сохраняет свидетельства.
- Контроль 16 вместо 32 кадров при том же входе/seed/описании сохранил цвет лучше.
  Три `short`-контроля заменили отвергнутые `fire24-field10/29`, `fire29-field12`.
  Оставшиеся 44 неотправленных draft переведены на 16; старые payload сохранены
  отдельно. [Палитровый draft](palette-input/README.md) **не отправлялся**.
- Три первоначальных задания `fire24-field02/04`, `fire29-field02` после admission
  стали недоступны с HTTP 404. Их PNG и terminal usage не получены; изменение
  баланса на 15 не выдано за подтверждённый usage. Замены имеют отдельные ключи r1.
- `fire24-field18` временно получил `failed: GPU worker dropped this`, затем
  **тот же job** завершился. Повторного POST не было. Такой ответ удерживает
  занятый слот, а очередь продолжает GET того же ID.

Очередь допускает максимум три активных задания, сохраняет ответы каждого GET
и блокирует повторный POST после admission/barrier. Код и подготовленные запросы
хранятся здесь; точные ответы API и архивы draft — вне репозитория:
