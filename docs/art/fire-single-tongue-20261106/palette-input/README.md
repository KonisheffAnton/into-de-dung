# Неподанная проба палитры для PixelLab

Здесь подготовлен **неотправленный** запрос `/v2/edit-animation-v2`: [draft.json](draft.json). Он содержит base64 четырёх неизменённых raw PNG из `fire24-field29`: кадр 00 как исходный цветовой ориентир и кадры 12, 16, 20 с существующими позами. Body не выводится на экран. `metadata.json` фиксирует SHA каждого входа, body и использованной схемы.

[Палитра](palette-32.png) содержит ровно 32 RGB, которые реально встречаются в видимых (`alpha>8`) пикселях исходного `field-inputs/fire24/fire24-29/input-transparent.png`: 8 светло-жёлтых, 9 оранжевых, 8 охристых и 7 тёмных пограничных цветов. Яркие красные с `R>=220,G<105` исключены из целевой палитры. Полные значения и число исходных пикселей каждого цвета находятся в `palette.json`. [Контакт выбранных raw](selected-raw-contact.png) показывает исходный цвет и красное смещение трёх поз.

Схема снимка `openapi-before-post-fire24-field10.json` разрешает максимум **4 кадра при 256×256** в описании операции, хотя формальная `frames.maxItems` равна 16. Перед любым POST ведущий сверяет свежую официальную схему. Формулировка запрашивает изменение только цветов при сохранении формы, alpha, положения и движения; это условие запроса, а не гарантия модели. Даже удачный ответ будет отдельной короткой пробой и не заменит 33 исходных кадра или полную плитку.

Повторить подготовку: `python docs/art/fire-single-tongue-20261106/palette-input/build.py`. Скрипт читает существующие источники и raw, не отправляет запросы и не меняет исходные PNG.
