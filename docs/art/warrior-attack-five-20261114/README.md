# Воин11 — пять атак PixelLab

U2026-11-14 поручил пять вариантов атаки текущего Воина11 «Красный бастион».
Это пробы движения для выбора, `integration=false`; игровая атака не меняется.

| № | Заданное движение |
|---|---|
| 1 | Диагональный удар сверху вниз |
| 2 | Горизонтальный разрез на уровне пояса |
| 3 | Тяжёлый рубящий удар сверху |
| 4 | Прямой выпад с возвратом |
| 5 | Восходящий диагональный удар |

Каждый запрос задаёт один удар, подготовку, акцент, восстановление и возврат
в исходную стойку. Сохраняются модель, меч, пустая вторая рука, направление
влево, передний ракурс 3/4, неподвижная камера и положение в клетке.
Это требования промпта; соблюдение оценивается по полученным кадрам.
Противник, щит, магические следы и отдельные эффекты удара не запрашивались.

## Источник и задания

`model/input-256.png` — побайтная копия
`assets/art_presets/approved/character_skins_v1/red_bastion/still.png`.
Новых масштабирования, вырезания или ретуши нет. Холст256², опора(128,200).
[Происхождение и SHA](model/source.json), [пять промптов](requests.json),
[ID заданий и SHA запросов](jobs.json).

Перед отправкой сверена [официальная схема PixelLab](https://api.pixellab.ai/v2/openapi.json);
выдержка — [api-schema.json](api-schema.json). Использован `animate-pixminimax`,
32 запрошенных кадра, прозрачность, `enhance_prompt=false`, все четыре caption-поля.
Исходник передан также как `last_frame`; это направляющая, не гарантия точного шва.
Полные запросы/ответы и безопасный DPAPI wrapper находятся вне Git:
`C:/Users/Aston/.codex/generated_images/warrior-attack-five-20261114/`.
Отправлено ровно пять заданий; повторные POST не допускаются после маркера попытки.

## Просмотр и воспроизведение

[Автономная галерея](gallery.html) содержит все PNG-листы внутри HTML.
Она собирается из сохранённых артефактов, без сети и новых генераций:

```powershell
python docs/art/warrior-attack-five-20261114/export_pixellab.py
python docs/art/warrior-attack-five-20261114/build_gallery.py
python docs/art/warrior-attack-five-20261114/validate_package.py
```

Повторный экспорт требует локальных сохранённых ответов PixelLab. Исходные PNG
кадров сохраняются побайтно в `pixellab/attack-N/frames/` и хранятся в Git вместе
с PNG-листами, GIF и `clip.json`. На чистом checkout достаточно сборки галереи
и валидатора; повторно экспортировать не нужно. Только автономный HTML исключён
как воспроизводимый дубликат встроенных листов/GIF.
GIF повторяется для сравнения. Время показа задано локально:32×50мс и700мс
последняя поза; PixelLab возвращает позы без авторского тайминга.
GIF может объединять одинаковые соседние позы с суммой их длительностей;
PNG-лист и галерея сохраняют все33 кадра.
Локальные инструменты только упаковывают готовые позы, не рисуют движение.

## Границы

Получены5/5 завершённых заданий, по33 прозрачных PNG256². Фактический расход —
25 генераций подписки (по5 за клип): [usage.json](usage.json).
[Проверка пакета](package-validation.json):165 исходных кадров и ячеек листов,
прозрачность/непустота каждого кадра, SHA, первый видимый RGBA/alpha, точный
исходник, GIF2300мс и10 встроенных ресурсов — PASS. Все скрипты py_compile PASS.
[Независимое ревью](review.md) — APPROVE для упаковки, не приёмка движений.
[Проверка браузера](browser-check.json): пять карточек, pause/replay/step/scrub,
скорость/фон и квадратные canvas102/384px проверены через интерфейс.

Визуальные замечания по исходным листам (кадры от0):

- №1: на кадрах1–2 появляется второй клинок, кадр3 содержит широкую дугу;
  активная часть очень короткая, далее длинное удержание стойки.
- №2: на кадрах10–11 голубой след вопреки запросу без эффектов.
- №3: читаемый замах сверху; при контакте есть светлый след движения.
- №4: кончик меча обрезан слева на кадрах8–12.
- №5: восходящее движение сохраняет узнаваемость; остановку клинка оценить в движении.

У всех5 конечный RGBA-кадр отличается от исходника. Это отдельная проверка шва,
а не утверждение о видимом скачке одинаковой силы. Изображения не исправлялись;
дополнительных POST, локальной дорисовки или повторных генераций нет.
