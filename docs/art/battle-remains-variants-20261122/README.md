по3 варианта каждого состояния от каждого генератора. Это P для выбора;
конкретный вариант не принят, игровые ассеты/правила/сцены не заменены.

G: встроенный image_gen,3 изображения голых костей и3 правки с остатками мяса.
[Точные исходные промпты](prompts-universal.json), [правка свежести](prompts-fresh-exact.json),
[файлы костей](imagegen-files.json), [файлы свежих](imagegen-fresh-files.json).
Все оригиналы скопированы в imagegen/G-B1…3.png и G-F1…3.png без перерисовки.
Это крупные растровые концепты с пиксельной формой, не нативные игровые64px.

PixelLab: create-image-pixen для трёх костей64×64, edit-image-pixen для свежей
версии каждого исходника. [Runner](pixellab/run.py), запросы/ответы и PNG
в pixellab/PL-B1…3 и PL-F1…3. Фактический расход:6 generations, повторных
POST не было. Ключ используется только через настроенный DPAPI и не сохраняется
в артефактах. Проверена [официальная схема](https://api.pixellab.ai/v2/openapi.json);
использованный фрагмент сохранён в pixellab/schema-used.json.

[Листы](build_previews.py) используют только оформление и nearest-neighbour:
общий bbox пары по видимой alpha≥128, вписывание в54×38 внутри64×64,
затем увеличение×4. Порог выбирает рамку и не переписывает alpha оригиналов.
Масштаб концептов унифицирован для сравнения, но на реальном поле не проверен.
