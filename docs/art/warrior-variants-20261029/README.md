# Двадцать воинов на тайле — 2026-10-29

По U сделаны 20 отдельных концептов встроенным ImageGen. [Общий лист](contact-sheet.png),
[малый просмотр](contact-sheet-game-size.png), [варианты с номерами](variants.json).
Каждый `warrior-01.png`…`warrior-20.png` — сохранённый без обработки результат генерации.
[Промпты и происхождение](prompts.json), [SHA и размеры](sources.json).

Исходный [референс U](user-reference.png) задаёт пиксельный стиль. Поздние уточнения U:
сохранить компактные пропорции Защитника; вытянутые фигуры не подходят;
персонаж теперь без изометрического взгляда сверху, тайл остаётся изометрическим;
показывать фигуры сразу на тайле в предполагаемом игровом соотношении размеров.
Первые четыре вытянутых пробы в итоговую двадцатку не входят.

Для композиции использован прежний [эталон на тайле](../../../assets/art_presets/approved/warrior_format_v1/on-tile.png).
В запросах: крупная голова, короткие ноги/корпус, около 2,8 головы по высоте,
высота фигуры около 43–45% ширины тайла. [Промежуточная проба](layout-style-trial.png)
задаёт внешний вид варианта 01; для 02–20 вариант 01 задаёт композицию.
Генератор варьирует размеры, ракурс, кладку и позу: это концептное сравнение,
а не точная посадка готовых спрайтов в Godot. Тайл включён в каждый концепт.
Для выбранного варианта отдельно потребуются прозрачный исходник, точная опора,
единая пиксельная сетка и проверка в игровом размере. Выбор и приёмка U открыты.

## Галерея и сравнение контура

`gallery.html` — автономная локальная галерея: номера, крупный/малый просмотр,
увеличение выбранного варианта, переключение шести фонов и режимов контура.
Файл содержит копии всех PNG (около 61 MB), поэтому не дублируется в Git.
Воспроизводится из сохранённых исходников командой из корня проекта:

```powershell
node docs/art/warrior-variants-20261029/build_gallery.cjs
```

[Статическое сравнение до/после](adaptive-outline-comparison.png) снято с галереи.
Для опыта используется прежний прозрачный `warrior_format_v1/character.png`,
не один из новых концептов. Полы — настоящие текущие атласы шести биомов,
ячейка (0,0) каждого листа. Это отдельная демонстрация алгоритма.
Ромб 128×96; исходник персонажа 128²; scale 0,8; anchor (71,83).
Масштаб 1×/2×/3× увеличивает всю сцену целиком, не фигуру относительно пола.

Контур строится снаружи итоговой маски спрайта, на один пиксель базового canvas.
Он выбирает светлый цвет на тёмном фоне и тёмный на светлом локально у силуэта.
Для выбора берётся средняя яркость участка 5×5 до отрисовки персонажа.
Пиксели персонажа остаются прежними; полупрозрачный мусор с alpha <128
не порождает контур. Сам PNG не изменяется. На льду/песке край головы над
тёмным задником светлый, а край ног/оружия над светлой плиткой тёмный.

P для Godot: отдельная маска силуэта + фон, снятый до персонажей/HUD/контуров;
локальный выбор контраста, толщина около одного экранного пикселя;
пространственное усреднение и гистерезис/временная стабилизация при движении.
Нужны проверки пересечения фигур, окклюзии стенами, зеркала, zoom/DPI,
смерти/падения и границ биомов. Временная стабилизация и игровой шейдер
в этом пакете не реализованы; показана статическая пространственная проба.
Существующие маркеры выбора и тень остаются отдельными элементами сцены.

## Проверки

внутри спрайта 0 изменений; отключение контура даёт точное равенство до/после;
увеличение не меняет базовый растр, первая и повторная отрисовка совпадают.
