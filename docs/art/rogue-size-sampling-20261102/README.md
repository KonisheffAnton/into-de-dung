# Размер Разбойника и зернистость показа — 2026-11-02

База f9eea8b7da12dfa5aefa4c8e51d972c642de6765, main. U попросил уменьшить
Разбойника и объяснить потерю качества относительно превью.

В сцене изменён только `rogue_art_scale`:0.8→0.72, то есть−10% по каждой оси.
Исходная высота152px при texture_scale0.5 теперь даёт54.72px вместо60.8px
на тайле128. Масштабируются рисунок и picking; опора стоп, HUD, остальные классы,
selected idle3/death2/ability3, кадры и тайминги сохранены. Этот же профиль
уменьшает legacy fallback. [Контракт](../../CHARACTER_SKINS_V1.md).

## Причина различий с превью

Галерея рисовала исходный кадр256². Высота самого силуэта —152px; крупный PNG
концепта ещё подробнее. В игре тот же силуэт при базовом размере занимал60.8px.
Помимо этого нормального уменьшения работает отдельная операция:
`BattleCharacterSkinVisual._set_skin_texture()` задаёт `native_size=256×0.5=128`.
`native_sprite.gdshader` выбирает центры этой сетки из исходного региона256².
При таком отношении из каждой исходной области2×2 читается один texel;
остальные детали не участвуют в последующем усреднении покрытия экранного пикселя.
Мелкие контрастные детали поэтому пропадают либо превращаются в отдельные пятна.

Затем шейдер смешивает до3×3 логических ячеек по реальному экранному покрытию.
На тайле128 до правки одна логическая ячейка занимала0.8 экранного пикселя,
после уменьшения Разбойника —0.72; при дальнейшем уменьшении камерой ещё меньше.
`nearest` в Sprite2D не отключает эту обработку. Это не случайный шум;
это потеря/перераспределение мелких деталей при выборке и сильном уменьшении.
Подключение общего прежнего sampler к новым256² кадрам сохранило этот эффект.

Уменьшение Разбойника само по себе не исправляет зернистость. Для неё нужна
отдельная оценка чтения полного исходного кадра с корректным фильтром уменьшения
и, при необходимости, упрощения художественных деталей для реального размера.
Изменений производственного shader здесь нет: U отдельно просил объяснение.

## Диагностическая проба

[sampling_probe.gd](sampling_probe.gd) рендерит один и тот же первый idle-кадр
Щитоносца02, Воина11 и Разбойника02 на одинаковой геометрии тремя способами:
текущий sampler128, прямой nearest256 и покрытие полного источника256 с
расширенным окном до5×5. Для сравнения выключены текст/HUD и случайные фазы idle.
Каждая ячейка содержит рендер1× и увеличение этих же экранных пикселей2×.
Все три выбранных облика имеют нулевую поправку палитры. Шейдер пробы создаётся
только внутри fixture, не назначается игровым ресурсам.

Это сравнение причин различий, не художественная приёмка нового рендера
или проверка его производительности. Ручные F5/zoom/DPI и оценка стыков остаются.

[Сравнение выборки](sampling-comparison.png): слева текущий показ, в центре
прямой nearest, справа полное покрытие исходника. В правом варианте мелкие
детали усредняются спокойнее, края мягче; крупное превью он не воспроизводит
пиксель в пиксель. Между левым/правым рендером различаются2199/1936/1534 пикселя
для Щитоносца/Воина/Разбойника при неизменной геометрии. Это измерение различий,
не численная оценка красоты. Дальнейший выбор рендера — отдельное поручение U.
