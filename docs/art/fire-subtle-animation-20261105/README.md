# Низкий огонь: 12 проб движения

После [предыдущей серии](../hazard-animations-20261104/README.md) заказана новая проба по одному клипу для `fire-low-22`, `23`, `24`, `29`. Затем U уточнил: пламя должно просто ровно гореть и слегка колыхаться без вспышек; по три клипа на источник. Первые четыре уже отправленных запроса `01` сохранены неизменными; добавлены только `02`/`03` для каждого источника. [Происхождение уточнения](user-steering-20261105.json) хранит SHA первоначальных запросов и новые тексты. Итого ровно 12 авторизованных ключей. Входы — копии исходных RGBA 1254² и уменьшенные целые кадры 256² (LANCZOS), без кропа и ретуши. `requests.json` и внешние `request.json` сохраняют текст, seed, четыре caption-поля и SHA-256. Источник, кадры API и галерея не предназначены для прямой интеграции в игру.

Запрос: PixelLab `/v2/animate-pixminimax`, 32 генерируемых кадра с одинаковыми first/last, `no_background=true`, `enhance_prompt=false`, максимум три активных задания. Для `02`/`03` текст прямо требует постоянной высоты, яркости и покрытия, только очень медленного бокового покачивания существующих кончиков пламени на 1–2 пикселя в кадре 256². Это требование к модели, а не утверждение о результате. Перед каждым POST bridge проверяет актуальную официальную OpenAPI-схему и ставит барьер `submit-started.json`; неопределённый POST нельзя повторять. Секрет DPAPI существует только вне Git и используется bridge только как Bearer для `https://api.pixellab.ai`.

Первоначальная подготовка: `python docs/art/fire-subtle-animation-20261105/prepare_requests.py` только до первого POST; после начала запросы не перезаписывать. Дополнение `02`/`03` подготовлено `prepare_additional_requests.py`, которое проверяет SHA уже отправленных `01`. Экспорт: `python docs/art/fire-subtle-animation-20261105/export_pixellab.py`; проверка: `python docs/art/fire-subtle-animation-20261105/validate_package.py --verify-raw`; галерея: `python docs/art/fire-subtle-animation-20261105/build_gallery.py`; дрейф: `python docs/art/fire-subtle-animation-20261105/measure_drift.py`.

Художественная оценка требует просмотра всего цикла: листы из пяти кадров могут пропустить всплески. Технический PASS происхождения и упаковки не доказывает сохранение низкой высоты, каменных боковин, alpha или бесшовный стык. После этих 12 вариантов новые запросы не предусмотрены.

## Фактический результат

Все 12 admitted заданий завершены, по 33 кадра каждое. [Проверка](validation.json) подтверждает 396/396 исходных PNG-байтов API, листы, GIF и неизменённые входы: технический `PASS`. Первый видимый кадр каждого клипа совпадает со входом; полный RGBA первого и последнего кадра с входом не совпадает ни у одного из 12. [Расход](usage.json): 60 генераций, баланс подписки 4847 → 4787.

Покадрово просмотрены все 12 циклов: **0/12 соответствуют заданному ровному низкому колыханию**. Во всех появляются новые высокие языки, провалы в высоте/яркости или цветовые вспышки; конкретные события записаны в [наблюдениях](clip-observations.json), [автономной галерее](gallery.html) и [полноцикловых листах](all-frames/). Максимальное расширение alpha вверх относительно исходного bbox по клипам — 7–11 px, кроме `fire24-03`: 49 px из-за двух непрозрачных stray-пикселей в кадре 6 на верхнем краю холста. У этого клипа проверка прозрачного отступа — **FAIL**. [Метрики alpha](all-frame-alpha.json) и [метрики дрейфа](drift.json) используют нижнюю сторону `y>=150` как приблизительную область камня и сами по себе не доказывают неподвижность геометрии.

[Браузерная проверка](browser-validation.json) автономной галереи: 12 карточек в четырёх группах, управление паузой/кадром/скоростью/масштабом и отсутствие горизонтального переполнения при 390 px — `PASS`. Эти результаты оставлены как исходная подборка для решения U; в игру огонь не подключён.
