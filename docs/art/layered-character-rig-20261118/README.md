# Настоящий послойный персонаж — офлайн-прототип

U2026-11-18 прямо поручил сменные слои брони/оружия с общей анимацией,
меч и топор, без внедрения. База `main`: `c0b15f912bc6d9939d990ae25a2af111c1025266`.

## Просмотр

- [Открыть прототип](gallery.html): выбранный герой и четыре синхронных сочетания.
- [Общий цикл](overview.gif): лёгкая/тяжёлая броня × меч/топор.
- [Замена экипировки на одной позе](swap.gif): тело и суставы неподвижны.
- [Разобранный персонаж](exploded.png) и [фазы удара](motion-poses.png).

Можно менять экипировку прямо во время движения или на паузе, выключать
броню/оружие, показывать суставы и раздвигать детали. Режимы: общий цикл,
только дыхание, только удар. Ползунок времени останавливает движение.

## Как устроено

16 самостоятельных статических PNG находятся в `assets/`; `manifest.json`
хранит размеры, точки привязки, извлечение и SHA-256. Нагрудник, наплечники
и наручи выбираются независимо от корпуса и рук; меч/топор используют одну
точку кисти. Собственные pivots предметов совмещают рукоятку с этой точкой.
Шарф — постоянная верхняя часть текстуры корпуса поверх брони.

`rig.js:pose(timeMs,mode)` не получает экипировку. Он задаёт общую позу;
`render` применяет её к иерархии частей и выбирает только изображения.
Один цикл5000мс: дыхание, замах/удар/возврат, дыхание. Отдельный режим
удара повторяет общую последовательность за2000мс. Смена вещей не сбрасывает
часы, не меняет позу и не выбирает другой клип. Оба оружия намеренно имеют
одинаковые тайминги и траекторию: разную тяжесть здесь не моделируем.

Статика создана встроенным image_gen по игровому Воину; исходный атлас
сохранён в `parts-atlas-original.png`, ориентир — `reference.png`.
[Происхождение](provenance.json), [бриф](generation-brief.txt).
`extract_assets.py` извлекает ячейки4×4, определяет bbox по alpha>=128
с полем2px и уменьшает nearest. Движущиеся позы не генерируются провайдером:
локальная общая анимация разрешена именно этим запросом пользователя.
Это отдельное разрешение для данной пробы, не отмена PixelLab в других задачах.

`build_preview.py` встраивает PNG и JS в автономный HTML. `check_preview.py`
проверяет его в headless Edge без изменения фокуса ОС и снимает кадры
непосредственно с того же JS-рендерера для GIF; второй реализации движений нет.

```powershell
python docs/art/layered-character-rig-20261118/extract_assets.py
python docs/art/layered-character-rig-20261118/build_preview.py
python docs/art/layered-character-rig-20261118/check_preview.py
```

## Проверки и границы

[Браузерные проверки](browser-validation.json): совпадение трансформаций тела
и точки оружия для4 сочетаний в125 моментах,500 показов без касания края
непрозрачными пикселями, движение/возврат цикла, смена экипировки без сброса
времени/паузы, отключение слоёв и разбор. [Итог](verification.json),
[независимое ревью](review.json).

Это работающий послойный **HTML-прототип**, не новая игровая сцена.
Конечности пока жёсткие плоские части; нет ходьбы, сгибания ног, смены ракурса,
динамической перестановки слоёв или симуляции ткани. Вращение растровых деталей
меняет пиксельный контур; силуэт, посадка брони, перекрытия и ощущение удара
требуют отзыва пользователя. Показ не доказывает совместимость со всеми
скинами, анимациями или предметами игры.

Runtime assets/сцены/core/preview/queue/RNG/save не менялись. Godot import,
игровые тесты/full/core, F5/Editor/DPI/performance не запускались.
