# Нарисованный низкий огонь: повторная проба V3

U уточнил, что должны едва колыхаться **только уже нарисованные** оранжевые контуры на четырёх исходных тайлах `fire-low-22/23/24/29`. Предыдущие 12 проб PixMiniMax создавали новые высокие языки и не соответствовали цели. Эта отдельная серия содержит ровно три варианта на каждый исходник (12 ключей), без кадров из неудачных анимаций и без ручной правки графики.

`model/<source>/source-original.png` — побайтная копия исходного RGBA 1254². `input-256.png` — весь кадр, уменьшенный LANCZOS без кропа и ретуши. [Манифест](requests.json) хранит SHA исходников, входов и точных запросов. Снимок live OpenAPI сохранён вне Git в `C:/Users/Aston/.codex/generated_images/fire-painted-sway-20261105/openapi-prepared.json`; перед каждым POST bridge повторно получает официальную схему.

Endpoint `/v2/animate-with-text-v3`: одинаковые first/last PNG, `no_background=true`, `drift_threshold=0`, `enhance_prompt=false`. Восемь запросов успели получить `frame_count=8`. После просмотра первых неудачных циклов только четыре ещё не отправленных запроса получили короткий позитивный action; `fire24-03` и `fire29-03` запрошены на 4 кадра, `fire29-01/02` — на 8. [История точечной ревизии](prompt-revision-01-positive.json) содержит исходные и новые SHA; точные первоначальные draft-запросы сохранены вне Git отдельно от принятых заданий. Фактическое число возвращённых кадров определяется по completed-ответу, а не предполагается заранее. Четыре caption-поля записаны в метаданных манифеста, но не отправляются V3: его актуальная схема имеет `additionalProperties=false` и не содержит caption-полей. Баланс перед серией — 4787 генераций. Внешний bridge использует DPAPI-ключ только в памяти как Bearer к официальному `https://api.pixellab.ai`; ключ не попадает в Git, запросы или логи. Для каждого ключа есть барьер `submit-started.json`: неопределённый POST повторять нельзя.

Экспорт сохраняет исходные PNG-байты admitted completed-ответов; PNG-листы, GIF и [автономная галерея](gallery.html) служат для просмотра. Галерея показывает неподвижный исходный вход 256² рядом с анимацией того же размера. [Наблюдения](clip-observations.json) описывают полный цикл каждого клипа; техническая проверка происхождения не является художественной приёмкой. В игру эти пробы не подключены.

## Фактический результат

Все 12 admitted jobs завершены: первые десять запросов на 8 кадров вернули по 9 кадров, два коротких запроса на 4 кадра вернули по 5. [Техническая проверка](validation.json) подтверждает 100/100 исходных RGBA PNG-байтов API, совпадение клеток листа и GIF, неизменность входов и полный RGBA-совпадающий первый кадр для 12/12 клипов. Ни один последний кадр не совпал с входом по RGBA. Нарушений внешнего прозрачного отступа нет. [Расход](usage.json) — 88 генераций, баланс подписки 4787 → 4699.

Полный цикл каждого клипа просмотрен по [листам всех кадров](all-frames/) и в [галерее](gallery.html). **0/12 соответствуют требованию двигать только уже нарисованные кончики пламени при неподвижном камне.** Первые восемь длинных промптов заметно перерисовывают огонь: плоские заливки, крупные формы, высокие пики, частицы или вспышки. После точечной ревизии `fire24-03` и `fire29-01/02` стали ближе к низкой нарисованной поверхности и не дают прежних высоких струй, однако весь тайл вместе с каменными боковинами меняет размер/положение. Короткий `fire29-03` создаёт новую дугу и частицы. Конкретные события и различия записаны по каждому клипу в [наблюдениях](clip-observations.json). [Метрики alpha](all-frame-alpha.json) и [дрейфа](drift.json) дополняют визуальный просмотр; цветовая разница сама по себе не доказывает сдвиг геометрии.

[Проверка автономной галереи](browser-validation.json) прошла для 12 карточек в четырёх группах: одинаковый размер исходника и анимации на каждой карточке, пауза, кадр, скорость, масштаб, фон и ширина 390 px без горизонтального переполнения. Художественная приёмка и интеграция остаются открытыми; новых запросов после этих 12 нет.
