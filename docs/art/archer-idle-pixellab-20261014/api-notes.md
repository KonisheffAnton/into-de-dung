# Выбор одного запроса PixelLab — 2026-10-14

Проверены официальные [llms.txt](https://api.pixellab.ai/v2/llms.txt) и
[OpenAPI](https://api.pixellab.ai/v2/openapi.json); хеш сохранённой схемы —
`request-manifest.json`. Scout проверил схему независимо, API не вызывал.

`transfer-outfit-v2` принимает отдельный рисунок и последовательность движения,
но для 13 кадров максимальная сторона результата —64. При81–256 доступны только
3 кадра. Это не подходит для восстановления полного цикла с детализацией128.
`edit-animation-v2` имеет сходное ограничение и не принимает отдельный рисунок.
Interpolation принимает лишь два ключевых кадра.

Выбран один `animate-pixminimax`: чистый PNG128 как первый и последний кадр,
12 запрошенных кадров, фиксированный seed20261014. У него нет входа для MP4
или массива кадров движения. Ролик и пользовательский пресет изучены локально;
провайдеру отправлены PNG и текстовое описание едва заметного дыхания.
Это новая генерация похожего движения, а не покадровая реставрация ролика.

Исходный1254×1254 PNG уменьшен целиком до128×128 через nearest-neighbor.
Ни кадрирования/перецентрирования, ни правки позы/RGB/alpha не было.
`no_background=true`, `drift_threshold=0`, `enhance_prompt=false`, направление east,
high top-down — как в пользовательском пресете; description дополнен требованиями
к чистым пятнам, постоянной палитре и отсутствию смаза/зерна.

Улучшение здесь означает получение исходных PNG без видеосжатия и с alpha.
Стилевую точность, сохранность формы оружия и качество движения оценивают по
результату отдельно. Увеличение×4 для просмотра не создаёт новой детализации.
Единственный POST и окончательный usage записаны в `pixellab/response.json` и
`pixellab/result.json`. Автоматических повторов или серий нет.

Ключ не входит в пакет. Его расшифровывают в памяти из локального DPAPI-хранилища
и передают только официальному api.pixellab.ai. Сохранённые запрос/ответы не
содержат заголовка Authorization.
