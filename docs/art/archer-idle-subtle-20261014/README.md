## Что изменено в запросе

Одна новая генерация `animate-with-text-v3` внутри PixelLab. В официальной
[OpenAPI](https://api.pixellab.ai/v2/openapi.json), повторно полученной2026-10-14,
для простого idle/breathing рекомендованы4кадра. Прежний animate-pixminimax
давал избыточную амплитуду. Это основание попробовать другой endpoint, а не
гарантия фиксации частей персонажа. Схема не содержит пространственной маски
или блокировки областей; `drift_threshold` исправляет цветовой дрейф, не позу.

Вход — **неизменённый целый frame-02 предыдущего PixelLab-результата**,128²,
binary-alpha и исходная стойка. Его выбрал ведущий, чтобы не повторять переход
от промежуточной alpha старого статичного рисунка к binary-alpha. Это не
ручное удаление фона/ретушь и не пользовательская арт-приёмка этого кадра.
First=last, seed20261015,4requested, no_background=true, drift_threshold=0,
enhance_prompt=false. В action разрешён максимум1px в центре груди/шарфа;
запрещены боковой/общий перенос, выпрямление коленей, смена опоры, движение
лука/тетивы/рук/головы/волос. Видео напрямую API не передавалось.

Job `616ecb27-f2e6-4785-b8bc-c4cc2005ac4d` завершён, **1 генерация подписки**.
API вернул5PNG128² при4запрошенных. Сохранены все5 в исходном порядке,
каждый по520ms: суммарно2.6s, как пользовательский ролик. Это пять поз с
удержанием, без синтетической интерполяции. Параметров стоимости в USD ответ
не содержит. Повторных POST в этом поручении не было.

## Что получилось

- Кадры02–03 по-прежнему меняют верхнюю часть фигуры и положение лука/рук.
  Границы alpha≥128 изменяются с `(25,15,119,121)` до `(22,10,117,121)`:
  до3px по горизонтальной границе и5px вверх. Это метрика общего силуэта,
  включая меняющую форму причёску, а не перенос каждой части на такую величину.
- В двух выбранных прямоугольниках стоп контур alpha≥128 совпадает с входом
  во всех5кадрах. ВидимыеRGBA различаются на1–4пикселя; полной пиксельной
  неподвижности не заявляем. Более широкая область ног меняет форму.
- В области «лук и правая кисть» у кадра03 меняются247пикселей binary-alpha;
  видимое движение лука противоречит прямому требованию. Прямоугольник
  захватывает окружающие пиксели, поэтому счётчик не равен смещению лука.
- Первый и последний кадры различаются на96RGBA-пикселей. Все кадры имеют
  binary-alpha; прежнего перехода partial→binary больше нет. Это не доказывает
  художественно незаметный шов. Даже первый кадр отличается от входа:
  125видимыхRGBA-пикселей и2пикселя alpha≥128.
- Полные RGBA-счётчики включают RGB невидимых пикселей; для видимых отличий
  использовать `visible_rgba_changed`, для контура — `alpha128_changed`.
