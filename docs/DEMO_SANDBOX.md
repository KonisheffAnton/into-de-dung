# Интерактивный полигон

Сцена `scenes/demo/battle_demo.tscn` — стартовая сцена проекта. Это ручная
песочница на общем ядре P01–P08: 8×8, четыре персонажа, полууровни,
движение, атаки, толчки, столкновения, падение, смерть и предметная реакция.

## Запуск

Из корня репозитория:

```powershell
python tools/demo/isolate.py
```

Скрипт копирует текущее рабочее дерево, включая необходимые незакоммиченные
зависимости, в новый `test_reports/demo-UUID/project`, импортирует его и открывает
окно игры. Исторические отчёты не попадают в class cache. Старые отчёты и корневой
кэш не переписываются. APPDATA задаётся только дочерним процессам.
Python 3 и Godot 4.7 нужны для запуска. Godot выбирается из `--godot`, `GODOT_BIN`,
PATH либо известного локального пути Godot 4.7.2 на этой машине.

В редакторе сцена запускается F6, а проект — F5. Для этого рабочего дерева
предпочтителен скрипт выше: старые `.gd` внутри `test_reports` могут конфликтовать
при корневом импорте. Прежняя `scenes/test/test_grid_scene.tscn` сохранена.

## Управление

- «Выбор / движение» или M: клик по персонажу выбирает его, по свободной клетке
  исполняет найденный путь. В списке справа также можно выбрать персонажа.
- «Атака» или A: клик по персонажу исполняет удар выбранным персонажем.
- ПКМ на поле или Esc возвращает режим движения.
- «Сбросить бой» или R создаёт новое состояние, восстанавливая карту, HP,
  предметы и действия. Выбор персонажа ничего не пополняет.

Высоты указаны на клетках в уровнях, шаг 0.5. Бирюзовые точки показывают
доступные по бюджету клетки, линия — маршрут. Это не предпросмотр последствий:
движение вниз может причинить урон. HP всех персонажей видны в списке,
равновесие и остатки действий выбранного — под ним. Полоски на поле показывают
HP и накопленную потерю равновесия. Крестик — погибший, клетка уже свободна.

## Два готовых примера

1. Выбранной Астрой щёлкнуть D3: три шага по ступеням 0.5 → 1.0 → 1.5.
   Включить атаку и щёлкнуть Стража на E3 (высота 1.0). Удар сверху наносит
   9 HP, сбивает равновесие и толкает на F3 (−0.5). Падение наносит 18 HP.
   Реальный амулет Стража затем лечит по 2 HP за оба события урона: 80 → 57 HP.
   У Астры остаётся 5 движения, 0 основных действий, 1 бонусное.
2. Выбрать Бора и атаковать Щита на D6. Стена E6 блокирует толчок;
   Щит получает 8 HP от удара и 8 HP от столкновения, оставаясь на D6.

Другие расстановки можно получить ручным движением. За обрывом нет проходимой
клетки: толчок туда приводит к смерти; предмет не лечит погибшего.

## Контракт демо

`BattleDemoSession : RefCounted` владеет одной BattleBoard, ItemSimulationState,
ActionContext и постоянной ActionQueue. `BattleDemo : Control` управляет вводом,
списком и журналом; `BattleDemoBoard : Control` рисует только текущее состояние.
Позиции меняет BattleBoard, игровые последствия исполняют MoveCommand и
AttackCommand через очередь. UI читает receipt после полного drain и не меняет
ядро из callback. У журнала максимум 80 строк, у reset/exit — явное закрытие
owner/inventory/equipment и отключение подписок доски.

Профили `spatial_move_v1` / `spatial_melee_balance_v1` сохранены. Разрешённые пары
атаки перечислены для всех разных персонажей демо. Это техническая песочница,
а не новое правило фракций или командных ходов. Одна атака тратит 1 main по
текущему ядру; возврат к персонажу сохраняет оставшиеся ресурсы. Политика будущего
Flow не реализована. Бонус отображается, но в демо нет действия для его расхода.
RNG инжектирован fail-closed портом: выбранные команды не требуют бросков.
Предмет поддержан настоящим HealOnDamageEffect, без имитации лечения в UI.

Изменений core, инициативы, BT/Utility AI, общего LOS, полного preview,
сохранений и командного Flow в этом этапе нет. Snapshot ядра не объявляется
сохранением игры. Проверенное состояние по-прежнему включает старые dirty
P01/P02/P06/P08; одного чистого HEAD недостаточно.

## Проверка

```powershell
python tools/demo/isolate.py --check
python tools/demo/isolate.py --render-check
python tools/demo/isolate.py --check --full
```

Каждый прогон создаёт уникальный каталог с manifest SHA-256 и логами.
`tests/test_battle_demo.gd` проверяет общую сцену, настоящий viewport mouse/key
dispatch, расход/отказы, смену выбора без refill, высоты, порядок событий,
урон/лечение, wall/collateral, смерть/occupancy, журнал и многократный reset/exit.
Графический режим также сохраняет три PNG для визуальной проверки.

Приёмка 2026-09-14: core **9440/0** на неизменённом ядре; графическое демо
**50/0**, import/startup PASS, без runtime errors или exit leaks демо.
У полного старого runner остаётся известная диагностика 47 ObjectDB / 18 resources;
она не появилась в демо. Первоначальные неуспешные UI-прогоны сохранены как история.
Финальные артефакты и независимое ревью перечисляются в CODEX_HANDOFF.
