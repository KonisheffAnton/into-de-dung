# Пробивание физической базы — M4

U, 2026-09-23: «Принять и реализовать пробивание 50%» после M3.
Base main `7dadc2614164a80d103422c5e75b78056a438ff8`.
Это свойство оружия, работающее в обычной атаке за 1 main, без отдельного
действия, длительности, заряда и cooldown. Основной бой остаётся командным.

## Правила

Сначала рассчитывается физическая база Сила + Оружие с прежними высотой,
ударом в спину, стойкой цели и критом C1. Затем 50% базы получают политику
`hp_only_natural`, остальные 50% — `standard`. Первая доля обходит броню,
но учитывает естественную защиту; вторая идёт через обычное покрытие,
сопротивления и overflow D0/D2. Это не снижение сопротивлений и не разрушение
половины запаса брони. Дополнительные компоненты, в том числе physical,
сохраняют свои прежние политики и множители. Пробивание не передаётся
воздействию, collision, падению, шипам или кровотечению.

Доли остаются точными дробями до существующей группировки type/policy и floor
в D0. Без дополнительных компонентов физическая база 11 при 50% даёт входы
5 + 5 до защит, а не 5 + 6. Промежуточного перераспределения остатка нет.
При базе 10, полной броне и нулевой естественной защите: 5 урона HP,
5 расхода брони; огненная руна 10 отдельно расходует ещё 10 брони.
Физический HP-урон этой атаки допускает кровотечение по существующему D3.

## Источник, допуск и исполнение

Append-only `StatTypes.StatType.PHYSICAL_PIERCING_PERCENT = 11` хранит процентные
пункты. Единственный источник у демонстрационного оружия — штатный
`StatModifierEffect(ADD_FLAT, 50)`. Общая формула Stat/StatsBag не меняется.
`StatTypes.is_valid_id(Variant)` объединяет допустимость ID в строгих snapshot
валидаторах и проверке предметов; float, bool, строки и неизвестные ID отвергаются.

`AttackCommand` читает итоговое значение из копии StatsBag. Отсутствующий stat
означает 0 и не добавляется в старый снимок. Итог должен быть конечным целым
0–100; некорректное значение отвергается до оплаты, без clamp. Ненулевое значение
поддерживает только `armor_spatial_v1`; legacy-профили явно отказывают.
Submit и execute повторно проверяют актуальное состояние.

Последний optional аргумент `ArmorAttack.components(..., physical_piercing_percent=0)`
делит базу. Ноль сохраняет прежний массив компонентов, 100 оставляет только
HP-политику базы; диапазон API шире единственного демонстрационного значения 50.
Предел 128 компонентов остаётся: при двух долях базы допустимо до 126 extras.
Переполнение точной арифметики и превышение лимита отвергаются.

`BalancePushRules` включает stat атакующего в SpatialRules.Guard для броневого
удара. Отсутствие фиксируется отдельно от нулевого значения: callback не может
добавить или изменить stat между оплатой и попаданием незамеченным. Guard
сохраняется в дочерних последствиях; FAULTED сохраняет выполненный prefix.
План расхода брони, RNG, события и единственный HP-путь остаются у D2.
Новых полей attacked/receipt и второго расчёта в UI нет.

## Предмет, сохранение и игровой вход

`D4Catalog` добавляет `piercing_sword` — «Пробивающий клинок»: +4 урона оружия,
50 пунктов пробивания, слот оружия. Новый профиль D4 получает один экземпляр
на склад (#13); его нужно надеть на выбранного героя перед отправкой.
Пассивные склад/рюкзак бонуса не дают. Прежние sword/keen_sword не меняются.

Схема D4 v1 сохраняет kind и размещение; новые схемы не вводятся. Старый профиль
из 12 предметов загружается без выдачи клинка. Для демонстрации нужен новый
профиль; существующий пользовательский save автоматически не сбрасывается.
ItemSimulation v1–v6 сохраняет новый ID в прежнем stat_modifier codec;
старые определения/снимки не получают пустых полей, catalogue equality сохраняется.
Restore восстанавливает эффект один раз, прогноз исполняет реальную команду
на копии предметов, ресурсов, RNG и счётчиков. D5/M1 сохраняют свои форматы.

F5 → «Забег»: на складе нового профиля надеть клинок и отправиться в бой.
Подготовка показывает пробивание 50%, осмотр — эффективный процент и его смысл.
Прогноз различает строки обычного физического урона и «в обход брони» по
политике настоящего hit; естественная защита и полный каскад учтены ядром.
