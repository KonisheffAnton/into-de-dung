### Масочные фрагменты опасностей — 2026-11-05

Свежая официальная схема `AnimateWithTextRequest` ограничивает `image_size`
ровно64×64; это не ограничение V3. `mask_images` — белое разрешает дорисовку,
чёрное сохраняет вход; `inpainting_images` задают четыре существующих кадра.
В [повторе огня и кальтропов](art/hazard-masked-retry-20261105/README.md)
из рабочего исходника256² вырезан фрагмент64² без уменьшения. Во всех четырёх
входных кадрах одинаковый фрагмент; первая и последняя маски полностью чёрные,
средние разрешают узкие края нарисованных мазков либо отдельные точки металла.
Это маски для генерации PixelLab, не вручную нарисованные промежуточные позы.

Сырые ответы64² сохранены отдельно. Показ256² — точная вставка всего сырого
фрагмента по целочисленным координатам в неподвижный исходник; без ретуши,
масочного исправления ответа или масштабирования фрагмента. Называть эту сборку
полноразмерным сырым ответом API нельзя. В15 пробах первый и последний RGBA
кадры совпали; вне масок нет изменений во времени. Строгое равенство исходнику
вне маски не выполнено: PixelLab одинаково во всех кадрах нормализовал несколько
почти прозрачных пикселей с alpha0/1. Они не исправлялись локально.
Паузы кальтропов и повтор готовой позы задаются явно в порядке/длительности
показа; новые пиксели этим не создаются. Проверять шов, всю временную цепочку
и художественное качество отдельно; успех этих проб не гарантирует будущие.

В [поиске движения2026-11-06](art/hazard-motion-20261106/README.md) пользователю
помогали выделением языков на статичном входе. Движущиеся позы по-прежнему
только PixelLab; отбор/тайминг и явная сборка неизменённых пикселей готовых кадров
не означают локальную генерацию движения. Исходники, raw и сборки разделять.
Последовательные legacy-окна с `n_frames=16` не обеспечили плавных стыков.
V3 фактически ограничил256² восемью запрошенными кадрами; interpolation-v2
вернул два промежуточных PNG. Число/размер результата и поведение масок проверять
по фактическому ответу, качество — по всему циклу, а не по успеху запроса.

В [продолжении с отдельными мазками](art/fire-single-tongue-20261106/README.md)
PixMiniMax получает прозрачный нативный crop128/256 с исходными RGB, выделенный
статической alpha-маской. Это входное выделение объекта, не региональная маска API.
Неизменённые raw RGBA накладываются при постоянных координатах на исходный тайл;
камень и рассеянное свечение остаются статическими. Отбор спокойных поз и обратный
показ тех же PNG не создают новых поз; плавность и все переходы проверяются отдельно.
Исходный кадр raw0 может отличаться палитрой от generated frames: одинаковые
first/last в запросе не гарантируют чистый стык ответа. Ответы фоновых заданий
нужно сохранять сразу при опросе: текущая схема Jobs предусматривает их очистку
после завершения. HTTP404 не доказывает успешную генерацию или получение кадров.
В контрольных крупных мазках этой серии запрос16 вместо32 кадров лучше сохранил
палитру при прежнем входе/seed; это наблюдение, не гарантия качества провайдера.
Ответ `GPU worker dropped this` может смениться completed у того же job:
сохранять ID и продолжать GET, не считать его разрешением на повторный POST.
