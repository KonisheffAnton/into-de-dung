# Текущий формат постоянного профиля

U «Приступай», 2026-10-11: граница совместимости по DESIGN_DIRECTION §7.2.
Этот документ владеет форматом и отказом загрузки; игровые правила остаются
в H1/U14, MAGE_DECK_V1, POST_BATTLE_V1 и SHIELDBEARER_V1.

## Файл и отказ загрузки

HeroHubStore читает и пишет только envelope `hero-hub-v6` с payload profile6.
Путь остаётся `user://hero-hub-v1.save`; имя файла не обозначает его версию.
SHA-256, лимит 1 MiB, строгие типы/поля и атомарная запись через `.tmp`/`.bak`
сохранены. Envelope и payload должны согласовываться.

Profile1–5 и прежние вложенные run1–3/plan1–3/report1–2 больше не читаются.
Миграции, заполнения пропущенных полей и автоматического включения колоды
при чтении нет. Неизвестные и повреждённые формы также отклоняются.
Ошибка возвращает `run=null` и объяснение, не пишет/удаляет исходный файл,
`.bak` или `.tmp` и не создаёт вместо него новый профиль. Экран хаба показывает
ошибку; игровой переход и повторная запись недоступны без загруженного состояния.
Новый профиль создаётся только при отсутствии основного файла и резервной копии.
`deck_mode` выбирает каталог/колоду только для такого нового профиля.

## Одна форма для каждого владельца

| Владелец | Текущая форма |
|---|---|
| HeroHubState | profile6: все поля прежнего текущего состояния обязательны, включая `hero_catalog_version`, `mage_deck`, `h1_ruleset`, достижения, отчёт и поход |
| ExpeditionRunState | run4: обязательны `ruleset_id` и `repair_spent`; набор артефактов либо карт определяется режимом, смешивание запрещено |
| ExpeditionGenerator | plan4: обязательны `ruleset_id` и `opening:bool`; `opening=true` допустим только для колоды |
| PostBattleRules / MageDeckReport | report3: обязательный `ruleset_id`; артефактная и карточная части взаимоисключающие; пустой отчёт означает отсутствие отчёта |

Каталоги героев 1/2 остаются явными данными. Каталог 1 не превращает `warrior`
в Щитоносца; новый обычный F5 выбирает каталог 2. Пустая колода требует пустого
`h1_ruleset`; непустая — корректную базу и `h1-legacy-v1` только в фазе `battle`.
Режимы U14 `u14-legacy-v1` и `u14-deck-v1` сохраняют игровые правила. Режим
плана должен совпадать с походом; версии и полные значения каталогов проверяются.
Оба существующих варианта графа представлены текущей plan4: прежний двухвходовый
и текущий вход с `ExpeditionOpening`. Смена номера старого файла не является миграцией.

Контрольная точка сохраняет начало боя, не середину хода. Поля checkpoint,
профильные RNG, seed боя, награды и сохранённые решения не пересчитываются при
roundtrip текущей формы. Переходы сохраняют границу копия → проверка → запись →
публикация; отказ записи оставляет прежний профиль и тот же candidate для retry.

## Отдельная граница боевых снимков

Профиль не содержит ItemSimulationSnapshot. Боевой граф для preview/worker
пишется и проверяется отдельно по [BATTLE_SNAPSHOT_CURRENT](BATTLE_SNAPSHOT_CURRENT.md).
Единая форма хранения не удаляет действующие варианты оплаты/статусов/маны.
D4RunStore и D4RunState не входят в этот пакет; их отдельный файл не читается,
не мигрируется и не удаляется. Текущие одноформатные codecs без старых веток
(достижения, карты, ActionResources, stats/RNG и прочие) не получают новых версий.

Проверки загрузки/файлов, фаз похода, сквозного исполнения и сравнения с base —
[TESTING](TESTING.md); свидетельства этапа — `test_reports/schema-cleanup-20261011/`.
