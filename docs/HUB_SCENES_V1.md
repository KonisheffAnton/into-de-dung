# Редактируемые сцены меню и хаба

2026-10-04. Поручение «Приступай»: перенос представления меню → база/колода →
награда/костёр → итог в сцены Godot. Боевой экран — отдельный [пакет HUD](BATTLE_HUD_SCENES_V1.md).
Игровые правила принадлежат H1/U14/MAGE_DECK_V1/POST_BATTLE_V1; они не меняются.

## Что редактировать в Godot

| Файл в scenes/demo/ | Назначение |
|---|---|
| main_menu.tscn | Фон, заголовок, описание, кнопка запуска и подсказка временного профиля |
| hero_hub.tscn | Общий фон/отступы, постоянная шапка, прокрутка, экземпляры страниц |
| hub/base_page.tscn | Разделы отряда, достижений, героев, найма, склада и выхода |
| hub/deck_base_panel.tscn, deck_card_entry.tscn | Редактор базы колоды и строка типа карты |
| hub/expedition_page.tscn | Поход, услуги, безопасная точка, подготовка и снаряжение |
| hub/deck_camp_panel.tscn, card_choice.tscn | Редактор состава у костра, выбор копии/награды |
| hub/deck_rewards_panel.tscn | Выбор карты, пояснение финала и отказ |
| hub/post_battle_page.tscn, report_hero.tscn, deck_report_panel.tscn | Итог, запись героя, переработка находок |
| hub/storage_error_page.tscn | Ошибка загрузки/записи и повтор записи |
| hub/hero_entry.tscn, candidate_entry.tscn, achievement_entry.tscn | Повторяющиеся записи базы |
| hub/allocation_panel.tscn, attribute_entry.tscn | Предварительное распределение очков |
| hub/equipment_entry.tscn, expedition_item.tscn | Строки снаряжения |
| hub/expedition_map.tscn, map_room.tscn | Область карты и шаблон кнопки комнаты |

Открыть нужный .tscn во вкладке 2D/Inspector; размеры, контейнеры, отступы,
шрифты, текстуры и постоянные подписи задаются в сценах. Для правки вложенной
сцены открыть её исходный .tscn; локальные переопределения экземпляра также
сохраняются при обновлении страницы. Имена узлов и типы, используемые скриптами,
являются привязками: их переименование требует обновления соответствующего кода.
Проверка игрового маршрута — F5; F6 отдельных шаблонов из hub/ не создаёт профиль.

Списки заполняются экземплярами сцен при запуске: число героев/карт/предметов
зависит от сохранения. В редакторе контейнеры списков пусты; внешний вид записи
виден в её сцене-шаблоне. Значения HP/маны/золота, доступность действий и
подписи с числами обновляются GDScript. Ветвление карты и линии связей остаются
процедурными по сохранённому плану. Это не генерация исходных сцен при запуске.

## Владение и обновление

HeroHubScreen загружает постоянную оболочку и страницы из hero_hub.tscn.
Неактивные страницы временно отсоединены от дерева; возвращается тот же
экземпляр с сохранёнными настройками. При закрытии экрана отсоединённые
страницы освобождаются. Повторный render удаляет только отмеченные HubUI
динамические записи. HubUI.bind заменяет свой предыдущий обработчик кнопки,
сохраняя другие подключения; обновления не накапливают повторные действия.

Presenter-скрипты заполняют именованные слоты и вызывают прежние команды
хаба/похода. UI не владеет RNG, транзакцией сохранения или боевым runtime.
Ошибка записи показывает отдельную страницу; публикация candidate и retry
по-прежнему принадлежат HeroHubScreen/HeroHubStore. Legacy H1/U14 выбирается
из сохранения. Бой продолжает использовать существующий HeroHubBattleView.

Python нужен только инструментам разработки/проверки. Обычный запуск Godot
читает сохранённые .tscn/.gd; генерация сцен внешним скриптом не требуется.
Меню владеет только временем жизни отдельного тестового файла; создание и
запись самого профиля остаются у HeroHubStore. Режим сброса при выходе и
переключение на продолжение — [REPOSITORY_STATE](REPOSITORY_STATE.md#обычный-запуск).

## Проверка и границы

test_hub_scene_authoring проверяет authored-структуру до _ready, сохранность
настроек и identity страниц после refresh/error-return, отсутствие дублей
обработчиков и неизменность профиля при render/edit/cancel.
Он также проверяет вход из меню, изоляцию/очистку временных файлов и сохранность
постоянного профиля; render сохраняет меню и свежий хаб.
Существующие hero_hub_ui/expedition_ui/mage_deck_ui проверяют реальные кнопки,
legacy, сохранение/retry/reload и отчёты. Полные маршруты — TESTING.

Техническая проверка этого переноса не заменяет пользовательскую приёмку
разметки и не утверждает финальный арт/баланс. Школы, кузня, экипировка13/стаки
и другие механизмы сюда не входят; сцены боя описаны отдельно по ссылке выше.
