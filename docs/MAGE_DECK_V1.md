# Колода внешнего мага — технический контракт V1

2026-10-04; base реализации main `e2a254749add81dadfce7a3676c1c6b3605cdc64`.
**Связный пакет реализован по поручению «Вперед».** Форматы и владельцы ниже
относятся к новому режиму; результаты проверок и остаток приёмки — HANDOFF.
Владелец игровых U/D4–D14 и открытых Q —
[DESIGN_DIRECTION §6.3](DESIGN_DIRECTION.md#equipment-mage-deck-20261004).
Legacy и общие эффекты описывают [K18](MAGE_COOLDOWNS_K18.md), [R14](MAGE_SUPPORT_R14.md),
[H1](HERO_HUB_H1.md), [U14](EXPEDITION_U14.md), [итоги](POST_BATTLE_V1.md).

## 1. Граница и существующие точки интеграции

Один пакет: сборка базы → поход → расстановка/рука/бой → награда → костёр → итог.
Включены все 12 типов и огненное усиление; не включены экипировка13, стаки,
школы, кузня/рецепты/слоты постоянных артефактов, новые реакции и D4-save.
Реализация, технический PASS, пользовательский плейтест и финальный баланс —
разные статусы. Пользователю предъявляется один целый путь для общей ручной
приёмки, без остановок на микроплейтест каждого эффекта.

| Основание до пакета | Изменение только для нового режима |
|---|---|
| `HeroHubState` schema3, `HeroHubStore` envelope `hero-hub-v3` | Версионированный профиль и явный выбор правил; путь файла прежний |
| `ExpeditionRunState` schema2, план schema1 / content version1 | Отдельные новые run/plan codecs; старый план проверять старым каталогом |
| `HeroHubScreen._commit/_retry_save` публикуют candidate после записи | Сохранить этот барьер для базы, колоды, награды, финала и миграции |
| `HeroHubBattleFactory.create/outcome`, `ExpeditionTransitions.apply` | Dispatch по сохранённому ruleset, а не export UI/наличию seed |
| `BattleAbilityState` schema1 требует максимум 6, содержит часы и откаты | Schema2 нового режима; единственный владелец фактической маны и часов |
| `MageCastCommand`/`AbilityDefinition` проверяют legacy ID, цену и события | Отдельная карточная команда; адаптер общих эффектов, без вызова старой оплаты |
| `ItemSimulationSnapshot` writer до v9; `SpatialRules.Guard` | Новые capability/полный снимок/фазовые guards, без изменения legacy bytes |
| `BattleCoreReactionsSession._refill` задаёт порядок командных границ | Карточные операции в явных границах, тот же порядок старых действий |

Пути: `scripts/core/{hub,expedition,abilities,actions}/`, `scripts/demo/`.
Максимум маны 6 и ограничение старых артефактов до пяти записей остаются
в legacy; новые владельцы не переиспользуют эти ограничения для колоды.

## 2. Каталог, идентичность и определения

`MageCardDefinition` — Resource; `MageCardCatalog` — проверенный immutable
набор `mage-neutral-v1`, version1. Definition содержит `id`, `version=1`,
`name`, `description`, `image_key`, `mana_cost`, `effect`, `parameters`,
`target_policy`, `cooldown_turns=0`. Тексты/изображения не входят в механический
digest каталога; параметры/цели/цены входят. Save не исполняет произвольный скрипт.
Новые ID стабильны; название/порядок UI не служат идентичностью.

| Card ID | Source ID (`kind=mage`) | Обработчик-основа / цель |
|---|---:|---|
| `card.fire` | 13 | `mage.fire`; живой вступивший враг |
| `card.heal` | 14 | `mage.test_heal`; живой раненый вступивший союзник |
| `card.shield` | 15 | `mage.shield`; живой вступивший союзник |
| `card.summon` | 16 | `MageSummonEffect`; свободная допустимая клетка R14 |
| `card.raise` | 17 | То же, плюс humanoid-тело с минимальным ID |
| `card.burning` | 18 | `MageStatusEffect/burning` |
| `card.wet` | 19 | `MageStatusEffect/wet` |
| `card.freeze` | 20 | `MageStatusEffect/freeze` |
| `card.stun` | 21 | `MageStatusEffect/stun` |
| `card.roots` | 22 | `MageStatusEffect/entangle` |
| `card.bleeding` | 23 | `MageStatusEffect/bleeding` |
| `card.fire_imbue` | 24 | Новый временный эффект; живой вступивший союзник |

Числовые эффекты/цены — единственная таблица U-D10 у владельца дизайна.
Для шести status-карт цель как в текущем `MageCastCommand`: любой живой
вступивший боец одной из двух команд, включая своего; прежние иммунитеты,
HP-gate, реакции состояний и причины отказа сохраняются. Pending запрещён.
R14-допуск клетки, напротив, учитывает и pending-союзников. Никакой новой
дальности/линии от выбранного героя. Старые source ID 1–12 не перенумеровываются.
Source ID обозначает тип, `card_instance_id` в карточном событии — копию.
Адаптер эффектов принимает проверенное определение и source; не выдаёт
новую карту за `mage.test_*` и не применяет второй раз ману/откат K18.

Копия похода: `{id:int, type_id:string, origin:"base"|"found"}`.
Ключ `(run_id,id)`, ID монотонный, не переиспользуется; `next_card_id` выше всех
выданных ID. В новом походе базовые копии получают 1..10 в порядке сортировки
type_id, затем номера копии; находки — очередной ID только после выбора.
Отказ от награды ID не выделяет. В бою те же ID, но независимые value-копии.
Стаки/усиление дубля отсутствуют. Порядок руки и draw важен; остальные множества
сериализуются по ID. Все ID/counters положительные в пределах int64 до
`ActionContext.MAX_ID`; переполнение — отказ до мутации, не обрезание массива.
Игрового максимума походной колоды и лимита копий нет; прежние лимиты artifacts
не переносить. Ограничения файла/памяти — диагностируемый отказ, не правило игры.

## 3. Владельцы и точные расширения codec

Каждый вложенный объект проверяется по точному набору полей; неизвестные
версии/режимы/типы/смешанные форматы отвергаются. Только чтение старого формата
может заполнить определённые ниже migration defaults. Во всех новых codecs
числовые поля принимают int, не bool/float; массивы и поля — value-only.

| Формат | Новая запись и ограничения |
|---|---|
| Профиль | Payload `schema=4`, envelope `hero-hub-v4`, прежний `user://hero-hub-v1.save`, SHA-256 и atomic replace/.bak по H1. Все schema3 поля сохраняются; добавляются `mage_deck` и `h1_ruleset` |
| `mage_deck` | `{schema:1, catalog_id:"mage-neutral-v1", catalog_version:1, base_types:Array[String], crafted_types:Array[String], forge_discovered_types:Array[String]}` |
| `h1_ruleset` | `"h1-legacy-v1"` только для верхней `phase=battle`, иначе пустая строка. В checkpoint H1 поле не дописывать; режим находится у профиля |
| Поход legacy | Сохранённый run schema1/2 читается прежними правилами; после нормализации writer оставляет вложенную schema2. Она однозначно означает `u14-legacy-v1` |
| Поход колоды | Run `schema=3`: поля schema2 без `artifacts/next_artifact_id`; вместо них `ruleset_id="u14-deck-v1"`, `catalog_id/version`, `cards`, `active_ids`, `next_card_id`, `reward_decisions` |
| План колоды | Plan `schema=2`: прежние ключи плана плюс `ruleset_id="u14-deck-v1"`; node keys прежние. `content` — `{catalog_id:"u14-deck-content-v1", version:1, rooms, encounters, cards}` с полными механическими values, без старого artifact-каталога |
| Checkpoint колоды | `{schema:1, ruleset_id:"u14-deck-v1", run_id, node_id, battle_serial, legacy_inputs, cards, active_ids, catalog_id, catalog_version, draw_seed}`. `legacy_inputs={heroes:Array, items:Array, seed:int}` — прежние value-входы героев/надетых обычных вещей/seed, поле artifacts отсутствует |
| Отчёт колоды | `battle_report.schema=2`: прежние поля отчёта schema1, кроме `artifact_selected`; добавить `ruleset_id`, `reward_state`, `offered_types`, `selected_type`, `selected_card_id`, `recycled_count`, `new_forge_types`, `return_reason`, `returned_cards`. Старые отчёты сохраняют schema1 |
| Ability runtime | `BattleAbilityState.schema_version=2`: поля schema1 плюс `ruleset_id="u14-deck-v1"`, `first_team:int`; legacy mage definitions/ledger отсутствуют, остаются descriptors прежних действий/предметов. Мана 0..maximum, maximum 2..9; часы поддерживают любой порядок команд |
| Deck runtime | `BattleDeckState`: `{schema:1, catalog_id, catalog_version, cards, draw_ids, hand_ids, spent_ids, draw_rng, mulligan_done, replaced_serial}`; только активные копии текущего боя |
| Эффект атаки | `BattleCardEffectState`: `{schema:1, ordinary_attacks, fire_imbues}`; карта unit→ID обычной атаки, плюс отсортированные записи эффекта из §6 |
| Боевой envelope | [Текущий ItemSimulation schema11](BATTLE_SNAPSHOT_CURRENT.md), scope `battle_state_v11`. При наличии `deck` обязательны `abilities` schema2 и `card_effects`, `artifacts` запрещён; summons допускает R14 `source_kind` |

`base_types` содержит ровно 10 записей, повтор type_id ≤2; сериализация
лексикографическая. Постоянные множества типов сортируются, не содержат дублей.
Допуск базы = 12 нейтральных типов каталога ∪ crafted_types. Нейтральный допуск
не заполняет фиктивный крафт или находки: оба множества нового профиля пусты.
Для будущего ненейтрального типа находка даст только forge_discovered_types;
первый реальный крафт даст crafted_types. Этот пакет такой операции не содержит.
Стартовый состав — U-D13, применяется лишь при первом добавлении mage_deck;
загрузка уже записанной базы не заменяет её дефолтом.

Run `cards` хранит базовые и найденные копии, `active_ids` — подмножество без
дублей размером ≥10; остальные — пассивное походное хранение. Базовых копий
всегда ровно 10, они не удаляются/не продаются. `reward_decisions` — массив
`{node_id, choice_index}` для уже закрытых наград: -1 отказ, иначе 0..2.
Каждой выбранной записи соответствует одна found-копия; ID находок следуют
порядку маршрута. Поля report `reward_state` = pending/chosen/skipped/none;
при отсутствии выбора `selected_type=""`, `selected_card_id=0`.
Финальный report хранит значения уничтоженной находки, не ссылку в пустой run.
`ruleset_id` отчёта всегда `u14-deck-v1`; `return_reason` = none/early/completed/defeat.
`returned_cards` — отсортированные по id value-записи
`{id, type_id, origin, was_active:bool, disposition:"recycled"|"lost"|"expired"}`.
При none массив пуст; при возвращении содержит каждую копию до удаления run.
Found получает recycled при early/completed либо lost при defeat; base всегда
expired без эссенции. `recycled_count` равен числу recycled, сумма эссенции
ровно count×10; new_forge_types — только разность найденных и прежних открытий,
при defeat пустая. Это исторические значения отчёта, не активные предметы.

Battle `cards` разбиты на draw/hand/spent без пересечений и потерь, рука ≤6.
Мана принадлежит только abilities; deck не имеет своего дублирующего баланса.
`first_team` — PLAYER/ENEMY по условиям встречи; неизменен. В setup serials/ended
нулевые, team=first_team, мана2. После start serial первого=1; разность serials
первого и второго всегда0/1. В active/closing/ready у текущего serial-ended=1,
у другого0; в ended оба закрыты. Первое открытие хода PLAYER не увеличивает
максимум: рост начинается, когда прежний serial PLAYER уже ≥1.
`draw_rng` — отдельный CombatRng schema1, не live combat RNG; ID/число вызовов
и состояние входят в snapshot. `mulligan_done=false` допустим лишь в setup;
`replaced_serial=0` либо номер своего хода ≤ abilities.serials[player].
Профиль не хранит изменяемую руку; run, checkpoint, session и preview не делят
массивы/definitions/RNG. ItemSimulation с deck и без него использует единый
текущий envelope. Сочетание deck/abilities1 или card_effects без deck — отказ,
не best effort. Старые item envelopes больше не принимаются.

## 4. Совместимость, checkpoint и барьеры

`ExpeditionRulesRegistry` разрешает отдельно четыре вещи: codec/валидатор,
каталог/генератор, battle factory, transitions. Ключи `u14-legacy-v1` и
`u14-deck-v1`; H1 — отдельный `h1-legacy-v1`. Legacy U14 закреплён за текущим
content version1, прежними наградами/поясом/маной/финальными 10 эссенции.
Новый registry применяется уже при проверке Store, до `from_dict` текущего
каталога, затем при factory/outcome/route/service/reward/retry/report.
Неизвестный ключ/content version не подменяется последним известным.

Миграция envelope/payload 1/2/3→4: сначала проверить согласованную старую пару
и данные старым reader; на отдельной копии добавить базу/пустые множества,
явный H1-mode если нужен; старый U14 run нормализовать только его существующим
reader. Сохранить героев/вещи/валюты/достижения, оба профильных RNG, seed,
весь план/checkpoint и открытый schema1 report. Старые artifacts/отчёты
не создают карты или открытия. Новая оболочка не меняет ruleset вложенного run.
Записать schema4 до допуска действий. При неудаче — исходный файл и тот же
pending candidate для retry; не создавать новый профиль и не регенерировать план.

Профиль без активного боя/похода может собирать базу; следующий start в U14
создаёт только deck-run. Legacy H1 и U14 заканчиваются своим dispatch до hub,
включая открытый отчёт после результата. Диагностические старые fixtures/сцены
сохраняют явный legacy вход. Export `expedition_mode` определяет новый запуск,
но не может переопределить загруженный режим. D4-save не читается/не мигрируется.

Сохранение игры остаётся на уровне начала боя H1/U14: загрузка `battle`
повторяет расстановку/бой из checkpoint, а не середину хода. Deck checkpoint
фиксирует состав активных копий и draw_seed, поэтому стартовая рука совпадает.
Restore боевого snapshot для worker/preview, напротив, возвращает точные
hand/draw/spent/mana/эффекты/RNG. Не обещать дисковое сохранение середины боя.

Любая постоянная операция: копия → проверка входа → расчёт candidate → полная
валидация → atomic write → публикация. Запись неуспешна: блокировать ввод,
держать тот же candidate; повтор без новых RNG/ID/XP/награды. После успешной
записи и crash до публикации load видит уже совершённую операцию. Receipt
содержит ruleset и `(run_id,node_id,battle_serial)`; режим/фаза/serial обязаны
совпасть. Battle outcome не принимается от worker pending/FAULTED.

| Операция | Что фиксируется одним барьером |
|---|---|
| Сохранить базу в hub | Весь валидный состав; отмена редактирования ничего не пишет |
| Начать поход | Run ID, изолированные 10 base-копий, весь план/тройки/seed, прежнее стартовое лечение; профильный expedition RNG продвинут один раз |
| Войти в бой | Выбранный узел, serial, checkpoint; только затем открывается расстановка |
| Победа любого боя, включая финал | Старые правила XP/смертей/лечения/достижений/золота комнаты, report pending и phase=reward; текущий узел ещё не resolved |
| Выбор/отказ нефинальной награды | reward_decision, одна found-копия сразу active либо ни одной, report chosen/skipped, узел resolved, phase=route |
| Выбор/отказ финальной награды | То же решение, затем полный возврат/переработка/открытия и phase=hub с удалением run; report остаётся open |
| Поражение | Прежние потери/итог, уничтожение всех походных копий; без ресурса и новых открытий |
| Костёр: применить состав | Весь новый active_ids при ≥10; base и found можно убирать/возвращать; копии сохраняются |
| Ранний выход | Уничтожение всех копий; эссенция только found, открытия типов found, report/кошелёк/hub — единый commit |

После терминального receipt повторный outcome запрещён уже в phase=reward;
reload не повторяет XP. В финале до решения награды поход не завершён, новый
поход/маршрут/редактирование недоступны. Закрытие игры не означает отказ.
«Продолжить» закрывает отчёт только после chosen/skipped (или none при поражении).
Повтор выбора/отказа отвергается без изменений. Ремонт и его ledger остаются
по POST_BATTLE_V1; в ожидании финального выбора ремонт заблокирован, после
возвращения действует обычный доступ отчёта/хаба, без изменения цен.

Ранний leave **создаёт новый открытый schema2 report**, даже если предыдущий
боевой отчёт уже закрыт. До удаления run захватить returned_cards (включая
пассивные), run/node/serial, кошелёк/эссенцию/потери и новые открытия. Установить
source=expedition, gold_scope=hub, open=true, return_reason=early, victory=true,
completed=false, reward_state=none, offered_types=[], selected_type="",
selected_card_id=0. Строки выживших показывают нынешние значения; XP/лечение/
достижения/repair receipts в этом новом отчёте нулевые/пустые, не повтор прошлого
боя. Victory здесь означает успешное возвращение; отчёт не запускает начисления.
Для финала существующий pending report после решения становится completed,
для поражения — defeat; они сохраняют строки фактического последнего боя.
Returned_cards строится после финального выбора и до уничтожения копий.
Запись отчёта, открытий, валют и удаления run — один candidate/barrier.
Schema2 validator разрешает открытый return-report при phase=hub/expedition={},
проверяет исторические ID по самому payload, не ищет удалённые карты в run.
При раннем выходе node — camp, serial — последний battle serial. Continue
сохраняет только open=false; restart до него показывает тот же итог, после него
не открывает отчёт заново. Старый schema1 validator этим не ослабляется.

## 5. Случайность, рука и команда розыгрыша

Новый генератор сохраняет форму карты/услуги/золото U14, заменяет только artifact
каталог и награды; троек теперь требует каждый battle/elite/final узел.
U-D14: три разных типа из 12, все равновероятны, уже имеющиеся не исключаются.
Генерация один раз на старте похода: в порядке node_id частичный Fisher–Yates
лексикографического массива 12 ID, выбрать первые три; порядок тройки сохраняется.
Использовать независимый reward RNG, не graph/battle seed/H1 recruitment RNG.
Его seed — SHA-256 UTF-8 `mage-reward-v1|<plan.seed>`, первые8 байтов little-endian
с очищенным старшим битом; числа как для draw_seed ниже. Это отдельный CombatRng
schema1 с `next_int("combat",bound)`. Для позиций i=0,1,2 выбрать j=i+draw(12-i)
и обменять элементы i/j. Отрицательный результат RNG отвергает весь candidate.
Полный план хранит предложенные ID/определения, UI не раскрывает будущие тройки.
Непредложенный ID/повторный выбор/подмена версии — отказ без мутации.

Для нового draw RNG seed = первые 8 байтов SHA-256 UTF-8 строки
`mage-deck-v1|<run_id>|<node_id>|<battle_serial>|<battle_seed>` как unsigned
little-endian, старший бит сброшен. Числа десятичные без пробелов/ведущих нулей.
Ноль допустим. Вычислить один раз при checkpoint, при чтении сверить; отдельный
CombatRng использует свой `next_int("combat", bound)`, не context.get_rng().
Начальный массив active ID сортируется и перемешивается Fisher–Yates от конца,
один draw для каждой границы >1. Верх draw — индекс0, новые карты идут в конец
руки. Все случайные планы вычисляются на clone и публикуют RNG вместе с зоной;
validate/hover не потребляют live RNG. Ошибка RNG не оплачивает действие.

В setup выдать 5 карт. До начала боя одна подтверждаемая замена 0..2 выбранных
различных копий; не тратит замену первого хода. `ConfirmMageMulliganCommand`
исполняется только в setup через очередь, после подтверждения расстановки;
до этого выбор слотов локален UI. Для неё временно убрать все
выбранные копии из руки, а из исходного draw последовательно выбрать замены
в прежнем порядке слотов руки: равномерно среди **копий** типов, отличных от
заменяемого; если их нет — среди всех доступных копий.
Возвращаемые копии не доступны друг другу в этой операции. Вставить новые в
те же слоты, затем вернуть выбранные в draw и перемешать его. Подтверждение
нулевого выбора не меняет RNG. После `mulligan_done=true` повтор невозможен.
Это точная адаптация принятого эталона, не обещание всегда иного типа.

В свой active-ход разрешена одна замена копии в руке, без маны/main, лишь при
непустом draw; алгоритм как выше для одной карты. В пустом draw отказ без траты
замены/RNG. Сохранить `replaced_serial`; serial берётся из командных часов,
а не frame/UI. Разрешение заново возникает в следующем своём ходу.
В конце своего хода добрать одну, если есть draw и рука <6; полная рука ничего
не сжигает, пустой draw ничего не делает. Spent не возвращается до нового боя.

`PlayMageCardCommand(card_instance_id, target_id, target_cell, revision)`:
проверить capability, окно K18, членство в hand, источник определения/цель,
цену, полные guards и резерв событий/ID до первой записи. Карта не требует
выбранного героя. Новая мана: первый свой ход максимум/остаток2 при любом порядке
команд; на каждом следующем своём begin максимум+1 до9 и полный refill.
Пропуск собственного хода не останавливает рост/добор. Main/bonus героев не тратить.

В prepare составить after маны и hand→spent; запись обеих частей оплаты без
callback, затем событие `mage_card_played` и общий effect executor.
Невалидная цель/нет маны/не та копия — отказ до оплаты. При FAULTED после оплаты
карта и мана остаются в фактическом prefix; автоматического возврата нет.
Событие оплаты содержит type/instance ID, actor=0, target/cell, source,
mana_before/after; `deck_changed` содержит before/after зон и причину
initial/mulligan/replace/draw/play. Новые draft validators/receipt frames
проверяют эти поля отдельно от legacy `mage_cast` (у него предел6/старые цены).
Никакого второго списания через K18 `paid()` или UI.

## 6. Огненное усиление и границы хода

Запись эффекта: `{unit_id, source_card_id, applied_team_serial, expires_after_serial}`;
expires = applied+2, бонус фиксирован каталогом. Новый розыгрыш заменяет source
и обе метки срока; не добавляет ещё +2. Счётчик — команды цели, не действий
юнита. В своём ходу №s работает сразу, весь s+1 и s+2; удалить в конце s+2.
Проверить overflow до оплаты. Смерть удаляет запись с guard в исполненном
prefix; конец боя сбрасывает её без тика. Save/restore боевого runtime сохраняет
срок; новый бой его не переносит. Отображать «этот ход +2 следующих» либо
остаток полных ходов по фактическим serial.

Обычная атака — корневая AttackCommand с default attack ID конкретного бойца
из actor loadout; helpers получают свою default binding при admission.
Это отдельный value-реестр `ordinary_attacks`, не ссылка на ограниченный
трёмя героями BattleArtifactState. Допуски/обновление binding валидируются
в factory и summon admission. В v1 factory/loadout использует канонический
`hero_attack_<unit_id>`; без персонального attack descriptor (враги, helpers,
диагностические сцены) default — `demo_strike`. Codec сверяет каждую binding
с этим правилом по ability catalog, а admission сверяет каталог с AttackRules;
подстановка существующей специальной/чужой атаки отвергается. Владелец
fire_imbue при capture/restore обязан быть живым PLAYER без pending.
Реакционные follow-up, способности/заклинания,
предметы, DoT, толчок/падение/среда бонус не получают. Бафф доступен помощнику.
Компонента fire/standard base2 добавляется в обычный ArmorAttack pipeline
до текущих множителей/группирования D0, защит и щита; не отдельный damage hit.
Она проходит те же правила модификаторов огненной компоненты, не поджигает
автоматически и не создаёт новую реакцию. Preview/контракт P07 привязаны к тем
же компонентам и исходной записи баффа, не к позднему чтению live UI.

Новый режим исполняет: close → прежний ControlTurnEnd → карточная end-граница
(истечение баффов уходящей команды, затем добор игроку, затем отметка ended) →
прежние collapse/bleeding/refill → begin (мана/serial) → open.
Карточная end-граница — одна очередь с заранее вычисленным after для часов,
баффов, зон и draw RNG; повтор того же serial отвергается. Между частями нет
окна ввода. Legacy исполняет нынешний порядок без карточной ветки.
На terminal/FAULTED после любого корня хвост перехода не выполняется.
Смена выбранного героя не влияет на serial/ману/замены/сроки.

## 7. Изоляция, UI и критерии проверки

Внебоевое представление перенесено в редактируемые сцены:
[HUB_SCENES_V1](HUB_SCENES_V1.md). Таблица ниже по-прежнему задаёт поведение;
боевые панель/рука этим переносом не изменены.

Добавить deck/card_effects к ItemSimulationState, capture/restore/clone,
SpatialRules guard и ожидаемым phase-after, snapshot bytes, admission и всем
forecast/live workers. Проверяются не только значения, но identity/reference
наборы runtime/definitions/items, counters/events/steps и оба боевых RNG.
Callbacks старых атак/лечения/щита/призыва также не могут менять новые поля.
Worker получает detached validated graph; UI читает только копии после join.
Неизвестные callbacks/scripts — прежний sync fallback. Hover не мутирует,
click строит свежую команду. Кэш по одной revision не вводить.

| Экран | Минимальный законченный UI пакета |
|---|---|
| Hub | Каталог12, счётчик10/10, количество0..2, цена/описание/placeholder; Сохранить/Отмена; выход при невалидной базе запрещён |
| Расстановка | Пять карт и выбор до двух замен, явное подтверждение/пропуск; начало боя только после завершения замены |
| Бой | Рука до6, мана текущая/максимум, draw/spent counts, оставшаяся замена, обычные UI причин недоступности; старую фиксированную панель мага в deck-режиме убрать |
| Цель | Выбор копии → подсветка/прогноз → свежая команда; Esc отменяет. Успех/отказ очищают режим и возвращают движение, отвергнутый клик не двигает героя |
| Награда | Три сохранённые карты, «Отказаться», затем «Продолжить»; в финале показать предстоящую переработку выбранной копии и итог после записи |
| Костёр | Active и пассивные копии с origin; применить весь состав ≥10 или отменить. Доступ после услуги безопасной точки в camp_departure; обычный rest не даёт редактор |
| Итог | Раздельно карты-находки/переработанное число/эссенция/новые открытия кузни; потеря при поражении; нейтральный допуск и крафт не смешивать |

Редактор базы только в hub; походная сборка только на костре, не на любой карте.
Подтверждённая награда сразу active, без дополнительного экипирования. Пассивное
хранение карт отдельным разделом общего UI, без предметного стака/бонуса герою.
Кнопки при save pending/worker/transition заблокированы. Изображения — заменяемые
заглушки/существующие значки; новый финальный арт не нужен. Legacy UI выбирается
по сохранённому режиму и сохраняет пояс/панель/отчёт старого похода.

Панель запрашивает `mage_card_reasons` для всей руки: общий аудит capability
выполняется один раз в этом синхронном вызове, затем причины каждой карты.
Между обновлениями результат не кэшируется; изменения без revision видны при
следующем опросе. Клик/замена/preview отдельно вызывают свежую singular-проверку.

Для изменения пакета обязательны import/parse, адресные meaningful runners,
full/render по [TESTING](TESTING.md), затем независимое ревью фиксированного
результата и один целый пользовательский маршрут. Матрица:

- Codec: согласованные v1/2/3→4; H1 battle, все legacy U14 фазы и открытый отчёт;
  завершение/поражение по старым правилам, затем новый deck-run. Неизвестные
  версии/content/hybrid/дубликаты ID/плохая provenance/множества/RNG — отказ.
- Save: failed write + retry и restart до/после commit на каждом барьере §4;
  нет повторных XP/лечения/достижений/карт/эссенции, оба финальных выбора и отказ.
- Рука: старт5, mulligan0/1/2, одинаковые типы/fallback, replace один/ход,
  draw при6/пустом, исчерпание без штрафа/reshuffle, новый бой и checkpoint replay.
- Мана: игрок первым/вторым даёт2, затем3..9, полный refill; смена героя,
  пропуски, нет main/bonus/cooldown. Все12 карт на реальных целях/эффектах R14/K17.
- Бафф: сразу/s+1/s+2/истечение, refresh, помощник/pending, смерть, обычная атака
  против реакции/способности, крит/щит/сопротивление, guard/P07/parity без двойного hit.
- Поход: база10/max2, свободный каталог12, найденные дубли active; костёр≥10,
  base в пассиве, found в пассиве; переработка10 только found, финальная находка
  включена, отказ не даёт10, поражение не даёт ресурсов/открытий и хранит прежние.
- Изоляция: полные snapshots/events/steps/counters/admission/оба RNG для sync,
  preview и workers; callback на оплате/HP/щите/призыве/end не меняет чужой
  runtime без FAULTED, показ сохраняет реальный prefix. Sequence/ID overflow.
- UI: реальный ввод всего пути, reload legacy и нового режима, отказ/выбор карты,
  отмена/ошибка цели, busy/retry, читаемые шесть карт и срок баффа; PNG осмотр.

Инициатива остаётся вне full/render, открытый viewport baseline не маскируется,
рендер `--screen 0`; capture cost не измерен. Frozen Pxx/§4.5 и старые legacy
bytes проверять на неизменность там, где новые capability отсутствуют.
