# Работа команды и ведение контекста

Правила, роли и коммиты — [AGENTS](../AGENTS.md). Здесь процедура делегирования
и ведения контекста; редакция 2026-09-23.

## Адресное чтение и пакет

Выбрать маршрут в [индексе](PROJECT_CONTEXT.md); ссылки не обходить рекурсивно.
В большом контракте искать раздел через rg, читать его целиком с исключениями.
Перечитывать при изменении или утрате контекста; размер не повод пропускать инварианты.

Scout ищет неизвестных владельцев, не повторяет поиск ведущего. Не дробить мелкую
задачу ради агентов. TOML читать при fallback/смене роли, без пробных заданий на старте.

```yaml
task_id: TASK-001
base_commit: <проверенный SHA>
goal: <один наблюдаемый результат>
allowed_paths: []
read_paths: [] # нужные разделы, не вся библиотека
contracts: [] # API, владение, ошибки/мутации, copy/restore/миграция
acceptance: [] # нормальный путь, границы, отказ, изоляция
checks: [] # команды из TESTING и проверки задачи
non_goals: []
```

Передать нужные API/правила явно, без истории чата. CONTRACT_GAP/NEED_CONTEXT
требует уточнения пакета; изменение API — его обновления. Предлагаемый API не факт.
Итог исполнителя: статус, файлы, проверки, непроверенное; reviewer возвращает
APPROVE/REQUEST_CHANGES с конкретными сценариями.

## Владельцы информации

| Информация | Единственный основной документ |
|---|---|
| Правила работы / инструкции ролей | AGENTS / .codex/agents/*.toml |
| Текущая задача, результат, остаток | CODEX_HANDOFF |
| Маршруты чтения | PROJECT_CONTEXT |
| Устройство / инварианты и причины | ARCHITECTURE / DECISIONS |
| Концепция, U/P/Q/A, выбор следующего среза | DESIGN_DIRECTION; §7 без хроники |
| Состав проверки ядра, пробелы и пакет выбранного среза | CORE_READINESS; правила остаются в контрактах |
| Точное поведение и критерии механизма | Его контракт |
| Запуск / команды проверок | REPOSITORY_STATE / TESTING |
| Прошлые этапы, свидетельства | HISTORY, архивы, test_reports/<этап>/ |

Обновлять утверждение на месте; в других документах — ссылка и нужное краткое резюме.
Дата/commit сверки не означают проверку всего проекта. U/P/Q/A отличать от реализации;
ответ закрывает Q с датой, согласование не запускает backlog. Правила хранить в Git,
не только в игнорируемых test_reports.
При изменении поведения обновить контракт и ARCHITECTURE; индекс — при смене маршрута.

## Проверка роста при обновлении

Ориентиры в символах с LF: AGENTS ≤5000, HANDOFF ≤2500, PROJECT_CONTEXT ≤3500,
WORKFLOW ≤4500; промпт следующего чата обычно ≤2500. Это местные ориентиры,
не лимиты модели. Превышение или рост изменённого входного файла более чем на 10%
к его версии в HEAD требует убрать повторы либо записать причину в отчёте этапа.
Не урезать уникальный контракт ради числа; не прятать рост длинными строками.

Перед сдачей проверить владельцев удалённых повторов, ссылки/разделы, сохранность
запретов, вопросов и неполной приёмки. Не добавлять в стартовый пакет каждый срез.
Сравнивать одинаковый набор файлов/разделов до/после отдельно от архивов;
символы/байты не объявлять токенами или экономией лимита Codex.

Размер из корня; сравнение и причины превышения хранить в отчёте этапа:
```powershell
'AGENTS.md','docs/CODEX_HANDOFF.md','docs/PROJECT_CONTEXT.md','docs/CODEX_WORKFLOW.md' |
  ForEach-Object {
    $text = [IO.File]::ReadAllText((Join-Path (Get-Location) $_)).Replace("`r`n", "`n")
    [pscustomobject]@{Path = $_; Chars = $text.Length}
  }
```

## Передача без накопления истории

HANDOFF обычно 25–40 строк: цель/результат, ветка и base, проверки с областью,
незакоммиченное, вопросы/следующий шаг, ссылки на контракт и свидетельства.
Правила прошлых механик, длинные логи и списки SHA оставить владельцам/истории.
Перед заменой сохранить весь исходный файл без изменений в новый
`CODEX_HANDOFF.history-<дата>[-N].md`, добавить ссылку в HISTORY, архив не перезаписывать.
Снимок рядом с исходником сохраняет относительные ссылки. Frozen Pxx/§4.5 неизменны.

Промпт содержит задание, проект и маршрут чтения; состав/вывод — AGENTS.
Не копировать контракты и не запускать новый чат автоматически. Финальный SHA
записать после commit в ответ и completion/next-chat-prompt; собственный hash
в коммите не нужен. Проверить status. Технические проверки не заменяют плейтест.

Набор проверок выбирать по риску через TESTING до запуска. Для локальной правки
не назначать full/render автоматически; расширять при конкретном риске или сбое.
