# Работа команды и ведение контекста

Актуальная редакция 2026-09-23. Роли, модели, права, коммиты и обязательные
ограничения заданы в [AGENTS](../AGENTS.md); здесь их практический процесс.

## Начало задачи

Прочитать текущий CODEX_HANDOFF, сверить HEAD/status, открыть [PROJECT_CONTEXT](PROJECT_CONTEXT.md).
Выбрать только нужный контракт и адресный код. Старый аудит/все modules/Pxx/историю
передач не загружать автоматически. Наличие роли проверять при проблеме с вызовом,
а не запускать диагностические задания каждому новому чату.

Ведущий определяет границу → готовит самодостаточный пакет → ограниченный кодер
реализует → ведущий проверяет → reviewer проверяет фиксированный результат →
ведущий интегрирует и фиксирует. Scout нужен для полезного независимого поиска.
Контракты и критическая интеграция остаются у ведущего по AGENTS.

Пересмотр команды 2026-09-23: Astra/high ведёт архитектуру; Luna 6 low/medium
выполняет поиск/небольшой точный пакет; Sol 6/high — независимое ревью и сложный
пакет с ограничениями кодера. Основание — [назначение моделей OpenAI](https://developers.openai.com/api/docs/guides/latest-model).
Это выбор для проверки на проекте, не измеренная гарантия экономии. API-цена
токена не равна расходу лимита Codex. Экономим объём: новый минимальный контекст,
адресные чтения, краткий итог, повторные проверки только по изменению/риску.
Не запускать scout, если ведущий уже знает нужные владельцы; не дробить мелкую
задачу ради числа агентов. После двух неудачных исправлений сначала уточнить
пакет, затем при необходимости привлечь Sol; критические контракты ведёт Astra.

## Пакет исполнителю

```yaml
task_id: TASK-001
base_commit: <фактический SHA>
goal: <один наблюдаемый результат>
allowed_paths: []
read_paths: []
contracts: [] # сигнатуры, ownership, ошибки/мутации, copy/restore/миграция
acceptance: [] # нормальный путь, границы, отказ, изоляция
checks: [] # команды из TESTING и проверки задачи
non_goals: []
```

Передать необходимые API/фрагменты и принятые правила, не историю чата и весь
дизайн. Предлагаемый тип не выдавать за существующий. При CONTRACT_GAP/NEED_CONTEXT
ведущий уточняет пакет; изменение зависимого API делает старый пакет неактуальным.
Исполнитель сообщает статус, файлы, критерии/проверки, непроверенное и блокеры.
Ревью возвращает APPROVE/REQUEST_CHANGES с конкретными сценариями.

## Один владелец каждой информации

| Информация | Где обновлять |
|---|---|
| Текущая задача, результат, следующий шаг | CODEX_HANDOFF |
| Маршруты чтения | PROJECT_CONTEXT |
| Фактическое устройство и ограничения | ARCHITECTURE |
| Инварианты и их причины | DECISIONS |
| Концепция, ответы/вопросы и рекомендуемая очередь | DESIGN_DIRECTION |
| Точное поведение и приёмка механизма | Его специализированный контракт |
| Команды проверки / исторические результаты | TESTING / HISTORY и отчёты |

Обновлять существующий актуальный текст вместо добавления очередного «состояние
выше устарело». Ссылаться на владельца правила, не копировать полные инструкции.
U/P/Q отделяют слова пользователя, предложения и вопросы; ответ закрывает Q с датой.
Согласование дизайна не означает его реализацию или запуск всего плана.
При изменении факта обновлять соответствующую строку ARCHITECTURE и контракт;
индекс меняется только при изменении маршрута. Отчёты/hashes хранить в новом
test_reports/<этап>/; обязательные для работы сведения должны быть доступны из Git.

## Короткая передача и сохранение истории

С разрешения пользователя на реорганизацию 2026-09-20 прежнее накопление полного
suffix заменено отдельными архивными снимками. CODEX_HANDOFF содержит только
текущую передачу: цель/статус, base и рабочую ветку, результат, проверки,
незакоммиченное, вопросы и следующий шаг со ссылками. Обычно достаточно 25–45 строк.
Перед заменой сохранить прежний файл целиком в `CODEX_HANDOFF.history-<дата>[-N].md`,
добавить ссылку в HISTORY; старый снимок не перезаписывать. При первом массовом
переносе исходные документы сохранены точными suffix архивных файлов.
Снимки лежат рядом с исходными путями, чтобы прежние относительные ссылки работали.
Frozen Pxx/§4.5 и старые отчёты остаются неизменными на прежних путях.

Финальный SHA записать в итоговый ответ и completion/next-chat-prompt после commit;
не требовать от коммита содержать собственный hash. После commit проверить status.
В конце этапа/при блокере вывести полный самодостаточный промпт следующего чата
отдельным блоком кода прямо в ответе: фактический HEAD, результат, docs/artifacts,
остаток, ограничения, проверки и это же правило. Ссылка на файл не заменяет текст.
