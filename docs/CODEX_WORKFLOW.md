# Работа в Codex с субагентами

Настроено 2026-09-13. Это делегирование во время активной задачи, а не фоновое расписание.
Конфигурация локальна этому репозиторию. Подписка, авторизация и политика разрешений наследуются.

## Один раз в приложении
1. Добавить/открыть папку C:\Users\Aston\Documents\into-de-dung как проект.
2. Если приложение запросит доверие к этой папке, подтвердить его в интерфейсе.
   Проектная конфигурация может не применяться в недоверенной папке.
3. Создать новую задачу внутри проекта. Проверить в выборе модели gpt-6-astra, High.
   Явный выбор модели в интерфейсе может перекрыть значение конфигурации.
4. Отправить стартовое сообщение из раздела ниже.
5. В ходе задачи смотреть статус помощников; не нужно создавать им отдельные чаты вручную.
   Если роли не появились в уже открытой сессии, открыть новую задачу; при необходимости
   перезапустить приложение. Самостоятельно глобальные настройки доверия не редактировать.

## Стартовое сообщение
Ты ведущий архитектор intoDeDung. Прочитай AGENTS.md и docs/CODEX_HANDOFF.md,
проверь состояние репозитория. Используй настроенных субагентов для ограниченных задач.
Сейчас: проверь обнаружение game_scout, game_coder и game_reviewer, сообщи назначенные модели.
Не запускай всех ради проверки. Если нужны пробные вызовы, выполняй их последовательно.
Игровой код пока не меняй. Назови следующий шаг и вопросы геймдизайна, от которых он зависит.

## Рабочий процесс
Ведущий составляет ТЗ → game_coder реализует → ведущий запускает проверки
→ game_reviewer проверяет фиксированный diff → ведущий интегрирует и обновляет передачу.
game_scout вызывается только для полезного независимого поиска.
Ведущий сам пишет спецификации и QA-сценарии; отдельные пять вызовов на каждую задачу не нужны.
Параллельные писатели допустимы позднее в отдельных worktree с явным разделением путей.
Рабочая цель — 70–85% обычной реализации делегировать Luna после стабилизации контрактов.
Это не обещание экономии лимитов: считать стоимость принятой задачи и число исправлений.

## Пакет задания
```yaml
task_id: TASK-001
base_commit: <фактический SHA>
goal: <один наблюдаемый результат>
allowed_paths: []
read_paths: []
contracts: [] # конкретные версии/сигнатуры, владение, ошибки и мутации
acceptance: [] # нормальный путь, границы, отказ
checks: [] # точные команды из TESTING.md и тесты задачи
non_goals: []
```
Передать нужные API и небольшой текущий код. Не выдавать неизвестные типы за существующие.
При нехватке информации помощник возвращает NEED_CONTEXT или CONTRACT_GAP.
Ведущий доставляет адресный фрагмент. Изменение зависимого API делает пакет устаревшим.

## Возврат результата
Статус; изменённые файлы; проверенные acceptance-пункты; точные команды/exit code;
непроверенное; блокеры. При ревью — APPROVE или REQUEST_CHANGES и сценарии ошибок.
Не выдавать чистый exit code за полную проверку игры; учитывать вывод и тестовые ожидания.

## Промпт следующего чата

В конце этапа или при блокере обновить CODEX_HANDOFF с точным исходным suffix.
В финальном сообщении привести полный промпт следующего чата отдельным блоком
кода: пользователь должен скопировать его прямо из сообщения, не искать файл.
Файл next-chat-prompt.md можно сохранить дополнительно; ссылка не заменяет текст.
Промпт содержит фактический финальный HEAD, результат, нужные docs/artifacts,
оставшуюся задачу, ограничения и проверки. Повторить в нём правило вывода полного
промпта прямо в сообщении, чтобы оно сохранялось в следующих чатах.

## Настройки
- .codex/config.toml — модель ведущего, включение агентов, лимит 2, дешёвый default.
- .codex/agents/game_scout.toml — Luna / low, чтение.
- .codex/agents/game_coder.toml — Luna / medium, реализация.
- .codex/agents/game_reviewer.toml — Terra / high, чтение и независимая проверка.
- AGENTS.md — постоянное указание делегировать по ролям и ограничивать контекст.

Права роли не сильнее действующих прав сессии. Отдельные инструменты могут не
поддерживать именованную роль; fallback описан в AGENTS.md. Текущий чат автоматически
не становится задачей проекта после записи конфигурации: начать новую задачу в папке игры.
