# Маг и откаты — контракт первого среза K18

Статус 2026-09-27: **реализован связный пакет K18**, техническая проверка
и независимое ревью этого изменения — в отчёте этапа. Base main
`1719f091e24403acbf176bc472323d12bbe10cb0`. U — принятые правила
[DESIGN_DIRECTION §3.2–3.4](DESIGN_DIRECTION.md); A — решения исполнения.
Общая приёмка F5 закрыта; область — [CORE_READINESS](CORE_READINESS.md#статус-приёмки).

## 1. Граница и игровые правила

U: маг вне доски действует внутри хода игрока между полностью завершёнными
действиями/очередями, в том числе до первого и после последнего действия героя.
Main героев не расходуется. Дополнительного общего лимита применений нет.
Смерть/оглушение выбранного героя не мешают магу при живом отряде и продолжающемся
бое. После гибели последнего союзника окна спасения нет. Расстановка, чужой ход,
окружение, BUSY/переход и terminal/FAULTED не являются окном применения.

| U: параметр | Значение первого среза |
|---|---|
| Мана мага | Максимум/старт 6; +2 до максимума в начале каждого хода игрока |
| `mage.fire` — Огненный импульс | Одна живая вражеская цель, база 4 огня, цена 2 маны, откат 2; без толчка/поджога |
| `mage.heal` — Лечение | Один живой раненый союзник, +4 HP до текущего максимума, цена 3 маны, откат 2; без брони/воскрешения |
| Цели | Любая допустимая цель на существующей клетке доски; дальность/линия от героя не нужны. Вступившие помощники допустимы, pending/трупы — нет |
| Остальные способности/действия | Параметр отката обязателен, значение пока 0; прежние цены, заряды и условия сохранены |
| Новый бой / restore | Новый бой: полная мана и нулевые откаты. Restore текущего состояния сохраняет фактические остатки |

U: откат N исключает N полных **следующих** ходов команды владельца.
Ход применения не считается. Уменьшение — в конце своих следующих ходов;
пропуск/оглушение живого владельца не останавливают время. N=0 не добавляет
задержки; применение на №1 с N=1 даёт повтор на №3, с N=2 — на №4.
У мага своя команда — игрок. Покомандный ход утверждён отдельно по
[DESIGN_DIRECTION §7](DESIGN_DIRECTION.md#7-порядок-разработки-и-задание-астре).

A: интеграция только в основной командный бой `BattleCoreReactionsSession`.
Общие определения/адаптеры получают параметр 0 и в прежних сценариях, но маг
и его ненулевой отсчёт не включаются в D4, инициативу или старые fixtures.
Хаб, развитие набора, положительные откаты старых действий/реакций, воскрешение,
новые статусы и полная контрольная точка сессии вне K18. Изменение значения
старого действия на положительное до отдельного контракта отвергается как
неподдерживаемая capability, а не молча игнорируется.

## 2. Сверенные владельцы и реестр охвата

Сейчас `ElementalCastCommand` использует героя, дальность 3 и main; команда
флакона лечит владельца предмета. Ни один путь не является командой мага.
`ItemSimulationState` владеет board/предметами/помощниками/средой;
`ItemSimulationSnapshot` сохраняет envelope 1–6 без capability и использует 7
с capability; UnitState — до 8.
`ForecastSimulation` и `ActionForecastWorker` допускают закрытый список команд.
`BattleExecutionWorker` переносит точную session и проверяет граф runtime;
`TurnForecast` восстанавливает изолированную сессию без reset. Это точки расширения.

A: единый типизированный descriptor `AbilityDefinition` (Resource) содержит
стабильный `ability_id: StringName` и `cooldown_turns: int`. Для магии требуется
также определение эффекта/цены. Адаптеры существующих определений предоставляют
descriptor; UI не выдумывает ноль при отсутствии записи. Набор конечный:

| Семейство и ключ descriptor | Нынешний владелец / правило адаптации |
|---|---|
| `attack:<definition.id>` | `AttackDefinition`, `AttackRules`: включая `demo_strike`, `blood_rune`, `entangling_strike`, `stunning_strike`, `opportunity_strike`, `counter_strike` |
| `move`, `safe_retreat` | `MoveCommand.movement_kind`: разные действия; сегменты пути не отдельные способности |
| `guard:<mode>` | `GuardCommand`, включая охрану/Оппортуниста/Прикрытие/Контратаку; установка режима отличается от его реакции |
| `restore_armor`, `raise_corpse` | `RestoreArmorCommand`, `RaiseCorpseCommand`; поднятие не объединять с предметной печатью |
| `elemental:<effect>` | K17 burning/wet/freeze; герой и цена main сохраняются |
| `item_use:<definition.id>:<kind>` | `ItemDef` → `ItemUseAction`: HEAL_SELF и SUMMON_ADJACENT; разные экземпляры не объединять по одному definition ID |
| `perk:<field>`, `immunity:<capability>` | Все семь полей `CombatPerksDefinition`, а также способности иммунитета в Control/Bleeding/Elemental; пассивная скрытая атака тоже имеет 0 |
| `item_effect:<definition.id>:<index>` | `StatModifierEffect` и `HealOnDamageEffect`; descriptor эффекта отличен от автоматической команды-последствия |
| `team.end_turn` | Завершение командного хода, descriptor 0; не блокировать переход новым ресурсом |
| `mage.fire`, `mage.heal` | Новый отдельный набор мага, значения §1 |

Фактический перечень определений собирается из доступного каталога, а не только
из этих демонстрационных ID. ИИ использует тот же descriptor выбранного действия;
BT по-прежнему выбирает намерение, команда исполняет. Непрерывная пассивка с 0
не получает искусственного события применения. Тики статусов, урон/смерть,
падение, цепной толчок, refill и реакции среды — технические последствия;
их нельзя задерживать откатом как самостоятельные способности. Выбор/осмотр,
reset и редактор расстановки не боевые способности.

Ключ runtime отделён от descriptor: `(owner_kind, owner_id, ability_id,
source_instance_id)`. Для мага owner_kind=mage, owner_id=0 — отдельное пространство
имён, не UnitId; для героя owner_id — его настоящий ID. Для предмета обязательны
пара owner ID/item instance ID и индекс эффекта при необходимости. Перестановка
слота внутри владельца не создаёт новый ключ. Межвладельческий перенос предмета
в бою сейчас не поддержан; K18 его не добавляет. Все такие откаты пока 0.

## 3. Runtime и часы команды

A: новая nullable capability `BattleAbilityState` (RefCounted) принадлежит
`ItemSimulationState`, не выбранному герою, UI или autoload. В ней: отделённый
каталог значений, мана, таблица остатков, часы обеих команд и допуск магии.
Маг не получает UnitState/клетку/HP/occupancy и не занимает счётчик UnitId.
Определения не меняются оплатой; runtime не переиспользует Resource как запас.

Для положительного остатка сохраняются `remaining` и `skip_current_end`.
При применении N>0: remaining=N, skip=true. На ближайшем конце своей команды
skip снимается без уменьшения; на следующих remaining уменьшается на 1 до 0.
При 0 skip=false и запись канонически готова. Пример N=2: после каста (2,true),
конец №1 (2,false), конец №2 (1,false), конец №3 (0,false), повтор на №4.
Для нулевых старых действий не создавать события/записи расхода отката.

Часы хранят серийный номер хода каждой команды и уже обработанный конец;
дублированная/неправильная граница отвергается до записи. Нельзя использовать
только общий round_number, выбранного героя или revision вместо часов.
Внутреннее окно магии закрыто в setup/переходе/terminal. Session проверяет свою
фазу, core-команда — этот сериализуемый допуск; расхождение не исправляется
молчаливым refill. Номер команды и stage проверяются вместе с ожидаемым revision.

Все числа целые, неотрицательные, без bool/float-подмены; mana≤maximum,
remaining≤определённой длительности, skip допустим только при remaining>0.
Операции счётчиков проверяются на int64 overflow до мутации, не клэмпятся.
Клэмп до максимума допустим только для принятого восстановления маны/HP.
Остатки не сбрасываются выбором, сменой панели, preview или повторной загрузкой.

## 4. Команда, оплата, источник и последствия

A: `MageCastCommand(spell_id, target_id, expected_revision)` — новая корневая
команда. Session-методы `cast_mage_spell`/`prepare_mage_forecast` получают scalar
ID; не используют selected_id для оплаты, дальности, принадлежности или source.
Оба пути строят одну команду. Core проверяет capability/каталог, окно своей
команды, отсутствие terminal/FAULTED, живые команды, цель/фракцию/pending,
доступный откат, ману, состояние брони/HP и вместимость новых событий/счётчиков.
UI предварительно объясняет отказ, но не заменяет admission исполнения.

До первой записи полностью рассчитывается допустимость эффекта: full/over-max
HP не лечится и ничего не платит. Живая допустимая вражеская цель с нулевым
итоговым уроном остаётся допустимым платным попаданием. Отказ admission не меняет
ману/откат/HP/RNG/ID; INVALID/unsupported не подменяются успешным пустым действием.

Сначала один guarded шаг списывает ману и ставит откат/skip, затем исполняется
эффект. Между двумя частями оплаты нет сигнала/callback. Checkpoint проверяет
identity и значения capability/каталога/цели/предметов/RNG, включая прямую
мутацию без revision. После оплаты любой FAULTED сохраняет фактический prefix:
без возврата маны, сброса отката или повторения эффекта. Игровые реакции идут
через общую ActionQueue; исход проверяется после drain, как сейчас.

Для источника добавить `DamageSource.kind = mage` без переупорядочения прежних
значений. `instigator_unit_id=credit_unit_id=0`; source_instance_id — постоянный
код заклинания (1 fire, 2 heal) в пространстве mage, не аллокация предмета/юнита.
`origin_cell=(-1,-1)` означает отсутствие пространственного источника только
для mage. Это не клетка героя/цели и не вход для высоты/дальности/угроз.
Корневое событие дополнительно содержит строковый spell_id и before/after
маны/отката; общие HP-события сохраняют прежнюю форму. Расширяются строгие
валидаторы source/events, а не снимается их проверка.

Огненный импульс использует `ArmorAttack`/`ArmorHitExecutor`: только огненная
база 4, нейтральная высота, прежние множители стойки цели и крита замороженной
цели, стандартная броня/сопротивления/округления/возможное лечение и добивание
замороженного. Нет оружейной базы, пробивания предметом мага, скрытой атаки,
толчка или наложения огня. Это техническая конкретизация существующего пути K17,
не новая формула. Поджог/мокрый/заморозка не меняются от отдельного наложения,
потому что его нет; death и предметные реакции на фактический урон сохраняются.

Маг не цель контратаки и не участник ближних угроз. Не вызывать attack-specific
контратаку подстановкой фиктивного героя: нынешняя `_counterattack_after`
рассматривает только корневой AttackCommand. Реакция предмета получателя на
реальный damaged и последствия смерти должны пройти прежним путём. Лечение
использует guarded Vitals/HP-примитив без вызова команды флакона и без события
item_used, расхода заряда, стойки/main/bonus или has_attacked героя.

## 5. Переход команды и остановка

Нынешняя цепочка: `BattleCoreCombinationSession._refill` исполняет истечение
контроля исходящих; `_after_team_end` в наследнике — окружение при переходе
к врагу; унаследованный BleedingTurnCommand — начало входящих; BattleTurnRefill
пополняет их действия/реакции и включает pending-помощников.

A: в K18 переход целиком закрывает ввод и проходит через guarded команды:

1. Закрыть окно магии и отметить начало перехода для текущего team/serial.
2. Прежнее истечение контроля исходящей команды → проверка исхода.
3. Обработать её конец откатов один раз по §3 → проверка результата.
4. Прежнее окружение, если требуется → проверка исхода.
5. Прежние эффекты начала входящей команды → проверка исхода → прежний refill.
6. Начать новые часы входящей команды; для игрока +2 маны. Опубликовать новую
   фазу и открыть окно магии только после успешного завершения перехода.

После каждого root FAULTED/terminal останавливает хвост; никакого позднего
тика, восстановления или открытия окна. Сессионный `_transitioning` покрывает
весь переход. Core допуск закрыт на промежуточных стадиях, включая публикацию
их событий. Повтор перехода после отказа не должен второй раз уменьшить откаты.
Обновление допуска не меняет незавершённый FAULTED prefix и не лечит fault.
Первый бой: полная мана/нулевые остатки и часы первого врага устанавливаются
один раз при старте после расстановки. Первый ход игрока получает обычное +2
до максимума; reset/restore не выдаются за дополнительные начала хода.

## 6. Снимки, guards и прогноз

Реализованная проверка реестра требует полный набор фиксированных descriptors;
предметные записи точно совпадают с definitions владельцев в envelope schema7.
Неизвестные пространства имён и лишние/пропущенные предметные ссылки отвергаются
до восстановления. `attack:<id>` ссылается на отдельно переданный AttackRules:
полное совпадение проверяется до root admission и подготовки прогноза, включая
прогноз границы хода. Board/items snapshot не подменяет собой AttackRules.

A: ItemSimulationSnapshot schema7/scope `board_items_abilities_v7` для состояния
с capability. Новый обязательный вложенный payload имеет свою schema1:
каталог определений по стабильным ID, мана, ledger, часы/stage/допуск. Формы
вложенных значений точные, с лимитами/уникальностью/каноническим порядком и
проверкой ссылок. Новые значения обязаны пережить capture→from_dict→instantiate.
Нельзя восстановить только remaining, потеряв skip/часы или цену определения.

Состояния без capability сохраняют точные прежние формы 1–6; Unit1–8 и Board
не получают фиктивного мага. Restore старой формы не создаёт мага и полную ману;
включение K18 — только composition root нового боя. Старые определения без поля
адаптируются к 0; сериализованный descriptor с пропущенным/плохим полем в schema7
отвергается. Downgrade с потерей capability запрещён. D4-save не расширяется.
Только боевой snapshot не становится полным save сессии: для resume нужны также
прежние session/context/queue/RNG данные; часы/допуск должны им соответствовать.

`SpatialRules.Guard`, остальные общие guards и проверки copy/restore фиксируют
identity и значения capability/определений, даже если выполняется старое действие.
Callback, меняющий ману/откат при ударе героя без revision, должен обнаруживаться.
Разрешённые delta оплаты/тика проверяются от исходного baseline, без recapture,
принимающего чужую мутацию. Нулевой каталог не меняет старые формулы/остатки/цены.

`ForecastSimulation.prepare/run_prepared` отделяет весь новый граф и допускает
MageCastCommand; `ActionForecastWorker` включает его явно. Preview исполняет
ту же команду на копии state/definitions/queue/RNG с теми же счётчиками. DTO
получает mage before/after и откаты без ссылок на live. `TurnForecast` переносит
новые данные и выполняет настоящую расширенную границу до первого решения ИИ.
Синхронный и worker пути обязаны совпасть по полным snapshots/events/steps/RNG/ID,
а не только ожидаемому HP. FAULTED не публикует готовый результат.

`BattleExecutionWorker` расширяет allowlist типов/методов и scalar-аргументы.
Во время владения worker UI не читает mage/runtime; публикуются только значения
после join. Новые данные входят в проверку внешних callbacks и unknown subclass.
Нет кэша допуска/мира только по revision. Reset/exit присоединяют оба вида worker.
Выбор заклинания и свежая публикация прогноза учитывают поколение/session,
фазу, spell/target, каталог, ману и полный ledger, включая прямую мутацию.

## 7. Проверяемая поставка

Один связный пакет: definitions/реестр, capability/codec/guards, команды и
границы, прогноз/оба worker, две отдельные кнопки мага и строки маны/откатов
в диагностическом UI. Изображение магического шара, новая графика и баланс
не нужны. Hero main/остатки показываются отдельно; откат определения и текущий
остаток не смешиваются. Общая ручная приёмка — один бой F5, без микроплейтестов.

Критерии проверки реализации:

- Наличие параметра у всего реестра §2, включая ИИ/пассивки/предметы; все прежние
  нули сохраняют результаты и не порождают новые затраты/реакционные задержки.
- Окно без выбранного живого героя; до/после действий, две магии, нехватка маны,
  полный HP, чужая/pending/мёртвая цель, последний союзник/враг, BUSY/terminal.
- Все 0/1/2 на определении мага; конец хода применения, пропуск/оглушение,
  повторный вызов границы, restore до/после конца, новый бой/reset, overflow.
- Стойка/armor50/уязвимость/сопротивление>100, замороженный крит/добивание,
  предметная реакция/смерть/тело; отсутствие контратаки против фиктивного героя.
- Malformed schema/catalog/source, отрицательные/дубли/неизвестные записи,
  immutable definitions и независимые restore/preview, точные legacy roundtrip.
- Callback после оплаты/armor/HP/death и на каждой стадии перехода: правильный
  prefix, сохранённая цена, отсутствие хвоста и защита новых данных в старой атаке.
- Полный parity sync/live-worker/action-preview-worker/TurnForecast, повторные
  прогнозы без live RNG/ID/ресурсов; pending input/reset/exit и refresh без revision.

Импорт/разбор, адресные runner, full/render по [TESTING](TESTING.md), затем
независимое ревью фиксированного результата. Свидетельства проверок —
`test_reports/mage-cooldowns-k18-20260927/`; состав покрытия — CORE_READINESS.
Существующий дефект initiative_ui ниже viewport учитывается отдельно, не скрывает
новые ошибки. Границы пользовательской приёмки ядра — CORE_READINESS.
