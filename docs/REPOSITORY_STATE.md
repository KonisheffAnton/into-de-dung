## Обычный запуск

Получите репозиторий через `git clone`, откройте `project.godot` в Godot 4.7
и нажмите F5. Проверенная здесь версия — Godot 4.7.2. Стартует
`scenes/demo/tactical_battle.tscn`. Сцену полигона можно открыть и запустить F6.

Для изолированных проверок нужен Python 3 и Godot. Укажите `GODOT_BIN` либо
передайте путь параметром `--godot`; локальная запасная запись launcher относится
только к исходному компьютеру разработчика.

```powershell
python tools/demo/isolate.py --check --full --godot "C:\Tools\Godot\Godot.exe"
python tools/demo/isolate.py --render-check --godot "C:\Tools\Godot\Godot.exe"
```

Путь к Godot в примере нужно заменить своим. Launcher создаёт отдельную копию
исходников и профиль приложения; новые результаты помещает в `test_reports`.
Там отслеживается только `.gdignore`: Godot не импортирует архивные копии скриптов.
Сами логи/PNG не входят в Git и для запуска игры не нужны. Новая копия репозитория
получит собственные отчёты после запуска проверок.

До коммита дерево Git `09f3808b7b806b98b90dcfe204ac38f3ddea9a1f` было выгружено
в отдельную пустую папку через `git archive`, без добавления локальных файлов.

Независимый reviewer подтвердил точный состав 16 файлов и APPROVE.

В старом core runner остаются известные 47 ObjectDB / 18 resources при выходе;
runner демо и боя проходят без этой диагностики. Чистый клон с изменениями
интерфейса `091ee40081862de4f8673e00ad6f195ddee43efe` прошёл import/startup,
полигон 138/0 и бой 152/0; `git status` после проверок чист. Графический прогон
этого кода: полигон 143/0 и бой 158/0. Последующее добавление инструкции и передачи
не меняет проверенные игровые исходники; их хеши дополнительно сверяются в клоне.
Состав команды, геометрия, урон, предметы, BT и полный сценарий боя этим
техническим коммитом не менялись. Frozen документы и §4.5 остаются историческими
контрактами соответствующих этапов; актуальное управление — TACTICAL_BATTLE.md.

AGENTS.md, CODEX_WORKFLOW.md и .codex содержат инструкции работы с проектом.
CODEX_HANDOFF хранит текущую передачу и точную предыдущую передачу как suffix.
После содержательных этапов следует фиксировать связанные код, тесты и документы
вместе, проверять `git status` и явно объяснять любой необходимый незакоммиченный файл.
Локальные коммиты и отправка на remote — разные действия; публикация требует
отдельного поручения пользователя.
