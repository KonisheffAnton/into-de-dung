# Запуск и воспроизводимость

## Обычный запуск

Текущий desktop renderer — **Mobile**, на Windows — **Direct3D 12**.
Мобильный platform override сохраняет `gl_compatibility`. Резервный запуск
с прежним renderer: `godot --path . --rendering-method gl_compatibility`;
Vulkan для диагностики: `godot --path . --rendering-method mobile --rendering-driver vulkan`.
Смена renderer требует перезапуска редактора/игры; import и профиль проверок
по-прежнему изолируются launcher. [Причины и измерения](performance/battle-soak-20261031.md).

Локальный checkout с 2026-10-08: `D:\Games\into-de-dung`.
Открывайте `project.godot` из этого каталога. Проект использует относительные
`res://`-пути; старый каталог в Documents для запуска не требуется.

Арт поля подключён к актуальному бою из хаба:
F5 → «Начать тест» → «В путь». `hero_hub_battle.tscn` получает
штатную сессию похода; текущий состав и облики определены ниже.
Enter — подтвердить расстановку; колесо/кнопки — масштаб,
ПКМ — сдвиг. Это пробный арт, ещё без художественной приёмки.
Старая `scenes/demo/art_trial_battle.tscn` (F6) остаётся отдельной проверочной
сценой с R-сбросом; она не является текущим экраном похода.
Материалы и границы — [арт-проба](art/defender-field-20261009/README.md),
[текущая проба травы](art/grass-reference-20261010/README.md),
[показ при масштабировании](art/pixel-zoom-20261010/README.md).

Эксперимент инициативы удалён; основной бой использует покомандный ход.

Откройте `project.godot` в Godot 4.7 и нажмите F5. Проверенная в проекте версия —
4.7.2; главная сцена `scenes/demo/main_menu.tscn`. Нажмите «Начать тест», затем в
[хабе](HUB_SCENES_V1.md) нажмите «В путь». Состав до трёх героев, найм,
колода и экипировка доступны через «Управление отрядом»; «К походу» возвращает
главную страницу. В новом профиле каталога4 стартуют Разбойник, Маг и Воин;
Щитоносец, Лучница и Нездоровый хоб-гоблин представлены у противника
([состав](CLASS_SHOWCASE_V1.md), [хоб-гоблин](SICK_HOBGOBLIN_V1.md)).
Облик класса выбирается в хабе: «Наёмники» → герой → «Облик».
Вкладки «Наёмники», «Кузнец», «Школы» открывают независимые
каркасы: выбор героя/предмета/узла и перелистывание работают только в UI;
улучшение, разборка и изучение отключены. «Управление экипировкой» ведёт в прежнее
управление. Карта модулей и редактирование — [HUB_SCENES_V1](HUB_SCENES_V1.md).
Новый поход сразу открывает расстановку в стартовой комнате со всеми текущими
опасностями и пятью классами на обеих сторонах вместе, без дополнительных NPC.
После победы карта [U14](EXPEDITION_U14.md)
показывает следующие пути; условия дальних комнат скрыты. Действует
[колода мага](MAGE_DECK_V1.md): базу можно
пересобрать в хабе, после расстановки подтвердить/пропустить замену до двух карт.
После победы выберите карту или откажитесь, затем продолжите; у безопасной точки
после услуги доступны состав колоды и выход. Финал требует решения награды перед
возвратом. Загруженный legacy H1 бой/старый U14 поход сохраняет прежние правила.
На время плейтестов меню по умолчанию использует `temporary_profile = true`:
каждый F5 создаёт новый отдельный профиль `user://hero-hub-playtest-*.save`.
При обычном выходе удаляются только его файл, `.bak` и `.tmp`; прежний
`user://hero-hub-v1.save` не затрагивается. Принудительная остановка может
оставить временный файл, но следующий запуск его не загрузит.
Для продолжения между запусками отключите **Temporary Profile** у корня
`main_menu.tscn` в Inspector: кнопка станет «Продолжить», будет использован
**Save Path** (по умолчанию `user://hero-hub-v1.save`). Загрузка посреди боя
повторяет его с начала. Python launcher использует отдельный каталог профиля;
временный режим меню действует и в нём.
Действия показываются последовательно на временных фигурах ([V1](BATTLE_PRESENTATION_V1.md));
Пропустить / Пробел завершает показ текущего действия, кнопка скорости даёт ×1/×3.
При ошибке записи экран предлагает повтор и не публикует несохранённые изменения.

Самостоятельный принятый бой ядра остался в `scenes/demo/core_reactions_battle.tscn`
(F6); из него доступны прежние демонстрационные режимы. Управление —
[TACTICAL_BATTLE](TACTICAL_BATTLE.md) и [DEMO_SANDBOX](DEMO_SANDBOX.md).
Кнопка «Забег» открывает [D4](EXPEDITION_D4.md): подготовку, два боя, отправку
и возврат. Прямой вход — `scenes/demo/expedition_d4.tscn`; профиль `user://d4-run.save`.
Из подготовки в бой с надетыми вещами ведёт «Отправиться · бой 1 из 2».
«К отдельным боям» выходит из забега в самостоятельный сценарий с его экипировкой.
Загрузка посреди боя начинает его заново с сохранённой контрольной точки.

Самостоятельная сцена ядра открывает расстановку: свободно переставьте отряд в зоне
или нажмите «Начать бой» / Enter с готовой позицией ([K9](CORE_BATTLE_BATCH_K9.md)).
После старта первым ходит противник, затем игрок и окружение. В ход игрока
панель использует четыре слота: атака, защита и два назначения —
[раскладка main/H1](BATTLE_PRESENTATION_REWORK.md#панели-способностей-и-области-действия--образец-2026-10-01).
R возвращает расстановку. Восьмислотовая панель сохранена в legacy-сценах.

Самостоятельный сценарий — «Сочетания ядра» — [K10](CORE_REACTIONS_K10.md),
наследник K9/K2. Бор на E4 может ударить Щита D4 и сдвинуть на шипы C4;
для скрытой атаки нужна вторая ближняя угроза, например Астра на D3.
После обеих команд [окружение K15](ENVIRONMENT_COLLAPSE_K15.md) случайно отмечает
клетку; в следующую свою фазу обрушает её. Пульсирующие трещины обозначают
предупреждение, hover объясняет срок; «Окружение · прогноз фазы» показывает
условный результат при текущем мире.
Астра/Страж получают режимы танка, Бор/Дозорный — пассивку.
Щит имеет иммунитет к кровотечению. Старый вход `core_combination_battle.tscn`
сохраняет прежнюю спину как сценарий регрессии C1/K9.
Астра рядом с телом A4, Рей оглушён до конца вашего хода. Кровавая руна — слот 5,

Это отдельный бой с собственной экипировкой, без загрузки профиля D4.

физический HP-урон от пробивания накладывает путы после последствий удара.

Кнопка «Сочетания ядра» возвращает к K2 из других боевых режимов. «Полигон»

Альтернативный изолированный запуск при установленном Python 3:

```powershell
python tools/demo/isolate.py --godot "C:\Tools\Godot\Godot.exe"
```

Замените путь на свой или задайте GODOT_BIN. Обычный интерактивный запуск сохраняет
рабочую копию и импортированные ресурсы в `test_reports/interactive-cache/`.
Первый запуск готовит её полностью. Повторный сверяет SHA256 исходников и копии,
переносит изменения и удаляет исчезнувшие файлы с их `.import`/`.uid`.
Неизменённый исправный кэш позволяет пропустить импорт; в `timing.json` это
`SKIPPED`, а не результат проверки. Изменения вызывают инкрементальный импорт:
индекс файлов Godot пересоздаётся, импортированные ресурсы сохраняются.
Это учитывает и изменения содержимого с прежним размером/mtime. Исходные файлы
проекта не изменяются; состав игровой копии включает tracked и неигнорируемые
untracked-файлы, кроме `.godot/`, `test_reports/` и `docs/`. Документация, отчётные
рендеры и художественные пробы не нужны игровым сценам и не должны задерживать
сверку/импорт при каждом запуске. Игровые ресурсы должны находиться в `assets/`,
а не загружаться из `docs/`. При первом обновлении прежнего кэша его копии
документов и sidecar-файлы удаляются штатной синхронизацией; оригиналы сохраняются.

Профиль, manifest и логи каждого запуска остаются отдельными в `test_reports/demo-<id>/`.
`timing.json.project` указывает использованную копию; `total_seconds` в cached-режиме —
подготовка до запуска процесса игры, без времени самой игры. Launcher остаётся
работать до её закрытия и держит блокировку копии. Повторный cached-запуск при
открытой игре откажет без изменения файлов; Ctrl+C закрывает только свою дочернюю игру.
После обрыва синхронизации она повторяется. При неизвестном исходе внешнего импорта
или запуска игры следующий запуск создаёт новую копию, оставляя прежнюю нетронутой.
Смена Godot (путь/размер/mtime) также создаёт новое поколение. Для Windows console.exe
учитывается и соседний основной exe: cached-режим запускает его напрямую,
чтобы ожидание и завершение относились к процессу самой игры.

Для независимого запуска с чистой копией используйте `python tools/demo/isolate.py --fresh`
(и при необходимости `--godot`). Этот режим обходит кэш и может запускаться параллельно.
`--fresh`, `--check` и `--render-check` сохраняют полный состав исходников, включая
`docs/`. Проверки всегда создают чистую копию без `.godot` и выполняют прежние
обязательные import/startup gates; `--fresh` с ними не применяется.
Команды и критерии проверок — [TESTING](TESTING.md).

### Автоочистка тестовых копий

Launcher автоматически оставляет **три последние завершённые копии проверок**
`--check`/`--render-check`. Очистка выполняется перед запуском и после завершения
проверок; удаляется только `test_reports/demo-<id>/project/`. Логи, скриншоты,
профили, manifest, timing и каталог отчёта сохраняются без срока удаления.
Это ограничивает число обычных копий, но не общий объём сохраняемых отчётов.

Для отладки с сохранением копии используйте, например:
`python tools/demo/isolate.py --check --only battle_hud_authoring --keep-project`.
Такая копия закрепляется сверх трёх последних и автоматически не удаляется.
Проверки с обычным FAIL также участвуют в лимите: их результаты остаются в логах.

Удаляются только копии с новой явной меткой завершения `project-retention.json`.
Активные, прерванные, завершившиеся timeout/ошибкой запуска и старые копии без
метки остаются нетронутыми: дочерний движок мог продолжить работу.
На Windows проверки запускают соседний runtime вместо `*_console.exe`;
если он отсутствует, проверка остаётся на оболочке без метки автоочистки.
Интерактивные `--fresh`, поколения `interactive-cache` и экспериментальные проекты
не входят в автоочистку. Такие исключения могут потребовать отдельной уборки.
Ссылки/junction внутри пути или удаляемого дерева запрещены; параллельные
очистки разделяет файловая блокировка. Ошибка удаления даёт предупреждение,
не меняя результата проверки; следующая очистка повторит попытку.

## Git и локальные артефакты

Git самодостаточен с фиксации зависимостей `c8dfb0b95e851263151e5f0ce39a9a636434637a`.
Старый dirty overlay восстанавливать не нужно. `test_reports/` ignored,
кроме `.gdignore`; отчёты не нужны для запуска чистого клона. Новый прогон
создаёт собственные логи. Сохранённые инструкции и контракты должны быть в Git,
а не только в локальном отчёте. `.godot/` — генерируемый кэш, не исходники.

Рабочие инструкции — [AGENTS](../AGENTS.md), передача — [CODEX_HANDOFF](CODEX_HANDOFF.md),
индекс — [PROJECT_CONTEXT](PROJECT_CONTEXT.md). Правила коммитов/публикации не
дублируются здесь. Подтверждения прежних clean-clone запусков сохранены в
[архиве воспроизводимости](REPOSITORY_STATE.history-20260920.md).
