# Сравнение командных ходов и инициативы

Поручение пользователя 2026-09-23: проверить темп обоих вариантов до продолжения
разработки механик. Это отдельный прототип, не выбор окончательной системы ходов.
Base: `9c2bae60d57f35fb2529e2925b44717230257f7c`.

## Запуск и сравнение

F5 → «Сравнить ходы» или F6 на `scenes/demo/initiative_battle.tscn`.
Кнопки «Командой» / «По инициативе» начинают одинаковый бой заново; R сбрасывает
текущий вариант. «К основному бою» возвращает обычный командный сценарий.
Рекомендуемый плейтест: по одной полной партии в каждом режиме, затем повторить
в обратном порядке. Оценивать частоту ожидания, удобство планирования комбинаций
и возможность ответить на действия противника. Технические PASS не выбирают концепцию.

Основа обоих вариантов — исходный «Бой у обрыва»: та же карта, позиции, 32 HP,
атака 1 main, движение/bonus, legacy-броня, стойка, флакон, печать и тот же BT.
Это не объединение D2–D5/C1: их дополнительные механики не подключаются к сравнению.
ИИ выполняет те же намерения с прежней паузой отображения 0.7 s.

## Правила эксперимента

- Командой: прежний BattleTacticalSession flow, свободный выбор своих с сохранением
  остатков; Enter завершает ход всей команды.
- По инициативе: один ход каждого живого участника за раунд. Выше INITIATIVE —
  раньше ход, равенство разрешается по UnitId, без RNG. Начальные значения:
  Астра 60, Страж 50, Бор 40, Щит 30, Рей 20, Дозорный 10. Эти же stats заданы
  в командном варианте, но не управляют его очередью. Числа — fixture плейтеста.
- В начале раунда фиксируется отсортированный состав; изменения инициативы
  учитываются в следующем. Погибшие пропускаются, раунд не начинается заново.
  Призванные входят только в следующий раунд со своей инициативой (default 0).
- Игрок управляет только текущим своим бойцом. После атаки можно потратить
  оставшееся движение; Enter явно завершает его ход. Выбор другого не разрешён.
  ИИ управляет только текущим врагом: максимум два намерения, как в базовом бою.
- Только начинающий собственный ход персонаж пополняет ресурсы и теряет стойку.
  Другие сохраняют остатки и стойку. Pending призыва снимается при его первой
  активации; обычный admission и ограничения владельца сохраняются.
- Исход и смерть текущего участника проверяются после полного command drain.
  Победа/поражение/обоюдная гибель/FAULTED завершают действия. Reset и смена
  варианта закрывают прежний runtime; отложенных корутин нет.

## Владение и границы

`BattleInitiativeSession : BattleTacticalSession` владеет экспериментальным
порядком и делегирует командный режим родителю. Сортирует существующая
SimpleInitiativeStrategy. Refill проходит обычную ActionQueue через
BattleTurnRefill для одного ID; команды атаки, движения и прогноз прежние.
`BattleInitiativeDemo : BattleDemo` показывает режим, активного бойца и очередь;
основной UI получил только ссылку-вход. Состояние очереди не сериализуется.

Core, enum, Q1–Q6/frozen, D4 save/profile и правила D5/M1/C1 не меняются.
Общий движок статусов, способности наложения, новые механики, графика и ощущение
удара не входят в эксперимент. Пример пользователя «путы: −1 к движению + ID» —
обсуждение архитектуры, не поручение заменить согласованное поведение C1.
