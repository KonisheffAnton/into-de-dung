# Характеристики, артефакты и подача боя — 2026-09-18

Статус: решения направления и предложения к обсуждению. Игровой код не менялся.
Исходный HEAD: `4866b0d863c33a661c7b1cbf52c63284d163565e`, ветка main.

## Решения пользователя

- Пока отказаться от стандартной концепции инвентаря. Развитие и управление
  сосредоточить на характеристиках и артефактах; ориентир пользователя — Isaac.
- Не требуется строить систему сменного оружия/одежды и отображать каждый
  предмет на теле. Обсуждение 2D-скелета было оценкой возможности, не поручением
  реализовать rig или редактор экипировки.
- Броня в новом дизайне — отдельный расходуемый в бою запас со своей полосой,
  а не простое вычитание из урона HP. Подробную логику пользователь опишет позже.
- Визуальная подача должна стать разнообразнее умеренно. Минимализм и цельность
  Into the Breach — ориентир пользователя; конкретный пакет анимаций ещё не принят.

Это не готовые системы. В нынешнем коде ARMOR ещё уменьшает прямой урон атаки;
новой шкалы брони нет. До её реализации нужны правила приёма урона, переполнения,
восстановления, взаимодействия со стойкой/HP/balance и snapshot/forecast.
Не считать броню автоматически первым поглотителем любого вида урона.

Ссылка на Isaac не определяет автоматически число артефактов, stacking, дубликаты,
снятие/передачу, владельца (персонаж/отряд) или сохранение между боями/забегами.
Эти правила остаются открытыми для отдельного среза. Ранее предложенные ведущим
два артефакта, два инструмента и слот доспеха не были утверждены пользователем.
Текущие флакон/печать, заряды, ownership и восемь мест панели продолжают работать;
отказ от стандартного инвентаря сам по себе не удаляет эти механики/legacy API.

## Предложение ведущего: короткие выразительные действия

Держать поле спокойным во время выбора, кратко выделять исполнение. Одна фигура
может иметь несколько поз или составных частей; полноценный скелет не обязателен.
Самое важное — направление, момент контакта и различие последствий.

| Событие | Предлагаемая подача |
|---|---|
| Выбор/ожидание | Ясный маркер выбранного; едва заметное дыхание или редкая смена позы. |
| Добровольное движение | Быстрый переход по реальному пути, небольшой шаг/покачивание, устойчивое приземление на клетку. |
| Атака | Короткий замах, выпад в сторону цели, дуга удара, контакт, возвращение. |
| Получение урона | Краткая отдача и локальная подсветка места контакта; читаемое изменение ресурса. |
| Толчок/столкновение | Принудительное скольжение без шага; остановка о препятствие с небольшим всплеском пыли/осколков и звуком. |
| Стойка | Более собранная поза и устойчивый небольшой знак защиты; иной звук/вспышка контакта. |
| Лечение | Короткий восходящий эффект, число фактического восстановления, изменение HP. |
| Призыв | Небольшой знак на клетке, появление силуэта, ясный маркер ожидания первого хода. |
| Артефакт | Значок эффекта/короткий всплеск при реальном срабатывании; редкий важный артефакт позднее может иметь заметную деталь. |

Рабочий диапазон для первого макета обычной атаки — примерно 0.3–0.5 секунды;
это гипотеза для проверки темпа, не обязательная длительность. Для сильного
контакта можно проверить очень короткую остановку локального движения фигур.
Она не ставит на паузу симуляцию/ввод всего приложения. Не умножать такую паузу
на каждую реакцию; цепь должна оставаться короткой и показывать причинный порядок.
Падение уже имеет отдельную анимацию; не выдавать существующую за новое внедрение.

Поддержать несколько различимых звуков: обычный контакт, столкновение, лечение,
призыв. Громкость/интенсивность подчёркивают событие; звук не является единственным
способом сообщить о нём. Значение передаётся также формой/позой/текстом, не одним цветом.

Не начинать с постоянных аур вокруг всех бойцов, большого числа летящих цифр,
полноэкранных вспышек и тряски камеры при каждом попадании. Сначала проверить
локальные эффекты; сохранить видимость клеток, целей, полос и forecast.
Ускорение/сокращение декоративных анимаций предусмотреть в контракте воспроизведения,
конкретную настройку UI не считать реализованной. Состояния/артефакты не должны
запускать боевые события от анимационных callbacks.

## Первый предлагаемый визуальный срез V1

После выбора пользователем визуальной работы либо отдельного приоритета:

1. Стабильные визуальные экземпляры персонажей; обновление selection/forecast
   не пересоздаёт фигуру и не сбрасывает движение.
2. Один нынешний боец/общий шаблон: атака, отдача, принудительный толчок/столкновение.
   Использовать существующие правила, не вводить новую броню/спину/крит/цепи.
3. Проверить в игровом масштабе, на уступе, у стены и при нескольких последствиях.
   Затем решать, расширять ли пакет на движение/стойку/лечение/призыв.

Технические ограничения будущего среза: core/ActionQueue остаётся источником
результата; view воспроизводит фактический порядок событий и исполненный prefix,
а не вычисляет бой заново. Согласовать presentation/input, чтобы во время показа
прошлого действия не выбирать цель по устаревшей позиции. Reset/close, смерть и
смена сцены отменяют анимации; старые callbacks не меняют новую сессию.
Не расходовать игровой RNG на декоративные вариации. Положение в board меняется
только игровыми командами, tween двигает отображение. Общий ENTITIES Y-sort
тайлов/стен/фигур сохраняется; внутренние части не сортируются как отдельные бойцы.
Художественный поворот/наклон не меняет логическое направление будущего удара в спину.

Приёмка будущего V1: прежние результаты/forecast/RNG/resources/revision сохраняются;
реальный input в отдельном SubViewport, reset во время эффекта, несколько быстрых
действий и корректные перекрытия; PNG и визуальный плейтест. Ни V1, ни его проверки
сейчас не реализованы. Полный набор звуков/эффектов таблицы не входит автоматически.

## Влияние на план модульности

M1 (определение помощника) остаётся следующим уже выбранным срезом и сохраняет
нынешний баланс. V1 — предложение; этот разговор его не запускает.
До M2a согласовать новую логику брони, чтобы будущий расчёт учитывал её отдельно.
Пока это зависимость будущего этапа, не блокер для M1.
M3 может обобщать применение нынешних активных предметов, но не должен возвращать
стандартный инвентарь/слоты экипировки. Правила пассивных артефактов — отдельный срез.
Исторические контракты ARMOR/инвентаря не переписываются задним числом.

Ориентир по читаемости: [официальное описание Into the Breach](https://www.subsetgames.com/itb.html)
подчёркивает заранее показанные атаки и минималистичный пошаговый бой.
Перечень анимаций, длительности и порядок V1 выше — предложения ведущего для нашей
игры, не утверждения о внутреннем устройстве или точных таймингах Into the Breach.
