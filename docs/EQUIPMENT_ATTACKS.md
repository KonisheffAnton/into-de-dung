# Перки экипировки: дополнительные атаки

Согласовано U 2026-10-18: «Парные кухонные ножи» сразу надеты на разбойника;
их перк может быть на других вещах и складывается между надетыми предметами.

## Правило

`extra_attack` означает **+1 последовательная обычная атака по той же цели**.
Одна команда оплачивает 1 main и исполняет 1 + число экземпляров перка ударов:
ножи дают два, ножи и ещё одна вещь с перком — три. Любой слот экипировки
может дать перк; один предмет содержит его один раз. Inventory, склад и снятая
вещь его не дают. Количество фиксируется при допуске корневой команды.

Каждый удар заново рассчитывает урон, броню, щит, крит, статусы и прочие
последствия на текущем состоянии. После полного каскада удара, включая реакции
вещей, следует следующий. Удары имеют отдельные attack group и hit ID.
Если атакующий/цель погибли, атакующий получил запрещающий действие контроль
или цель больше недосягаема, серия заканчивается без смены цели и доплаты.
Выжившая цель получает одну возможность контратаки после всей серии по K12.
Прикрытие проверяется для каждого удара и платится по обычным правилам.

Перк относится к обычной атаке, заданной `MageDeckRules.default_attack_id`:
персональный ID героя из каталога способностей либо `demo_strike`.
Реакционные удары, особые атаки/приёмы и заклинания серии не порождают.
Дополнительный удар также не порождает новую серию. Общие лимиты очереди
применимы; FAULTED сохраняет исполненный prefix, хвоста после отказа нет.

## Владение и совместимость

`ItemDef.equipment_perks` задаёт перки определения; сейчас поддержан только
`extra_attack`. `ItemOwnerState.equipment_perk_count` выводит сумму из активных
надетых экземпляров. Перки не записываются в личный `CombatPerksState` героя:
снятие вещи немедленно убирает источник, отдельного refill/накопления нет.
Форма descriptor и строгая проверка — [боевые снимки](BATTLE_SNAPSHOT_CURRENT.md).

`ActionAttackPolicy` планирует серию в той же `ActionQueue`, перед единственной
контратакой. Внутренняя `AttackCommand.equipment_followup` проходит обычную
подготовку hit без расхода main; внешний submit этой команды запрещён.
Событие `attacked` дополнительного удара содержит `extra_attack:true`,
`main_cost:0`, одинаковые main_before/after. Остальные поля проверяет общий
валидатор. Изменение источников перка callback-ом во время серии даёт FAULTED.

ForecastSimulation и workers используют те же команды/определения в изоляции;
прогноз включает всю серию и ответ. Playback получает отдельные attacked/hit
шаги и проигрывает их последовательно; журнал отмечает источник дополнительного
удара. Инспекция героя показывает сумму бонусов и итоговое число атак.
Никаких действий из UI в обход очереди нет.

`weapon:rogue` теперь называется «Парные кухонные ножи», содержит один
`extra_attack`; прежние урон и 35% пробивания сохранены. Стабильный ключ уже
назначен стартовому/нанятому разбойнику, поэтому новый профиль и загрузка
прежнего профиля разрешают эту экипировку через обновлённый каталог.
Профиль v7, RNG и алгоритм выдачи вещей не меняются; новые вещи остальных
классов с этим перком в данном срезе не добавлены.

## Проверка

`equipment_attacks`: сумма по слотам, цена, цель, снятие/inventory, смерть,
контратака, исключённые атаки, internal admission, limits/FAULTED,
snapshot/definition isolation и preview/live/worker parity.
`hero_hub`: выдача/имя/профиль/производственная фабрика.
Команды и регрессия — [TESTING](TESTING.md). Технические тесты не заменяют
пользовательский F5-плейтест, визуальную приёмку серии или оценку баланса.
