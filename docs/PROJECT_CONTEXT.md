## Что представляет собой проект сейчас

Рабочий прототип одного тактического боя 3v3: командные ходы, свободное переключение
своих без refill, атака за 1 main, враги через BT, толчки/столкновения/падения,
осмотр и прогноз атаки, стойка, лечебный флакон и призыв помощников.
Это проверяемая основа боя; законченного цикла хаб → забег → возвращение пока нет.
Пользовательский плейтест последнего боя остаётся открытым.

| Область | Состояние и граница |
|---|---|
| Исполнение | ActionQueue и команды работают; последствия, отказы и частично исполненный FAULTED учитываются явно. |
| Прогноз | AttackForecast исполняет настоящую атаку на изолированном состоянии с предметами/RNG/ресурсами. Не общий прогноз всех будущих действий. |
| Данные | Есть StatsBag/modifiers, Vitals, определения/экземпляры предметов, ownership и версионные снимки. Это не готовая система всех будущих механик. |
| Броня | Сейчас числовое вычитание из урона. Расходуемый запас брони и две группы сопротивлений ещё не реализованы. |
| Урон | Есть конкретные формулы и профили. Расширяемый расчёт типизированных компонентов требует отдельного среза. |
| Клетки/трупы | Есть terrain/hazard, occupancy и сохранение мёртвых юнитов в реестре. Нет общего движка поверхностей/дыма/статусов и модели нескольких трупов на клетке. |
| Предметы | Флакон/печать работают; use_heal_amount/use_summon — специальные поля, не универсальный контракт применения. |
| Прогресс | Боевой snapshot не является сохранением профиля мага или целого забега. |

## Какой источник читать

| Вопрос | Источник |
|---|---|
| Нынешний бой и управление | `TACTICAL_BATTLE.md` |
| Прогноз, стойка, лечение, призыв | `ATTACK_FORECAST.md`, `ACTION_PANEL_GUARD.md`, `HEALING_ITEM.md`, `SUMMON_ITEM.md` — только затронутые |
| Новая концепция и предлагаемый порядок | `DESIGN_DIRECTION.md`; это консультация, а не поручение выполнить весь план |
| Ранее согласованный будущий дизайн | `TACTICAL_DESIGN_NEXT.md`; новая броня требует согласования мест, где ещё сказано «вычесть броню» |
| Предыдущий план рефакторинга M1–M4 | `MODULARITY_PLAN.md`; не реализован и автоматически не запускается |
| Инварианты и история архитектуры | `DECISIONS.md` R-1..R-6; `ARCHITECTURE.md` и остальные разделы содержат устаревшие статусы |
| Контракты исполнения и снимков | `COMMAND_ACTION_QUEUE_CONTRACT.md`, нужный Pxx TASK и его REVIEW; frozen документы не переписывать |
| Запуск и проверки | `REPOSITORY_STATE.md`, `TESTING.md`, свежая приёмка в HANDOFF |
| Работа команды и передача | `CODEX_WORKFLOW.md`, `../AGENTS.md` |

Последние явные указания пользователя определяют желаемое направление. Они не
доказывают наличие механизма в коде. Реализованное поведение подтверждается кодом,
действующим контрактом и результатами проверок; при расхождении описать конфликт.
Новый обзор не отменяет frozen контракт и не делает предложение утверждённым.
R-7 читать с учётом позднейших поручений: второй предмет уже существует;
практический принцип — завершать игровые циклы и ограничивать размер этапов.

## Технические ограничения и проверка

Адресная карта кода (сверена в этом этапе):
- `scripts/core/actions/attack_command.gd`: нынешняя формула внутри команды;
  `attack_definition.gd`/`attack_rules.gd`: id/profile и три известных профиля.
- `scripts/core/combat/damage_calculator.gd`: отдельная legacy-формула;
  `scripts/core/actions/action_hp_executor.gd`: flat/bypass. AttackCommand передаёт
  bypass после собственного вычета брони; не добавлять второй вычет ниже по цепи.
- `scripts/core/stats/stat.gd`: `(base + sum(flat)) * (1 + sum(percent)) * product(multiply)`;
  это расчёт stat, не общего урона. `units/vitals.gd`: HP и накопленный impact.
- `scripts/core/stats/stats_bag.gd`, `items/item_owner_state.gd`,
  `actions/simulation_snapshot.gd` (все под `scripts/core`): проверки stat IDs 0..10;
  добавление ID затрагивает согласованную валидацию, а не только enum.
- `scripts/core/board/battle_board.gd`: terrain/height/occupancy/units;
  `scripts/core/actions/attack_forecast.gd`: настоящий изолированный прогон.

Строго типизированный GDScript; Resource — определения, RefCounted — runtime.
Текущие ресурсы отделены от maxima/stats. Позиции — через BattleBoard; зависимости
и RNG инжектируются; реакции порождают команды. Preview включает все влияющие
данные и последствия. Enum append-only; snapshot validation до мутации/allocation.
Старые форматы и §4.5 P08 сохранять до явного нового контракта миграции.
