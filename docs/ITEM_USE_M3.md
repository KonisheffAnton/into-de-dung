# Общее описание применения предметов — M3

Первый этап доработки ядра после отложенного выбора порядка ходов.
База: `add9f573b24d211a13dbd3d6f8466b4c516b4320`, 2026-09-23.
Правила флакона и печати остаются в [HEALING_ITEM](HEALING_ITEM.md) и
[SUMMON_ITEM](SUMMON_ITEM.md); определение помощника — [M1](SUMMON_DEFINITION_M1.md).

## Владение и API

`ItemUseAction : Resource` — производное типизированное описание двух известных
применений: `HEAL_SELF / SELF` и `SUMMON_ADJACENT / ADJACENT_CELL`.
`ItemInstance.get_use_action()` каждый раз строит его из определения предмета.
Описание содержит параметры лечения или изолированную копию SummonDefinition,
ёмкость зарядов и общую цену: 1 main + 1 заряд. Остаток зарядов принадлежит
ItemInstance, остатки действий — ActionResources; описание не хранит live runtime.
Getters шаблона призыва возвращают копии. Пассивный/невалидный предмет даёт null.

`from_definition()` принимает только точные ItemDef/совместимый Item и известные
сочетания use_*; это проверка описания применения, не замена полной проверки
effects/armor/identity владельцем и снимком. Новый класс не получает поддержку
применения или прогноза автоматически. Kind/TargetMode не записываются в снимок.

`create_command(actor_id, item_id, revision, cell)` создаёт прежнюю команду лечения
либо призыва; неподдерживаемое описание даёт null. `availability_reason()` читает
текущую revision и вызывает настоящую Command.validate; не оплачивает действие,
не меняет snapshot/RNG/counters/last_receipt. Невалидные ID и revision проверяет
сама команда. Устаревшее описание не подменяет живые параметры/остатки предмета.
`hint_reason()` использует тот же factory и локальные проверки команды, но
пропускает snapshot всего боя. Это подсказка кнопке/намерению BT, без кэша и
мутаций; она может разрешать действие при неизвестной capability другого
участника. `availability_reason`, validate/execute и очередь остаются строгими:
такое действие будет отклонено до оплаты. Цена, геометрия и порядок кандидатов
не меняются; hint не используется как авторизация клика или готовый прогноз.
`target_cells()` возвращает геометрические кандидаты призыва в прежнем порядке
UP/LEFT/RIGHT/DOWN; это не обещание доступности при нехватке ресурсов или лимите.

Фаза боя, выбранный персонаж и busy/faulted gate остаются у session. Общие helpers
BattleTacticalSession обслуживают обе публичные операции; BT читает доступность,
выбирает намерение, session создаёт команду через тот же factory. На submit и
execute команда повторно проверяет состояние и сама атомарно платит main/charge.
Callback, исполненный FAULTED prefix и события сохраняют прежний контракт.

## Совместимость и представление

Миграция потребителей выполнена через адаптер существующих use_heal_amount,
use_summon, max_charges и summon_definition. Эти поля остаются единственным
сериализованным источником; второго поля действия/новой схемы нет. ItemSimulation
v1–v6, canonical bytes, catalogue equality, D4 и M1 не меняются. После restore
описание заново выводится из уже проверенного определения. Сам ItemUseAction не
сериализуется; его поддержка не означает общий forecast применения предметов.
[K3](ATTACK_FORECAST.md#k3--прогноз-лечения-и-печати) отдельно поддерживает только
эти две команды на изолированной копии, сохраняя gates/factory/живое исполнение.

UI получает цену, ёмкость, параметры и тип цели из описания, текущие заряды — из
экземпляра, причину отказа — из session/команды. Для нестандартного лечения
подсказка показывает его фактическую величину. Слоты 3/4, клавиши, отдельный
режим выбора клетки, его отмена/очистка, страницы и прокрутка сохраняются.

Начало/конец хода, refill и pending помощника остаются у соответствующих session.
Этот этап не выбирает систему ходов и не подключает D2–D5/C1 к сравнению.
Новые предметы/цели/цены, редактор, смешанное heal+summon, общий движок статусов,
графика и экономика не входят в M3. Прогноз двух существующих применений
добавлен отдельным K3; общий прогноз новых действий не подразумевается.

чистота доступности, повторная проверка ресурсов/типа/revision, восстановление

проверяет очистку режима цели; прежние проверки клавиш/страниц/scroll сохраняются.
