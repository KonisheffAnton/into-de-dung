# Прогноз действия и панель осмотра

Действующий прогноз нынешней атаки с её последствиями, стойкой и влияющими
предметами. Стойка — [ACTION_PANEL_GUARD](ACTION_PANEL_GUARD.md); лечение/заряды —
[HEALING_ITEM](HEALING_ITEM.md); helpers и item snapshot v3 — [SUMMON_ITEM](SUMMON_ITEM.md).
Прогноз не расходует live-заряды. K3 добавляет отдельный прогноз двух применений
M3 (ниже); K4 добавляет движение, K5 — поднятие одного тела, K6 — охранную стойку, K9 — восстановление брони.
Перковый удар и иммунитеты [K11](CONTROL_PACKAGE_K11.md) используют тот же
исполнитель; пропуск контроля отображается отдельно от урона.
K17 добавляет ElementalCastCommand в ForecastSimulation/ActionForecastWorker:
Поджечь/Облить/Заморозить и nullable elemental в unit_values. Стаки/сроки,
добивание и последствия движения исполняются тем же путём; правила —
[STATUS_EFFECTS_NEXT](STATUS_EFFECTS_NEXT.md). TurnForecast переносит выбранный
вариант и реальные новые тики командной границы.
Готовый элементальный прогноз проверяется и при неподвижном курсоре: ключ
включает полный item snapshot, RNG/счётчики, admission и лимиты очереди.
Прогноза нескольких команд нет.
Будущий дизайн TACTICAL_DESIGN_NEXT не включается автоматически.
Происхождение срезов — [архив](ATTACK_FORECAST.history-20260920.md).

## Контракт исполнения

`AttackForecast.build(context, queue, command: AttackCommand)` возвращает RefCounted
с `status: StringName`, `reason: StringName`, `units: Dictionary` (ключ int unit id),
`events: Array[Dictionary]`, `steps: Array[Dictionary]`. Только APPLIED является
готовым прогнозом. Отказ, неизвестная capability или незавершённый каскад не дают
полос ожидаемого HP. В DTO нет ссылок на live/изолированные UnitState.

Каждая запись units содержит `before` и `after`: словари `hp`, `hp_max`, `balance`,
`balance_max` (float), `cell` (Vector2i), `alive` (bool), `main`, `bonus` (int),
`move` (float). Записи включают всех участников, UI выделяет изменившихся.
Записи также содержат `guard_stance` (bool); полный snapshot
переносит состояние в Unit schema v3 без refill. Снятие стойки атакующего совпадает
с настоящим исполнением. Проценты защиты не применяются к столкновению/падению.
`snapshot_before/after: Dictionary`, `rng_after: Dictionary`, `counters_after:
Dictionary` сохраняются для проверки parity. DTO не является save-game/token.

Снимок ItemSimulationSnapshot переносит доску, занятость, предметы, активность,
runtime эффектов и ресурсы без equip/refill. Определения копируются из каталога.
RNG клонируется отдельным объектом с совпадающим состоянием. Точный базовый
ActionRngPort допускается как порт без случайных чисел; неизвестный неклонируемый
порт отклоняется. Очередь сохраняет лимиты, контекст — revision и три счётчика.
Исполняется настоящая AttackCommand через ActionQueue с изолированным sink до
завершения mandatory/reactions. Копия закрывается на всех путях после создания.
Live состояние, сигналы, sink, счётчики, RNG и last_receipt не меняются.
Произвольные внешние мутирующие callbacks не входят в capability этого среза;
игровые реакции обязаны быть представленными в item runtime/командах.

`BattleDemoSession.preview_attack(id)` строит ту же команду, что атака, без submit
в live очередь. Tactical session применяет те же input/friendly gates без _reject
(он меняет last_receipt). Прогноз не завершает ход и не вычисляет исход боя.

## UI и приёмка

Наведение атаки использует `prepare_attack_forecast` и один `AttackForecastWorker`.
Обработчик ввода сразу запоминает последнюю цель и показывает «Рассчитываем
последствия удара…», без вымышленных HP/подсветки. На следующем tick основной
поток снимает изолированный `ForecastSimulation.Prepared`; worker восстанавливает
состояние и выполняет настоящий submit через `AttackForecast.build_prepared`.
Пакет одноразовый; worker допускает только точный AttackCommand и штатные
ActionRngPort/CombatRng. Синхронный `preview_attack` сохранён для клиентов/проверок.
Ключ запроса включает цель/клетку, actor, revision и обычный удар/руну/путы/оглушение K11.
Новый запрос заменяет ожидающий, не создавая очередь потоков. Refresh инвалидирует
поколение и при прямом изменении без revision. Перед публикацией проверяются
поколение, actor/revision/вариант, режим/фаза и цель под мышью либо переход к панели.
На панели можно дождаться ещё не готового результата. Выход отменяет запрос;
клик исполняет свежую команду, не ожидая worker. Завершённый поток присоединяется
при обработке кадров; уничтожение UI присоединяет также незавершённый поток.
Заголовок ожидания и результата (включая отказ) показывает «Атакующий → Цель»
по ID текущего запроса. Смена персонажа/цели заменяет имена; отмена и исполнение
очищают их вместе с прогнозом. Имена читаются только при владении session у UI.
Фоновый расчёт сохраняет прежнюю полноту прогноза; подготовка снимка остаётся
на основном потоке, поэтому это не обещание нулевой задержки при любом составе боя.

Стойка (включая Оппортуниста/Прикрытие), лечение, призыв, поднятие тела и
восстановление брони также используют отложенную подготовку и один
`ActionForecastWorker` для этих действий. На вводе появляется ожидание без
готовых чисел; на следующем tick отделяется Prepared. Поток принимает только
точные Guard/UseHealingItem/UseSummoningItem/RaiseCorpse/RestoreArmorCommand и
штатный ActionRngPort/CombatRng; выполняет ForecastSimulation.run_prepared.
Guard/ItemUse/RaiseCorpseForecast.from_simulation переводят результат в прежние
DTO. Синхронные preview/build остаются доступны и проходят ту же симуляцию.
Последний запрос заменяет ожидающий; actor/revision/действие/клетка/цель и
поколение должны совпасть перед публикацией. Refresh обновляет также ещё
ожидающий прогноз кнопки при прямом изменении без revision. Уход, выбор, режим,
фаза, reset и закрытие сохраняют те же правила отмены/присоединения потока.
Клик всегда исполняет свежую команду и не ожидает фонового результата.

Панель доступности и BT намерение используют дешёвые hint API предметов
([M3](ITEM_USE_M3.md)) и поднятия ([D5](ENVIRONMENT_D5.md)). Hint не является
успешным прогнозом или допуском команды: отделение снимка, validate, submit и
execute сохраняют полные проверки. Глобальный кэш по одной revision не вводится.
Snapshot raw preflight проверяет scalar leaves и ключи без рекурсивного вызова;
лимиты, типы, cycle detection и диагностический fallback неизменны.
Основной общий бой исполняет свежую live-команду в отдельном worker с передачей
владения session и согласованным видом UI; [контракт](BATTLE_EXECUTION_UI.md).
Остальные session и внешний callback fallback синхронны. Текущая оценка
плавности и её границы — HISTORY; это не обещание FPS для всех состояний.

Текстовая панель — диагностический вывод; направление боевого представления
значками/цифрами на персонажах — [DESIGN_DIRECTION §2](DESIGN_DIRECTION.md#2-последняя-концепция-пользователя).

В режиме A наведение на фигуру показывает отказ либо итог всего каскада, включая
HP/равновесие, толчок, столкновение, падение, смерть и лечение. Конечный HP отмечен
на существующей полосе каждой затронутой фигуры; потеря красная, лечение зелёное,
числа показывают текущий и итоговый HP. Стрелка идёт из from_cell к to_cell или
attempted_cell, исход объясняется текстом. События берутся из receipt, не формул.
Hover не меняет selection/осмотр. Клик исполняет свежую команду с текущим состоянием.
В командном бою клик по живому своему бойцу вместо удара сразу выбирает его и
возвращает движение; готовый или ожидающий прогноз прежнего бойца отменяется.
Колесо вверх/вниз над текущей целью в режиме A прокручивает текстовую панель,
сохраняя цель, готовый прогноз и live-состояние. Подсказка видна в её заголовке.
Новый прогноз начинается сверху; вне цели колесо не перенаправляется из других
панелей. Прокрутка не исполняет команду и не расходует действия.
Переход мыши прямо на панель сохраняет результат для прокрутки; выход из неё или
уход с поля в другое место очищает его. Смена режима/выбора, receipt, reset, смена сцены, смерть и блокировка
не оставляют устаревшего прогноза. Пересчёт допустим при refresh/смене клетки,
но не каждый кадр неподвижного hover. Refresh сбрасывает кэш также при изменении
состояния вне revision. Реальные сущности сохраняют ENTITIES Y-sort.

Закреплённая панель описывает осматриваемого врага, иначе выбранного союзника;
при A-hover временно показывает цель. Поля: HP, накопленная потеря равновесия,
движение/main/bonus, броня, базовое оружие и его урон, текущая атака, эффекты.
Эффекты читаются из runtime, без hardcoded проверки номера персонажа; действие,
величина и срок активности понятны, технический источник по умолчанию скрыт.
Неизвестные эффекты обозначаются как неизвестные, не пропускаются молча.

Проверки ведущего: import/startup; headless parity полных snapshot/receipt/RNG/
counters с реальным исполнением; repeated no-mutation, stale/locked/friendly,
нет main, недосягаемость, предметное лечение после всего каскада и lethal,
collateral союзник, толчок в стену/void/с уступа, queue limits/busy/fault,
неклонируемый RNG, изоляция определений/DTO и cleanup. Затем весь core и demo/battle
runner; viewport hover/exit/selection/phase/reset и PNG, независимое review.


## Призванные участники (2026-09-15)

[SUMMON_ITEM.md](SUMMON_ITEM.md) добавляет item snapshot v3 с use_summon,
зарядами и metadata владельца/ожидания первого хода. AttackForecast сохраняет
полную доску с helpers, их предметных владельцев и admission rules копии контекста.
Заряд печати не расходуется атакой. Совпадение полного snapshot, receipts,
counters/RNG проверяется для атак с pending/готовым helper, включая атаку на
него. Прогноз самого призыва добавлен отдельным API K3 ниже. Unit snapshot v3
стойки не меняется.

## Новая броня D2

Профиль armor_spatial_v1 исполняется тем же forecast. Unit/ItemSimulation v4
переносят E, перки/сопротивления, a_i/ключи экземпляров; CombatRng клонируется.
В units добавлены armor_state, armor_current, armor_max только для новой capability.
События armor_changed/hit_resolved дают фактический расход и по типам D/защиты/
HP-damage/healing; старые damaged/healed отражают net HP. Панель и синяя полоса
читают эти значения без своей формулы. Завершение боя и истечение E также
исполняются очередью на копии; внешние callbacks по-прежнему не копируются.
Полный контракт и ограничения — [ARMOR_DAMAGE_D2](ARMOR_DAMAGE_D2.md).

## Кровотечение D3

Unit v5 переносит BleedingState внутри ItemSimulation v4. Поле units.before/after
`bleeding` содержит значения состояния. Допуск прямого hit (physical HP-damage
до лечения или явный bypass) виден в hit_resolved; результат наложения — в
bleeding_changed и шаге bleeding_apply, включая SKIPPED по иммунитету/смерти/gate.
Прогноз включает spatial → статус → item reactions; будущие ходы и их тики
не моделируются этим API. Изоляция и parity тиков проверяются отдельно через
настоящую BleedingTurnCommand на восстановленной копии. [Пакет D3](BLEEDING_D3.md).

## Среда D5

ItemSimulation v5 переносит клетки с шипами, тела, их ID и обработанные смерти.
При нестандартном определении печати [M1](SUMMON_DEFINITION_M1.md) использует
ItemSimulation v6: все stats/параметры имени, включая неиспользованную печать,
копируются и проверяются тем же codec. Forecast исполняет прежнюю команду атаки;
нестандартный шаблон не включает armor capability у старого призыва.
Толчок на шипы исполняет тот же EnvironmentCommand/ArmorHitExecutor на копии;
события fire hit и corpse_created видны в прогнозе. Состав среды включён в
snapshot_before/after и проверку live isolation. Прогноза движения и поднятия
тела этот API не добавляет. Правила транзита и потребления — [D5](ENVIRONMENT_D5.md).


## K3 — прогноз лечения и печати

`ItemUseForecast.build(context, queue, command: Command)` допускает только точные
UseHealingItemCommand/UseSummoningItemCommand. Подклассы, атака, поднятие D5 и
произвольные команды отклоняются с `preview/unsupported_command`. Отдельные
`BattleTacticalSession.preview_healing_item()` / `preview_summoning_item(cell)`
применяют прежние `_item_reason` gates без `_reject` и изменения last_receipt.
Клик заново получает текущий ItemUseAction и создаёт свежую live-команду.

`ForecastSimulation` владеет общей изоляцией: прежние snapshot/definitions/RNG,
revision/counters, admission, лимиты очереди, изолированный sink и cleanup.
Помощник имеет закрытый список команд: атака, две M3, движение K4,
поднятие K5 и стойка K6.
Публичный AttackForecast, его тип команды и поля units не меняются. Внешние
callbacks не копируются; прогноз не моделирует следующий ход/refill/исход session.
Настоящие обязательные последствия текущего submit исполняются очередью.

ItemUseForecast возвращает значения `status/reason`, `events/steps`, полные
`snapshot_before/after`, `rng_after`, `counters_after`, `admission_before/after`
(представление SummonAdmission.values). Только APPLIED заполняет готовые `units`
и `items`; FAULTED хранит исполненный prefix в журнале/снимках без обещания успеха.
Ранние отказы capability/session могут не иметь снимков. Все данные независимы
от live, следующего прогноза и восстановленного runtime, не являются save/token.

`units[id]` содержит `before` и `after` с прежними значениями AttackForecast,
плюс `id`, `name`, `owner_unit_id` (0 для исходного бойца), `pending`.
У нового помощника **before = null**, after содержит реальный ID, клетку,
HP/ресурсы, владельца и ожидание. Это появление, а не лечение погибшего бойца.
`items[item_id]` содержит `actor_id`, `before/after: {charges: int}` только для
предмета этой команды; ID экземпляра локален владельцу и используется вместе
с actor_id. Остатки HP/main/bonus/move принадлежат units, полный runtime — снимку.
Призыв сохраняет pending и нулевые стартовые действия; hover не добавляет live unit.

Hover слота 3 показывает лечение/расход либо отказ даже у disabled-кнопки.
Кнопка/клавиша 3 по-прежнему сразу лечит. В режиме печати hover клетки показывает
нового помощника/цену либо отказ, клик применяет. Предметный результат выводится
отдельно в существующей текстовой панели; поле AttackForecast/полосы атаки его
не принимают. Смена выбора/режима/receipt/фазы/reset/сценария и выход очищают
результат. Пересчёт при новом hover/refresh, без повторения каждый кадр; панель
доступна для прокрутки. Правила возврата в движение сохраняются.

Печать при `actor.armor != null` сохраняет `armor/summon_unsupported`: успех
проверяется в обычном тактическом бою, лечение также в K2. K2/D4 не получают
призыв при броне. Нет новых эффектов, цен, схем save, прогноза движения,
поднятия D5 или цепочки действий. Покрытие и остаток — [CORE_READINESS §K3](CORE_READINESS.md#k3--прогноз-двух-применений-m3);
команды/runner — [TESTING](TESTING.md), результаты — [HISTORY](HISTORY.md).

## K4 — прогноз движения

Безопасный отход K14 использует этот же механизм с видом команды `safe_retreat`.
Правила расхода и UI — [SAFE_RETREAT_K14](SAFE_RETREAT_K14.md). Вид движения
входит в актуальность hover; клик создаёт свежую команду соответствующего вида.

`MoveForecast.build(context, queue, command: Command)` допускает только точный
`MoveCommand`; подклассы/другие команды дают `preview/unsupported_command`,
внутреннее продолжение — прежний отказ очереди `move/internal_continuation`.
`ForecastSimulation` исполняет настоящий submit на копии с теми же правилами,
предметами, средой, admission, RNG, revision, счётчиками и лимитами очереди.
Все гарантии изоляции/cleanup выше сохраняются; внешние callbacks не копируются.
Смена фазы/выбора, будущий ход и refill не моделируются. Внутренние последствия
текущего submit, включая завершение временной брони после гибели, исполняются.

DTO содержит `status/reason`, `units`, `events/steps`, полные
`snapshot_before/after`, `rng_after`, `counters_after`, `admission_before/after`.
`units[id].before/after` сохраняют поля AttackForecast, без ссылок на runtime.
`actor_id: int`, `requested_path: Array[Vector2i]` описывают запрос;
`traversed_path: Array[Vector2i]` содержит начало и действительно пройденные клетки
из `moved`/`transit_path`. Конечная клетка/жизнь/ресурсы берутся из `units.after`,
расход — разность остатков, без повторного расчёта цены или урона в UI.

Готовы **APPLIED и INTERRUPTED**: корректно завершённый прерванный путь показывает
исполненный участок, причину остановки и гибель. Цена оставшегося пути не платится.
Это исключение только для движения; критерий готовности атаки/M3 не расширяется.
FAULTED сохраняет доступные снимки/events/steps исполненного prefix, но не `units`
или `traversed_path` готового результата. При невозможности снять итоговый snapshot
APPLIED/INTERRUPTED превращается в FAULTED `preview/result_snapshot_failed`.
Отказ до создания копии может не содержать снимков. DTO не является save/token.

`BattleDemoSession.preview_move(cell)` использует тот же `path_to` и MoveCommand,
что `move_to`; TacticalSession сохраняет `can_player_act` без `_reject` и изменения
last_receipt. Клик заново ищет путь и создаёт команду на текущем состоянии.
Hover свободной клетки в обычном движении показывает результат либо отказ.
Наведение на фигуру сохраняет выбор/осмотр; режимы атаки/печати/поднятия и осмотр
врага не показывают прогноз движения. Контроль C1 объясняет запрет движения.

В готовом прогнозе полоса HP показывает итог, сплошная линия — пройденный участок, кольцо — конечную клетку
(красное при гибели). Текст содержит расход/остатки, HP/броню, снятие стойки,
прерывание и журнал реальных последствий. При отказе/FAULTED готовых полос/пути нет.
Кэш: клетка, выбранный actor, revision; refresh инвалидирует также прямые изменения
вне revision. Смена режима/выбора/receipt/фазы/reset/сценария очищает или пересчитывает
результат. Колесо на цели и переход на панель сохраняют прогноз без исполнения;
уход вне поля/панели очищает его. Пересчёта каждый кадр неподвижного hover нет.

После отзыва о задержке hover (2026-09-24) UI ждёт 60 мс на последней клетке,
затем `prepare_move_forecast` снимает проверенный snapshot и копии определений,
RNG, правил, счётчиков и очереди на основном потоке. `ForecastSimulation.Prepared`
— одноразовый пакет без live board/юнитов/фасадов; восстановление и настоящий submit
выполняются через `run_prepared` в одном `MoveForecastWorker`. Обычные синхронные
API прогноза сохранены. Worker принимает только root MoveCommand и штатные
ActionRngPort/CombatRng; неизвестный RNG не исполняется в фоне.

Пунктирный маршрут запроса появляется в обработчике hover, до ожидания 60 мс
и запуска worker. UI берёт его из штатного `path_to` только для клетки из уже
найденной доступной зоны; это геометрия намерения, а не итог исполнения.
Панель явно отличает выбранный маршрут от ещё рассчитываемых последствий;
готовые HP, расход и кольцо конечного результата до расчёта не показываются.
APPLIED/INTERRUPTED заменяют пунктир сплошным фактически пройденным участком,
включая остановку/гибель до выбранной клетки; отказ/FAULTED убирают маршрут.
Недостижимая клетка и запрет движения не получают предварительной линии.
Быстрые hover заменяют ожидающую цель, не создавая очередь расчётов. Смена цели,
refresh (включая прямую мутацию без revision), выбора, режима, фазы или сценария
меняет поколение запроса: старый результат отбрасывается. Перед публикацией
повторно проверяются actor/revision/режим/фаза и клетка под мышью. Уход с поля
отменяет ещё не готовый прогноз; переход к панели сохраняет только готовый.
Клик не ждёт worker и исполняет свежую live-команду. Завершённый поток присоединяется
без ожидания в обработчике мыши; при уничтожении UI присоединяется также незавершённый.
Предварительный маршрут очищается вместе с запросом и сразу заменяется при
смене цели, даже если worker ещё занят старым расчётом. Долгоживущего кэша
маршрутов нет; подготовка точного прогноза и live-клик заново находят свой путь.
Hover обновляет существующие визуалы/полосы и overlay без перестройки доски и
повторного поиска доступной зоны. Полный refresh сохраняет прежнюю инвалидацию.

K4 сохраняет цены, нынешнюю шкалу падения, шипы D5, транзит союзников и схемы save.
Новая шкала/занятое приземление/цепи/поднятие D5 и несколько будущих действий
не входят. Состав проверки — [CORE_READINESS §K4](CORE_READINESS.md#k4--прогноз-движения),
runner — [TESTING](TESTING.md); технические проверки не заменяют плейтест.

## K5 — прогноз поднятия тела

`RaiseCorpseForecast.build(context, queue, command: Command)` допускает только
точный `RaiseCorpseCommand`; null, подкласс и другие команды возвращают
`preview/unsupported_command`. `ForecastSimulation` исполняет этот настоящий
submit на изолированной копии по прежним правилам [D5](ENVIRONMENT_D5.md).
Порядок ходов, цена, default помощника, admission и snapshot codecs не меняются.
Прогноз не моделирует следующий ход, refill или дальнейшие действия помощника.

DTO содержит `actor_id/corpse_id: int`, `status/reason`, `units/corpses: Dictionary`,
`events/steps`, полные `snapshot_before/after`, `rng_after`, `counters_after`,
`admission_before/after`. Только **APPLIED** заполняет `units` и `corpses`.
Поля units совпадают с K3, включая имя/ID/owner_unit_id/pending. Новый помощник
имеет `before = null`; прежний погибший остаётся погибшим. `corpses[id]` содержит
`before/after` только изменённых записей тела, у израсходованного `after = null`.
Снимки/events/steps сохраняют доступный FAULTED prefix без готового помощника.
Данные не содержат runtime-ссылок; остаются гарантии изоляции/cleanup основного
контракта. Копирование записей тел для DTO выполняется только для поднятия.

`BattleEnvironmentSession.preview_raise_corpse(cell)` применяет прежний input gate
без `_reject`/изменения last_receipt. Preview и live используют `_raise_command`:
первое humanoid тело из упорядоченных по ID `corpses_at(cell)`. Клик создаёт команду
заново; сохранённый прогноз не является токеном исполнения или save-game.

В режиме слота 6 наведение на клетку показывает отказ либо расход/остатки main,
bonus/move, потребляемое тело и нового помощника с клеткой, владельцем, HP,
нулевыми ресурсами и ожиданием. Это отдельная текстовая панель: фигура/тело live
и полосы атаки/движения от наведения не меняются. Кэш включает клетку, actor и
revision; полный refresh инвалидирует его и при прямых изменениях без revision.
Смена выбора/осмотра/режима/фазы/reset/сценария, клик и выход очищают результат.
Переход с цели к панели и колесо сохраняют готовый прогноз без нового submit.
Синхронный расчёт запускается при изменении запроса, не каждый кадр.

K5 не добавляет новые правила D5, перенос M4/D4 в K2, общий runtime статусов,
цепочки будущих действий или оптимизацию задержки K4. Покрытие —
[CORE_READINESS §K5](CORE_READINESS.md#k5--прогноз-поднятия-тела),
runner — [TESTING](TESTING.md); пользовательская приёмка отдельна от тестов.

## K6 — прогноз охранной стойки

`GuardForecast.build(context, queue, command: Command)` принимает только точный
`GuardCommand`; null, подклассы и другие команды дают `preview/unsupported_command`.
`ForecastSimulation` исполняет настоящую команду на изолированной копии со всеми
прежними ресурсами, предметами, RNG, admission, revision и лимитами очереди.
Правила/цена/срок стойки принадлежат [ACTION_PANEL_GUARD](ACTION_PANEL_GUARD.md).
Защитные формулы, save/codec и порядок ходов не меняются; будущий удар, ход и
refill прогноз не моделирует.

DTO содержит `actor_id: int`, `status/reason`, `units: Dictionary`, `events/steps`,
полные `snapshot_before/after`, `rng_after`, `counters_after`, `admission_before/after`.
Только **APPLIED** заполняет готовые `units[id].before/after`; поля совпадают
с AttackForecast, включая `guard_stance`, HP/main/bonus/move и текущие capabilities.
Успешная стойка расходует 1 main и сохраняет bonus/move. Отказы не дают готового
состояния; FAULTED сохраняет доступный prefix в снимках/журнале. Гарантии изоляции,
отсутствия runtime-ссылок и cleanup основного контракта действуют и здесь.

`BattleTacticalSession.preview_guard()` использует прежний чистый `guard_reason()`
без `_reject` и изменения last_receipt, затем строит прогноз новой GuardCommand.
`guard_selected()` остаётся входом исполнения: клик и клавиша 2 создают свежую
команду и проверяют текущее состояние, cached DTO не является токеном исполнения.

Наведение на слот **2 «Защита»** в фазе игрока показывает отдельную текстовую
панель: выбранный союзник, расход/остатки main, bonus/move, стойка до/после и срок.
Недоступная кнопка также объясняет отказ; заблокированная фаза не строит прогноз.
Hover не включает стойку, не меняет выбор/осмотр/режим и не рисует полосы атаки.
Кэш привязан к actor/revision; неизменный hover не пересчитывается каждый кадр.
Полный refresh инвалидирует кэш и при изменении без revision, перечитывая результат,
если курсор остаётся над кнопкой. Переход к панели и её прокрутка сохраняют DTO.
Выход, смена кнопки/выбора/осмотра/режима/фазы, исполнение, reset, сценарий и
закрытие очищают прогноз; наведение на поле заменяет его текущим прогнозом поля.

K6 не добавляет общий runtime статусов, прогноз цепочек или новые эффекты и не
оптимизирует задержку K4. Состав проверки — [CORE_READINESS §K6](CORE_READINESS.md#k6--прогноз-охранной-стойки),
команды/runner — [TESTING](TESTING.md); пользовательская приёмка отдельна.

## K9 — прогноз восстановления брони

`BattleArmorSession.preview_restore_armor()` возвращает value-only ForecastSimulation
от настоящей RestoreArmorCommand(selected_id, 20, revision). В whitelist общего
исполнителя добавлена только эта точная команда. Цена/распределение/излишек/срок
не меняются: правила D2 и ArmorRecovery. DTO units_before/units_after включает
расход main и итог брони; items/grants читаются из фактически исполненного
armor_changed. Изоляция переносит все capabilities, вещи, определения, RNG,
ресурсы и counters. REJECTED/FAULTED не показывает готовые units_after; prefix
остаётся в снимках/steps/events. Два preview/live и лимит cleanup проверяет K9.

Наведение на слот 4 показывает броню до/после, починку каждой вещи, временную
броню и расход main. Клик/клавиша 4 строит свежую live-команду. Cache привязан к
выбору и revision; refresh перечитывает состояние даже без revision. Смена
действия/персонажа/хода/сцены/reset и уход из области чтения очищают прогноз.
Расстановка не запускает боевые прогнозы. Все восемь нынешних слотов K2 и
движение имеют прогноз; K13 ниже добавляет границу командного хода основного боя.
Несколько будущих действий и новые механики этим не объявляются прогнозируемыми.
Единая проверка K9 — [CORE_BATTLE_BATCH_K9](CORE_BATTLE_BATCH_K9.md).

## K10 — прогноз перков и реакций

[CORE_REACTIONS_K10](CORE_REACTIONS_K10.md) расширяет тот же исполнитель:
AttackForecast показывает фактический бонус скрытой атаки/Прикрытие, MoveForecast —
реальный удар и остановку Оппортунистом, GuardForecast — оплачиваемый выбор режима
и союзника. Снимки/units включают combat_perks, events — участников угрозы и расход
общего заряда. Геометрический пунктир K4 не обещает пройти через перехват.
Кэш стойки различает actor/revision/mode/target; клик создаёт свежую команду.
Подсветка участников угрозы очищается вместе с прогнозом; выбор Прикрытия
отменяется через Esc без оплаты. Это не прогноз намерений ИИ или нескольких ходов.

## K12 — полный ответ на атаку

Контратака по [K12](COUNTERATTACK_K12.md) входит в результат того же submit:
прогноз учитывает изменения обоих участников, заряд, ответный hit и исход боя.
GuardForecast включает новый режим; hover не платит main/заряд. Новый клик
проверяет живой контекст. Counterattacked/reaction_used описываются по реальным
событиям; worker не выводит ответ из одной только геометрии или revision.

## K13 — прогноз завершения командного хода

Область: основной общий бой `BattleCoreReactionsSession`, фаза игрока после
расстановки. Наведение на «Завершить ход» показывает переход до первого решения
ИИ. Прогноз включает истечение контроля исходящей команды, фазу окружения K15
(новую отметку, обрушение и смерти), кровотечение
входящей, исход и штатное пополнение её ресурсов/реакций/помощников. Победа от
тика останавливает переход до refill. Новых правил времени или цен здесь нет;
инициатива, D4 и прежние отдельные демо не получают этот прогноз автоматически.

`TurnForecast.prepare()` на владельце live проверяет фазу, busy/FAULTED,
поддержку полного runtime и внешних callbacks, затем отделяет snapshot, вещи,
определения, RNG, context/queue с лимитами и счётчиками, сессионные значения.
Разрешены точный класс общего боя и известные runtime/RNG; неизвестные отклоняются.
`run_prepared()` один раз восстанавливает изолированную сессию без reset и
выделения глобальных UnitId. Она вызывает настоящий `end_player_turn()`;
`step_enemy()` не вызывается. Формулы перехода не копируются в прогноз.

DTO содержит до/после, итоговую фазу, все root receipts/events/steps в порядке
исполнения, RNG/counters/admission. Терминальная победа — успешный прогноз,
даже когда переход в фазу врага не состоялся. Отказ не платит live-ресурсы;
FAULTED сохраняет фактически выполненный prefix, но UI не выдаёт его за
готовый успешный итог. Произвольные live callbacks не исполняются на копии.

`TurnForecastWorker` получает только отделённый одноразовый пакет. UI немедленно
показывает ожидание, принимает только актуальное поколение для той же session,
выбора, revision и фазы. Переход курсора на панель сохраняет чтение/прокрутку;
уход, отмена, выбор, действие, фаза, reset/сцена очищают старый результат.
Refresh заново захватывает мир даже без смены revision; это не кэш мира по revision.
Клик/Enter выполняет свежий live-переход и не ждёт/не применяет результат preview.
При выходе worker завершается до освобождения владельца.

Проверки: `test_turn_forecast.gd`, `test_turn_forecast_ui.gd` в full/render.
Проверяются preview/live/worker, изоляция, ранний исход, отказы и prefix,
реальный hover/click/Enter, обновление без revision, очистка и PNG.

## K15 — условный прогноз фазы окружения

Основной общий бой исполняет CollapsePhaseCommand на текущей изолированной
копии через ForecastSimulation/ActionForecastWorker. UI «Окружение · прогноз
фазы» показывает новую случайную отметку, обрушение прежней и реальные смерти.
Это состояние при немедленном начале фазы, не предсказание будущих действий
обеих команд. Подробные правила, RNG и проверки — [K15](ENVIRONMENT_COLLAPSE_K15.md).
K13 сохраняет границу до первого решения ИИ и включает этот корень в реальный
переход после игрока. Отдельная кнопка окружения сохраняет условный прогноз
самой фазы без истечения контроля и bleed/refill.

## Цепное отталкивание K16

Обычная атака общего боя включает [K16](PUSH_CHAIN_K16.md) в прежнюю очередь
прогноза. DTO переносит `chain_link` и все HP/balance/cell последствия; UI
показывает силу дошедшего импульса и остановку, стрелку только реального сдвига.
Forecast worker и live worker используют скопированные определения с capability;
новых snapshot-схем или отдельного расчёта цепи в UI нет.
